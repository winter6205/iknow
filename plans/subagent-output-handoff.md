# Plan: Subagent Output Handoff and Full-Report Retrieval

**Goal:** Keep parent-visible subagent handoffs short while preserving and making the complete worker report reliably readable through the fenced `subagent_result` path.
**Approach:** Pin the incident and negative-control trajectories before changing model-visible text. Align the `spawn_subagent` receipt and `subagent_result` instructions, preserve raw final text independently from the folded IPC envelope, and add bounded reads so reports beyond the current 200-line window remain retrievable. Finish with a tracked real-model A/B trajectory evaluation using production subagent wiring.
**Spec link:** Settled user-approved scope from this session; no new spec requested.
**ACR:** all-yes for the proposed implementation scope; plan review only, not evidence that implementation or runtime verification has passed.
**Per-ticket loop (all bullets):** test-driven-development → typecheck and tests → verification-before-completion. After all bullets land, run the end-of-round code review; if `GATE: BLOCKED`, repair in the next slot and then run `verification-before-completion`.
**Persist list:** None — retain existing subagent vocabulary; no new ADR or domain term is required.

## Settled contract and evidence

- The current incident is a short-report handoff problem: four synchronous receipts were about 2.1 KB, marked `truncated`, and the parent chose `read_image` for `final.md`. The trace does not show the 20,000-character fold as the cause of that choice.
- A separate long-report gap exists: `truncateEnvelopeResult` folds `env.result` before IPC when its JavaScript string length exceeds 20,000 UTF-16 code units, and the host currently persists that folded copy to `final.md`. The current `tests/subagent/pad-final-text.test.ts` locks this behavior in.
- A second separate read limit exists: `subagent_result` currently has no page arguments and `inspectWorkerPad` returns only the first 200 lines. Raw persistence alone therefore does not guarantee complete retrieval.
- Keep the frozen envelope's `tmp_root` field and its current parent-visible presence for compatibility; do not silently remove or rename it. Explicitly de-emphasize it as diagnostic metadata, not a file-read target. The actionable retrieval instruction uses `task_id` and the pad-relative `output_path` through `subagent_result`; tool arguments never pass the host absolute path to `read_image`, `read_file`, or a shell command. The existing worker fence and path checks remain the access boundary.
- Preserve the existing dedicated per-worker final-report `final.md` pad and `subagent_result` lifecycle. This remains the subagent report channel; it is not generic executor tool-result offload. Keep ADR-0006's generic offload ruling and the executor result cap unchanged. Do not change the worker fence, model/provider route, global system prompt, or unrelated truncation/error paths. The existing [model output truncation plan](model-output-truncation.md) covers provider generation limits and remains a separate effort.
