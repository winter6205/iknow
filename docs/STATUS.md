**Auto-memory (ADR-0031 / ADR-0033 / ADR-0034, 2026-08-28)**: **off by default** — when `settings.memory.autoExtract` or `settings.memory.dream` is missing or not `true`, the corresponding path does not run; with both off the hook is still present and only the mechanical part runs (`memory_gc` + capability sweep, zero LLM). Extraction: chat / tui / serve trigger asynchronously at `StopReason=completed` after 3 accumulated completed turns (`ask` not wired); CJK and ASCII share one tokenizer (Han/Kana/Hangul overlapping bigram; empty-token neighbors get no hits) → four-state op → atomic write `source: auto`. When `autoExtract === true` the extraction prompt carries the user/project instruction sheets and the English discipline (do not copy the instruction sheets, do not store repo-/git-derivable content, do record corrections and confirmations); candidates whose word overlap with the instruction sheets is too high are dropped before the four-state gate (repo-derivable content relies on the prompt only; the workspace is never scanned); if `memory_save` already succeeded this round, this extract is skipped; the dream double gate stays independent. Dream: a second LLM merge pass behind its own switch, triggered at **24h ∧ 5 sessions** (it does not share the completed gate with extraction), writing `source: dream`; it must never enter `gc.ts`; with both switches on and the dream gate reached: ingest → dream → mechanical GC. Read path (ADR-0034, `autoExtract` only): `system` may carry a short catalog of current entries plus a fixed English discipline sentence after EXISTENCE_POINTER (unpromoted bodies still never enter `system`); each turn prefetches up to 5 bodies against the user's raw text via the same `scoreMemoryEntries`, stacked onto the user-message side (zero-word-overlap candidates dropped); `memory_recall` still defaults to at most 10 verbatim title+frontmatter+body entries with the same English low-trust wrapper. SessionHub hooks and prefetch are held per `workspaceRoot`; chat and serve call the same `notifyAutoMemory`. Failures go through the host's `// EXIT: log-and-continue`, so the user turn still succeeds. **Not done**: vector / graph retrieval, memory-management UI, per-turn synchronous extraction, changing the default to ON, manual "dream right now", auto-promote, putting prefetched or unpromoted bodies into `system`, the five Low items in §2.5.

**Auto-memory layering (2026-08-29)**: **still OFF by default** (`ask` has no memory layer) — the extraction verdict shrinks to three states ADD/UPDATE/NOOP (UPDATE keeps the neighbor's `ttl_days`); SUPERSEDE no longer comes from extraction, only from dream LLM output's `replaces: string[]` (≤8 ids per entry, unknown slugs are log-and-continue skipped, the `supersedes` frontmatter becomes a comma-separated list, and mechanical GC softly disables target entries in the same pass); the dream gate state file is renamed `dream.json` (no `dream-cursor.json` compatibility); when `autoExtract === true` the dream triggers with the same **24h ∧ 5 sessions** double gate (also when `dream: false`; with both switches fully off it stays zero LLM); promote assembly and the short catalog enter `system` only when `autoExtract === true` (AGENTS / EXISTENCE_POINTER / recall / save unaffected); disabled entries are archived (rename) to `memoryDir/archive/` at ≥30 days or over cap, hot scans skip the archive, MEMORY.md index lines are removed along with archives, and nothing is ever hard-deleted. **Not done**: memory MCP / cold storage, vector / graph retrieval, changing the default to ON.

**TUI rendering backend platform statement (2026-08-10)**: the TUI has migrated from ink to @opentui/react 0.5.1 (Zig native renderer; only bun can drive its FFI). **Verified on Linux (incl. WSL2); macOS / Windows unverified** (cross-platform behavior of native binaries is upstream's responsibility). The old ink implementation is archived as read-only reference.

**TUI skill + MCP extension sources (2026-08-11)**: the TUI entry aligns with chat/serve in assembling skill and MCP extension sources — the `skill` tool + the `<available_skills>` system section + MCP manager connections (`mcp__*` tools discovered via tool_search). Slash input `/` mixes static commands with dynamic skill candidates, Tab to complete; `/skill-name [prompt]` loads deterministically (the skill body is appended into the user message on send); the `/mcp` dashboard shows server status / tool details / reload.

**Skill-model index increment (ADR-0098, spec `specs/skill-index-increment.md`)**: the opening `<available_skills>` stays frozen in system; skill-model-index names newly created under current scan roots are appended to the tail of messages as a hidden user message before the next call (newly created only). The **loadable-skill surface** (including those without a description) feeds slash; TUI/Web/CLI share one entry; `skill()` rejects human-side skills but does not block file reads. Plugin/MCP packages take effect via reload or a new conversation.

**Global plugin component loading (ADR-0095, 2026-09-14)**: loads skills / agents / hooks carried by plugins installed globally on this machine. Plugin roots = `~/.iknow/plugins` (default) + `IKNOW_PLUGIN_ROOTS` + the `plugins.roots` setting (**user layer only**, not in the project allowlist — plugin-contributed hooks mean arbitrary command execution, guarding against a clone-then-execute supply-chain surface); discovery = the `<root>/installed_plugins.json` ledger first (`<plugin>@<marketplace>` → installPath, namespace taken from the key prefix) + directory-scan fallback. Skills / agents register the canonical name `<plugin>:<name>` plus a bare-name alias (conflicts dropped + warned), entering `<available_skills>` and the `spawn_subagent` enum; the agent `ROLE_ID_PATTERN` is relaxed to allow `:`. Hooks: `hooks/hooks.json` is compiled through the `HookContribution` seam (ADR-0055) into async subprocess hooks — exact/regex matcher split + iknow tool-name candidate sets (`write_file`↔`Write`, `edit_file`↔`Edit|MultiEdit`, `todo_write` unmapped), common envelope key aliases, `${*_PLUGIN_ROOT}` and similar suffix substitution; Pre exit 2 = block, anything else fail-open. The hook chain is additively made async (`await pre/post`, no unhandledRejection). ADR: `docs/adr/0095-global-plugin-components.md`.

**TUI visible loop (2026-08-24)**: the verification final state is visible to humans (`VerifyBanner`, HITL + auto modes); the **environment snapshot** (cwd / git / diff highlights, capped at 2000 codepoints) hangs on TUI chrome, separate from the ADR-0028 status bar. The model-side long verify envelope stays hidden.

**Kernel slice (2026-08-25)**: foreground `runInSandbox` and background `bash` spawn share one set of bwrap fence parameters; consecutive `isConcurrencySafe` calls within the same tool phase may overlap, unsafe calls stay serial, and `tool_result` order matches `tool_use`.

### 2.5 Auto-memory known limitations / leftovers (ADR-0031 code-review follow-up)

> Source: the 2026-08-26 whole-round auto-memory code review (Standards + Spec axes): 3 Medium + 6 Low. The three Mediums were landed by ADR-0033. The five Low items remain; **each must be disposed of or explicitly accepted before flipping the default to ON**.

| Medium     | SessionHub multi-root "first root wins"      | **disposed (ADR-0033 D3)**: each `engineByRoot` entry holds a per-root `autoMemory`; `notifyAutoMemory` selects the hook by the session's `workspaceRoot`.                                                                                                                                                                                                        | —                                                                                                                        |
| Medium     | BM25 / CJK tokenization                      | **disposed (ADR-0033 D1)**: `src/harness/memory/tokenize.ts` shares ASCII tokens + CJK overlapping bigrams; empty token sets get no neighbor hits.                                                                                                                                                                                                                | bigram remains heuristic, not morphological analysis (ADR-0033 consequences)                                             |
| Medium     | `notifyAutoMemory` duplicated implementation | **disposed (ADR-0033 D3)**: helper exported from `src/harness/memory/notify-auto-memory.ts`; chat and the hub call the same function; log slots are still injected by the host.                                                                                                                                                                                   | —                                                                                                                        |
| Low        | Error-type naming-domain mismatch            | `requireGate` in `src/harness/memory/auto-hook.ts` validates the hook option `minCompletedTurns` but throws `MemoryGcOptionInvalid` (GC domain)                                                                                                                                                                                                                   | extract a shared option-invalid type, or add a hook-domain error class                                                   |
| Low        | `ingest.ts` variable shadowing               | inside `extractMemoryCandidates`, the inner `for (const raw of parsed)` shadows the outer `let raw: string` (the LLM's raw output). No behavioral bug today; readability and future-change risk only                                                                                                                                                              | rename the inner variable (e.g. `item`)                                                                                  |
| Low        | Heuristic thresholds uncalibrated            | the four-state verdict's `SAME_SUBJECT_FLOOR` / `NEAR_DUPLICATE_FLOOR` / `RESTATEMENT_FLOOR` / `CONTRADICTION_FLOOR` and `MIN_CANDIDATE_CONFIDENCE` are rule-of-thumb constants with no tuning evidence (acknowledged in ADR-0031 consequences)                                                                                                                   | calibrate once real corpora exist; constants are centralized in one place in `ingest.ts` for easy change                 |
| Low (Spec) | UPDATE swallows the neighbor's provenance    | `persistMemoryOps` UPDATE reuses the neighbor's slug but rewrites the entry wholesale: `ttl_days` takes the incoming argument, `source` is overwritten to `auto`, `supersedes` resets to `null`. When a hand-written entry (written by `memory_save`, no `source`) is hit by an automatic UPDATE, its TTL and provenance markers are swallowed                    | UPDATE should "read the old entry → merge fields" instead of a full rebuild, at minimum preserving `ttl_days` / `source` |
| Low (Spec) | `drain()` not wired to host shutdown         | the `AutoMemoryHook.drain` comment calls itself "Test seam and shutdown hook", but only `tests/harness/memory/auto-hook.test.ts` invokes it; neither `build-engine`'s shutdown composition nor `hub.shutdown()` wires it. On process exit an in-flight ingest is truncated (writes are tmp+rename atomic so no half entry survives, but that memory pass is lost) | wire it into the host-composed shutdown, or change the comment to "test seam" to match the wiring                        |

## 3. Outlook

### 3.1 Near-term (suggested within 1–2 iterations)

1. **Perception & kernel slices**
   - Perception slice: **merged** (TUI Verify final state + environment snapshot).
   - Kernel slice: **merged** (sandbox discipline + `isConcurrencySafe` scheduling).
2. **Reliability / workflow**
   - Fault recovery: **landed** (FaultClass → transport retry → loop detection + `fused`). Clarification turns / design approval still deferred. Manual `/compact` bypassing the auto-compact token gate has landed (same path as after an auto firing; terms: docs/CONTEXT.md "manual compact", "auto-compact token gate", "compact reason").
3. **Observability minimum set**
   - Structured logs: conversation_id, turn, tool duration, llm flag.

### 3.2 Mid-term

1. **Multi-turn / session quality**: cross-run session persistence, N-step sample evaluation over injected history.
2. **Harness tool expansion**: additional tools on demand (constrained by the harness ACI decor layer; permission / timeout tiers must be fixed first).
3. **LLM guardrail hardening**: configurable host rules (forced first-hop read_file, sensitive approval, etc.).
4. **Session API enhancements** (auth, SSE, session persistence) — the Web surface has settled on the Vite React SPA; no protocol reopening.

### 3.3 Long-term

1. **P4 engineering**: multi-tenancy, audit compliance, approval flows and enterprise IdP integration.
2. **Human-machine collaboration**: productized approval flows (carried by the harness ACI decor layer authorization mechanism).
3. **Continuous evaluation**: production sampling + drift alerts + cost gates.

### 3.4 Non-goals (deliberately not doing)

- Starting a separate KB suite beside the harness general agent to replace the current tool set
- Buying a simpler UI by hiding trace fields in the presentation layer

## 5. Common commands (current)

```bash
npm test
npx tsx src/cli.ts chat
npx tsx src/cli.ts ask "单次问题"

# Session API + static host (prefers web/dist after SPA build)
npx tsx src/cli.ts serve --port 8787
# or: npm run serve

# Trace 面板（ADR-0020：同进程入口；HTTP 探测 serve 后打开 /trace SPA）
npx tsx src/cli.ts trace
# 同进程未起 / 想独立跑：保留独立进程 24881
npx tsx src/cli.ts trace --separate

# Frontend SPA (package under web/)
npm install --prefix web
npm run dev --prefix web      # Vite :5173, proxy /api → :8787 (run serve in another terminal)
npm run build --prefix web    # → web/dist  (root alias if present: npm run web:build)
# root alias if present: npm run web:dev
```

Configuration: `.env.local` + API keys in environment variables (see `docs/llm-config-quickstart.md` and the root `.env.example`).
