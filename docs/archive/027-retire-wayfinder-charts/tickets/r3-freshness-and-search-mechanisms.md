# R3 写前新鲜度与搜索面的机制选项

- Map: [ACI 文件/搜索工具面（整体升级决策）](../aci-file-tool-surface-map.md)
- Type: `wayfinder:research` (AFK)
- Status: resolved
- Blocked by: —

## Question

把「写前必须先读」和「搜内容工具长什么样」拆成**机制**（不是产品名）：

1. 新鲜度权威常见有哪几档（会话级 path 登记、扫对话历史、只在失败文案说话、edit 内自动再读）？哪一档能覆盖「同回合刚读就改」？
2. 搜内容工具常见输出形态：默认回匹配行，还是默认只回路径？上下文行 / 分页要哪些执行期不变量（排序、parser、exit 归因）才不会静默错行？
3. 参数展示名（短旗标 vs 驼峰、`limit` vs 别名）是不是契约？和本仓 ACI 统一 `limit` 怎么相处？

落盘只写机制与取舍，**零外部产品名、零「参照某某」attribution**。可上网，但不得把来源写进本票或任何仓库文件。

## Resolution

1. 新鲜度权威四档
   - **会话级 last-read 登记**：`read_file` 成功即按规范 path（可附指纹）入表；`edit_file` 查表。权威在进程内表，不在对话快照。
   - **对话历史扫描**：从已落库的消息里反查「读过该 path」。跨回合或许可用；同波工具结果通常尚未进快照。
   - **失败文案引导**：仅在 `old_str` 未命中 / 多处命中时点名再读。成功路径无闸，猜对片段即可过。
   - **handler 内自动再读**：写前 handler 自读现态再套替换（或仅在表缺/指纹变时再读）。权威是磁盘现态。
   - **「同回合刚读就改」**：能覆盖的是 **handler 内自动再读**（不依赖消息/登记时序）。**会话级 last-read 登记**仅在 read 成功落表之后、edit **串行**启动时覆盖；同波并行会竞态。历史扫描与失败文案盖不住这一档。

2. 搜内容输出形态与不变量
   - 默认常见是 **匹配行**（`路径:行号:行内容`），与现行契约一致；**仅路径** / **计数**是可选模式，不是默认替换。
   - 上下文行或分页要先钉执行期不变量，否则会静默错行：
     - **稳定排序**（先 path、再行号）必须发生在截 `limit` 之前。
     - **专用 parser**：匹配行 `:`、上下文行 `-`、组分隔 `--` 分列处理，禁止「第一个冒号切三段」。
     - **exit 归因**：有匹配 / 无匹配 / 工具失败三态分开；无匹配不得当失败，失败不得当空成功。
   - 模式切换只换投影，不换上述三条。

3. 展示名 vs 契约名，与统一 `limit`
   - **契约**是 schema 属性名（模型实传）。短旗标、驼峰口语、`head` / `maxResults` 等是 **展示名**，不是第二套入参。
   - 本仓 ACI 已在 `read_file` / `glob` / `grep`（及若干列表件）统一 **`limit`**。搜内容继续用这一个名字；description 可写同义，schema 不加别名并行。
   - 单件为展示习惯改名会撕裂统一 `limit`，本切片不取。
