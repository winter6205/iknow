## Question

过程中的一问（G0 先定顺序）：`grep` 契约扩到哪？默认输出形态变不变？本票不预选。

- A：纯加法一个输出模式枚举，**默认仍是现状**（匹配行 + `limit`）。不改名、不加上下文行、不加分页。
- B：输出模式 + 上下文行 + 分页，**必须与 parser 重写 + 稳定排序 + JS 侧切片同票**，不可拆。
- C：本切片不动 `grep`。
- D：改默认输出形态（例如默认只回路径），视为破坏性变更，要单独说清迁移与黄金集。

撤回「只为对齐外部展示名而 rename `limit` / `ignoreCase`」。`multiline` / 语言 `type` 不在本票（见地图 Not yet specified）。不在本票改代码。

## Progress

操作员要求拆成逐问，不一次裁整档。

1. 默认出法：同意改为**只给路径**（不说则不吐匹配行）。
2. 可选出法：同意 **匹配行 + 计数** 两档都加。
3. 附近几行：同意做，与 parser、稳定排序**同票**，不拆。
4. 分页：同意做，同票；结果名单跳过前 N 条再取（文件列表/命中列表），不是读文件行窗。偏移过头 ≠ 没有匹配。
5. 条数：默认 **50**、硬顶 **2000**；三种出法同一个数。2026-09-12 再裁：改名为 **`head_limit`**（不叫 `limit`，不叫 `grep_limit`）。
6. 按文件名收窄：同意要（目录 `path` + 文件名模式）。
7. 按语言类型收窄：同意要，与解析、错误归因、无引擎降级**同票**（文件名模式仍在；`type` 是并列收窄，不是替代）。
8. 跨行：同意 **行窗**（`also` + `within_lines`），不做裸跨行正则开关。
9. 搜引擎：同意安装/发版按平台下载钉死版本+校验和，运行只 exec 安装根这份；PATH 不当主路径；Node 扫仅当自带起不来。

## Resolution

`grep` 契约要变，不是「只换后端」。默认改为只给路径；可选匹配行 / 计数；附近几行 + 结果名单分页（`offset`，过头 ≠ 无匹配）与 parser、稳定排序同票；`head_limit` 默认 50、顶 2000；文件名模式 + 语言类型并列收窄；跨行用行窗（`also` 是附近过滤，不是展示；落地后实测，问题写入计划汇报），不做裸跨行正则（收尾汇报提一句）。引擎：安装时自带钉死二进制，不依赖 PATH；Node 扫只当自带起不来。落地须本地跑现行被 CI 排除的 `grep` 测试；CI 进引擎后可再议拿掉排除。不改代码。
