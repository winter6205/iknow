## Context

ADR-0023 ruling 4 once locked "v1 = single root + recents + three anchors unified; worktree/multi-root read-only deferred". What was deferred then was **product workspace multi-root** (several roots bound to serve's main root), not the physical problem of multiple sessions (or session and human) co-writing one checkout. The operator's later ask is a different thing: concurrent edits by several sessions (or by a session and a person) in the same checkout trample each other — the cure is git worktree, not more main roots for serve. This ADR therefore **reopens one narrow exception within ADR-0023's deferred surface**: session-level git worktree isolation, controlled by a global switch, default off; ADR-0023's serve single-root + recents + three-anchors-unified semantics stand untouched, neither covered nor silently modified by this ADR.

Nail the boundary first: **git worktree ≠ product workspace multi-root**. A worktree is a git-level physical checkout serving exactly one purpose — isolating write conflicts; `workspace` / `workspaceRoot` (ADR-0019 / ADR-0023) are product-level main-root and per-root state anchor semantics, and this ADR does not move them.

The specific background of the 2026-09-02 reopen: the original §1 described "block the first mutate → host `git worktree add` creates the task worktree → rebind the current session root anchors" as an automatic gate action. That description did not match the shipped implementation — `src/harness/isolation/worktree-gate.ts`'s comment states plainly "NEVER provisions (no `git worktree add` on the execution path)", with tree creation entirely owned by "the create-worktree ACI tool"; in the intermediate state "will write but no tree yet" the gate is only an observable block reading "unbound → have the model call the tool". Meanwhile, the plain meaning of "a mutate within the same run lands on the new tree after the tool succeeds" directly contradicted the ruling "same-turn mutator listed as non-goal": trace evidence showed that rejection makes users give up. This ADR therefore completes the model-provision contract, makes `taskRoot` a live root, and explicitly rescinds the old ruling.

## Decision

Adds a global switch `settings.isolation.worktreeOnMutate` (boolean-only, **default OFF**; missing or non-`true` values count as OFF, the same fail-closed value-domain discipline as `settings.memory.autoExtract`). The exact field wiring and type landing are left to implementation in `src/config` (the single fail-closed read site is `src/config/settings.ts:236`); this ADR locks the semantic contract.

### 1. Two-state switch (hard requirement 1)

- **OFF (default)**: session behavior is exactly today's — reads, writes, permission, directories all as-is, zero new interception points. (**Marked superseded by the 2026-09-06 reopen, for the bash fence physical surface only**: the OFF tier's fence is equally closed-world, see §9.1; the gate, root rebind, and permission semantics unchanged. Default FS posture superseded by ADR-0092: default global tier.)
- **ON**: the session may treat the main checkout as **read-only** (read / grep / glob / read-only bash and other read paths pass and may stay in the main checkout); the moment a **write path** appears (write_file / edit_file / bash that mutates the workspace, etc.), the gate **blocks** that write — the host does **not** auto-`git worktree add`; instead **the model calls "the create-worktree ACI tool"** to create the task worktree (including the task branch) and rebind **the current session's** root anchors; tool success = the tree exists and the session root has switched to that path, after which this session's mutates only land on that root. Once this session is bound to a task worktree, write paths pass directly and no second tree is created. (**Superseded 2026-09-19, bash half only** (ADR-0109): "bash that mutates the workspace" is no longer predictively blocked — at the unbound tier the fence physically `--ro-bind`s the main checkout and bash passes unconditionally, real writes coming back as EROFS violations with feedback text naming `create-worktree`; write_file / edit_file pre-blocking stands, and "never auto-provision" stands.)
- **Orthogonal tier `isolation.worktreeExclusive` (added 2026-09-08, ADR-0070)**: **orthogonal** to this switch, boolean-only, default OFF, same fail-closed value-domain discipline. When ON, `enter-task-worktree` adds one precondition — if the target tree is occupied by **another existing session** (test = the `workspaceRoot` recorded by a live session, zero new persisted state), a typed refusal (`worktree_claimed`). **This section's OFF / ON two-state semantics and the gate's adjudication logic are unchanged**; the OFF tier's enter behavior is byte-identical to today.

### 2. Rebind affects only this session (hard requirements 2–5)

Creating a worktree must rebind this session — a tree without a binding = non-compliant. Rebind does not check out other sessions' / other worktrees' HEADs; pushing / opening PRs inside a task worktree must not drag the current branch of the main checkout or of other worktrees. Concurrent shared writes to the main checkout are not the target shape: this feature is **optional isolation**, not the tool guessing "whether to start a task" for the operator. A subagent spawns from the parent session and follows the same tree after the parent's rebind, never triggering a second tree (root-ownership semantics narrowed and landed by ADR-0040).

### 3. Determinate policy when the task worktree / task branch name already exists (hard requirement 8)

Fail-closed: the create-worktree ACI tool returns the model a **visible typed error — no silent overwrite, no reuse of a tree of unknown ownership, no checkout of another session's HEAD**. Concurrent first mutates within one session (hard requirement 7) are not in this bucket — tree creation is idempotent: several write paths arriving together before creation completes still produce exactly one worktree / one task branch and no double write into the main checkout.

### 4. Session roots divided by role: rebind switches only `taskRoot` (relation to ADR-0019 / ADR-0023)

This section's text was locked by amendment on 2026-08-31: "rebind switches only `taskRoot`, leaving ADR-0019's per-root state anchors alone"; the 2026-09-02 reopen additionally upgrades `taskRoot` from an assembly-time frozen field to a **live root** — its liveness boundary is in section 7.

The session holds four roots **by role**, none doubling for another (`productRoot` / `taskRoot` / `installRoot` are session roots; `projectIdentityRoot` is a project root — rebind does not move it):

- **`productRoot`** — the main checkout opened at session start, pinned at first assembly, unchanged across rebinds and process restarts (on restart it may be derived from the task tree's git common dir). `mcpConfigRoot` consults only it, derived from it. **Project identity** (rules / project `AGENTS.md` / `permissions.toml` / project skills discovery, the identity root inherited by subagents, the memory-store namespace name) consults not `productRoot` but **`projectIdentityRoot`** — the project the user is actually working on, pinned once at host startup (today = startup cwd), unmoved across rebinds, falling back to cwd when absent (the hub's per-root rebuild gains one more intermediate fallback level: pinned value → current `boundRoot` → `root`). The assembly layer applies **`mainCheckoutOf` to both the pinned value and the fallback** — the identity root must not be a task worktree. The value is decided at the assembly layer, **validated through the session-root SSOT** (the fourth role of `resolveSessionRoots`; empty / relative values fail closed as typed errors, never interpreted against `process.cwd()`). Under the `--workspace-root <dir>` redirection, `<dir>` is not the project (`dir ≠ cwd`), and querying identity with it would silently erase the project's own rules / ruleset / skills. **Per-root state** (memory-store location / tasks registry) is anchored at `workspaceRoot`, but since after rebind `workspaceRoot` itself is already a tree, it falls back to `productRoot` — so ADR-0019 D1.3's `--workspace-root <dir>` redirection still works, while state never lands in a gitignored tree. The memory store's **namespace name** is determined by `projectIdentityRoot`, neither by `taskRoot` nor by the anchor: several projects under one anchor must not collapse into one namespace. Settings read / watch / write-back anchor is the root resolved **at startup**, and rebind does not reload it (see §5), so settings do not follow `taskRoot` either.
- **`taskRoot`** — this session's task worktree (create / enter switch to it, exit switches back to the main checkout). **Writes and tool cwd consult only it**: `write_file` / `edit_file` / bash that mutates the workspace / git / LSP directory / subagent working directory. `taskRoot`'s liveness is in section 7 — it is the core addition of this ADR's 2026-09-02 reopen; decision and SSOT in `src/harness/session-roots.ts`.
- **`installRoot`** — iknow's own runtime installation location (worker bootstrap resolves tsx and its own dependencies). **≠ the user project's `node_modules`**, so a real worker still starts on a bare task worktree.

ADR-0019 D1.1's default resolution (`workspaceRoot` defaults to `process.cwd()`) and serve's main root (ADR-0023, explicitly selected + unbound semantics) both stand — a rebind is not a serve-main-root rebinding, touches neither recents nor trust, and does not promote a git worktree into product workspace multi-root. The main checkout stays in place, read-only.

Accompanying hard constraints:

- A successful rebind **copies and seeds nothing** — the tree gets no `.iknow/{rules,skills,memory,sessions,tasks}` from the main checkout; missing directories on the tree count as empty, and project identity still reads the existing files at `projectIdentityRoot`.
- Callers are forbidden from using `join(cwd, '.iknow', …)` or `join(workspaceRoot, '.iknow', …)` as project identity; always take paths by role through the session-root SSOT, fail closed on a missing root / relative path, and **never fall back to `process.cwd()`**.
- The **parent-session engine's** tool sandbox, **when the isolation switch is ON and rebind has happened** (`isolationEnabled` and `taskRoot` is a task worktree), grants a **read-only** channel to `projectIdentityRoot` (same source as §1's "read paths may stay in the main checkout"; implemented as a read grant over the entire identity-root tree — it may be a **subdirectory** of the main checkout, not a per-path identity allowlist); writes still must not enter the main checkout. This grant is new in this change: at the OFF tier "today" grants **none at all**, so the door must also check the switch — `taskWorktreeOwnerOf` alone is only a path-shape test, and on its own a cwd that merely happens to be shaped `<X>/.iknow/worktrees/<name>` would get an out-of-sandbox read grant while isolation is off. Known gap (not yet filed): only `read_file` gets this grant; `grep` / `glob` stay confined to `taskRoot`; the subagent worker's registry does not get it either (the worker's rules are piped in, not read).
- User-level `~/.iknow` (profile, user rules / `AGENTS.md`, `init.sh`, trust) keeps following `home` — neither `productRoot` nor `taskRoot`.

### 5. Configuration read contract (hard requirement 9)

The switch is read exactly once at the **startup load point**; the config layer carries boolean value-domain semantics only — **it does not read git and holds no session state**. A session-root rebind **does not implicitly reload** project settings: the settings source keeps its startup assembly result for the session's lifetime; if "reload settings after rebind" is ever wanted, it must be an explicit separate decision — silently switching the settings source is not allowed.

### 6. Failure semantics fail-closed (hard requirement 6)

Main checkout is not a git repository / git unavailable / the create-worktree ACI tool fails (`git worktree add` or the rebind fails): mutates are uniformly blocked with a **typed, non-empty, visible** error (aligned with the harness fault-class and session-api `WorkspaceRootError` typed-error conventions), **never silently letting writes into the main checkout** — zero writes to the main checkout after a create/bind failure is an acceptance item, not an implicit assumption. A missing or illegal switch value falls back to OFF, i.e. exactly today's behavior, from the same fail-closed source.

The boundary of "main checkout is not a git repository" (2026-09-07 amendment): the **only** trigger for `not_a_git_repo` is that the session root has no usable gitdir (`git rev-parse --git-common-dir` or an equivalent probe fails). A bare gitdir and a `core.bare=true` checkout that can `git worktree add` are both usable git repositories and must not be misclassified as non-git just because the root "does not contain / is not merely working files" — the test is tree-creation capability, not the existence of working files. A git spawn failure → `git_unavailable`. An empty bare with no commits **is still a usable gitdir and never collapses into `not_a_git_repo`**: the outcome of `git worktree add` is adjudicated by git itself and varies by version (older versions, having no HEAD to branch from, fail → `worktree_add_failed`; git ≥2.53 measured to infer `--orphan` and succeed), and the tree-creation function does not pre-adjudicate for git.

### 7. Live `taskRoot` (added by the 2026-09-02 reopen)

`taskRoot` is not a field resolved once at session assembly but a **live root that changes within this run as trees are created / exited**. Its contract is locked by the sub-decisions below (this ADR locks only the contract boundaries; file / function / type names are left to implementation).

#### 7.1 Single writer (D1)

The live holder sits inside the session-root SSOT module (the existing single root-policy point, whose doc already states "writes and tool cwd consult it only"); `resolveSessionRoots` stays a pure function — its "no git reads, no filesystem, no session state" constrains it alone. **The single write entry = the harness assembly layer's wrapper around the host `provision` / `enter` / `exit` seams** (writing only when a seam resolves successfully). On failure: no write, no rollback, the typed error bubbles as-is, and the zero-writes-to-main-checkout guarantee stands. Hub / CLI-side semantics are unchanged — they only observe the returned root for dirty-root persistence.

#### 7.2 Batch snapshot semantics (D2)

One `executeAll` call (= one wave of tool calls) reads the live root **once** at entry and the whole wave shares that snapshot. Reason: the gate lets mixed/mutating batches through call by call, so reading the live root per call would split one wave half onto the old root and half onto the new — cleaving one logical change across two trees, an astonishment violation. Rebind therefore takes effect on the **next wave of tool calls within the same run**, not on the current wave or the next turn.

#### 7.3 Stable root list (D3, strictly no activation)

All of the following roots remain assembly-time frozen and do not follow `taskRoot` rewrites:

- `productRoot`, `projectIdentityRoot`, `installRoot` — all three survive rebinds unchanged (reasons in §4).
- `mcpConfigRoot` — derived from `productRoot`, stable across rebinds.
- `stateAnchor` — the per-root state anchor (settings write-back / worktrees); state never lands in a gitignored tree.
- `memoryDir` — the home project tree's `projects/<slug>/memory/` (ADR-0099), frozen across rebinds, not following `taskRoot`.
- `todoDir`, `traceDir` — stable roots from the same source.

In particular ADR-0037 §4 already constrains: per-root state **never** lands in a gitignored tree, and a live `taskRoot` must not drag `stateAnchor`.

#### 7.4 Rebind effective boundary (run / turn existing vocabulary)

This ADR refuses vague wording like "next turn" and pins it using **run** (:185) and **turnCount** (:26) as already defined in `docs/CONTEXT.md`:

- One **run** = one `run()`, from a user's instruction until control returns to the user; it may contain many tool loops and produce many messages.
- One **turn** = one assistant ↔ tool_result closed loop inside `run()`, and `turnCount` increments once per completed assistant turn.

After `create-task-worktree` succeeds at turn N, the live `taskRoot` flips to the new root immediately; per 7.2's batch-snapshot semantics, **mutates within the same wave of this turn still use the old root** (one snapshot value for the whole wave), and from the **next wave of tool calls** of the same run onward all mutates land on the new root. No operator message is required between runs, and `/continue` is not needed. This effectiveness boundary directly closes the measured root cause of "same-run mutates permanently blocked".

#### 7.5 Mutator gate wording correction

The old wording "re-issue next turn" is corrected per 7.4's run / turn vocabulary: both the gate text and `create-task-worktree`'s success text become "the next wave of tool calls within this run will land on the new root", dropping "next turn".

### 8. Explicit rescission: same-turn mutator listed as non-goal (2026-09-02)

The ruling implied by the original §1 / §2 — "propagation of same-session mutates after tool success is a non-goal, triggered by the operator's `/continue` starting the next run" — **is rescinded as of this reopen**. Two reasons, both measured or straight from the spec text:

1. **Trace disproof**: on 2026-09-02, the trace of `conversation_id = d52e0f28-703c-439a-bce4-3a3ae1017139` (run `9b69b055`) shows that after `create-task-worktree` succeeded at turn 0, three mutates at turns 1/3/4 were still permanently blocked with the same "unbound" message, and turn 5's read_file not_found was a downstream consequence of the blocked write.
2. **Spec-text violation**: the amended text rescinded by `4b4fa6fe` (model-provision amendment, `git show 4b4fa6fe^:docs/adr/0037-worktree-isolation-on-mutate.md`) plainly states: after tool success Host only guarantees the path is switched: it replays blocked writes **in a different wave**, never secretly executing them — the model **re-issues** each blocked write itself on the new root at the next turn; **the operator is never required to `/continue`**. Rescinding the old ruling restores this spec text as the live contract.

New ruling: **within the same run, from the wave of tool calls following `create-task-worktree`'s success, mutates land on the new root; no operator message is needed in between, and `/continue` is not needed.** The precise effective boundary is §7.4.

### 9. Closed-world bash fence: all-tier deny-by-default inversion and allowlist adjudication (2026-09-06 reopen)

> **Superseded 2026-09-13** (ADR-0092): the **default FS posture** adjudicated in this section is superseded — the default is no longer a closed-world fence but the **global tier** (host real paths readable and writable, home not hidden), and the session tmp uses a host path and is no longer bound as `/tmp`. The fence still runs (network / env / rlimit / FS sandbox). The workspace tier (later) may reuse §9.2's write allowlist.

This section was landed by the 2026-09-06 reopen, answering the three background defects: under a writable-home base, other projects / any path under home are writable inside the fence (a blacklist can never be exhaustively enumerated), persistent execution config had only `overlaySensitivePaths`' one tmpfs layer of cover, and `~/.iknow/init.sh` is a persistent executed file (the core concern of this reopen). Evidence source: the inventory of `scripts/sandbox-probe-closed-world.ts` (**archived 2026-09-13** to `archive/onetime-probes/closed-world-inventory-probe.ts`) (commit `d777c050`) — legal scenarios measured one by one under an assumed fence of "system ro-bind + cwd writable + /tmp, no writable home bind", producing 16 BREAKs (node/npm/npx/bun exit 127 command not found, git global config reads and worktree operations exit 128, `~/.iknow` / `~/.claude` invisible exit 2, login shell rc unreadable, every home entry of the host PATH unreachable, etc.).

**Closed-world fence**: non-allowlisted paths under home are **invisible** — not "visible but read-only", absent from the mount surface; the writable set = `taskRoot` + `/tmp`; every read channel outside the allowlist is deny-by-default, opened explicitly by ro-bind on demand. (Default FS posture superseded by ADR-0092: default global tier.)

#### 9.1 All-tier semantic inversion (a)

- The inversion applies to **all tiers** (OFF / ON / after rebind): the OFF tier's bash fence is equally closed-world. (Default FS posture superseded by ADR-0092: default global tier, no longer closed-world.) Reason: if OFF kept a writable home, other projects would stay writable at the default tier, root cause 1 would never close, and the inversion would be meaningless for the default usage surface.
- Therefore **superseded** (for the bash fence physical surface only): §1 OFF's promise, within "session behavior identical to today", about fence argv and home visibility; Amendment 2026-09-05 (d) "OFF / unbound = argv byte-identical to today"; the Positive item "default OFF guarantees a zero-regression path". The rest of §1 OFF's semantics (the gate does not block, roots do not rebind, permission status quo) is unchanged.
- Harness-layer writes (memory_save / settings write-back / trust / recents / state.json) do not go through the bash fence, so the closed world does not touch them; hence the "memory_save compatibility" concern is not an allowlist item.

#### 9.2 Read/write allowlist adjudication (b)

The read allowlist, itemized with the reason each is present (each traceable to inventory evidence):

1. **System prefixes** `/usr` `/bin` `/lib` `/lib64` `/etc` (kept as-is) + optional host prefixes `/opt` `/snap` (skip-if-absent, kept as-is) — the host of the toolchain and base commands; the inversion does not dismantle this existing ro-bind group.
2. **`taskRoot` (cwd)** — writable bind, the working tree itself. "Writes and tool cwd consult only it" (§4) is realized physically as this writable bind.
3. **`/tmp`** — writable. The process's ephemeral surface, and the landing spot for rejected caches of npm / pip and friends. Backing and lifetime per ADR-0074 (per-identity host-backed, following the session); not a delivery landing spot. (The bind surface superseded by ADR-0092: session tmp uses a host path, no longer bound as `/tmp`; the per-identity backing and lifetime still stand.)
4. **`installRoot`** — `resolveSessionRoots`' existing fourth role (§4), the read channel for the project's own toolchain (`node_modules/.bin`, tsc, etc.); a contract input, fail-loud per §9.4 configuration-fault class.
5. **node toolchain root** = `dirname(process.execPath)` (the directory of the node running the harness); npm / npx reachable via the node root. Measured in the inventory: inside the fence node / npm / npx all exit 127 command not found, `which node` exit 1 (this machine's node chain = `~/node/bin`, not the `~/.nvm` shape). If node already sits under a system prefix, this root collapses into item 1 with no new bind; a contract input.
6. **`projectIdentityRoot` (main checkout)** — under the closed world it **always** enters the read allowlist, no longer a conditional overlay / conditional read-only grant (§4's "parent-session engine tool sandbox … read-only channel" accompanying constraint is taken over by this item). The main checkout's `.git` gitdir becomes reachable accordingly, fixing the broken worktree repo discovery measured in the inventory: `git -C <taskRoot> status` / `git var GIT_COMMITTER_IDENT` exit 128 `fatal: not a git repository` — a worktree's `.git` file points at the main gitdir, and repo discovery dies first when the main checkout is unreachable. Supplied by the assembly layer only when `isolationEnabled` (same passing condition as today; when unbound, `.git` is inside cwd and needs no extra read channel), no longer conditioned on "rebound"; a contract input, fail-loud per §9.4 configuration-fault class.
7. **git global config** `~/.gitconfig` and `~/.config/git/config` — **optional read members, skip-if-absent** (absence must not explode, unlike the contract roots). Fixes the `Committer identity unknown` measured in the inventory (`cd /tmp && git var GIT_COMMITTER_IDENT`, the pure identity axis pinned to the isolation-at-/tmp entry). When absent, git identity resolution fails = a runtime-observable error (§9.4 runtime-observable class); single-file, read-only, low risk surface.

**Write allowlist: `taskRoot` + `/tmp`, nothing else.** (Default FS posture superseded by ADR-0092: default global tier; the workspace tier may reuse this allowlist. **ADR-0109 amendment 2026-09-19**: at the worktree-gate-ON ∧ unbound tier (waveRoot = main checkout), a `--ro-bind` of the main checkout is remounted over that root's writable bind (after the rw bind, before `--proc`, last-mount-wins), so real writes on the `taskRoot` tier in fact get EROFS; the session fence tmp pad is remounted rw after the shadowing mount, and scratch writes go to the pad. At the bound / gate-OFF tiers this allowlist is byte-for-byte unchanged.)

Explicitly not on the allowlist (rejection reasons on file, to pre-empt relitigation):

- **`~/.bun`**: bun is used only by host test workflows; a broken link inside the fence is observable and acceptable (inventory: `bun -v` exit 127, evidence on file).
- **npm / pip caches**: rebuildable; cache writes inside the fence should land in `/tmp` (inventory: cache-directory reachability test exit 1, unreachable in consequence).
- **`~/.claude`**: a credentials and session-data surface; not readable either (inventory: `ls` exit 2, invisible, kept).
- **shell rc files** (`~/.bashrc` / `~/.profile`): login bash already works (inventory: `bash -lc 'echo ok'` exit 0; unreadable rc is non-fatal for login bash); rc invisibility removes a persistent side-effect surface and is an accepted — even favorable — item.
- **`~/.iknow`**: granting read = granting an executable surface (`init.sh` is a persistent executed file; closing exactly this surface is what the closed-world ruling is for); memory writes do not go through the bash fence and need no read channel (inventory: `ls ~/.iknow` exit 2; `init.sh` does not exist on the host at all = skip).
- **`~/.ssh`**: by design (same inventory entry; invisibility is the design intent).
- **PATH passthrough (ruling: no rebuilding / no env pruning)** — PATH enters the fence **verbatim** via `BASE_ENV_WHITELIST`, with no pruning/reassembly at the env assembly layer; unreachable home-mounted entries **naturally drop out** at the mount surface (directory invisible → command resolution fails), and env itself is never rewritten. Inventory: of the host's 56 PATH entries, all home-based ones are unreachable; broken links are the runtime-observable class (§9.4) and do not auto-extend the allowlist.

#### 9.3 Amendment 2026-09-05 identity-overlay clauses superseded (c)

Reason: under the closed world home is not writable, so the "writable ancestor covering the main checkout" defect disappears; the overlay was a patch over the writable-home shape and has nothing to operate on once the parent shape is gone; the identity root is demoted to a read-allowlist member per §9.2 item 6.

- **Superseded**: (a) the overlay condition (mount the overlay only when ON and rebound); (b) the argv-order contract (the shadowing order of the identity root's `--ro-bind` after the writable home `--bind`); (d) OFF / unbound = byte-identical argv; and within (e) the overlay framing of "the same overlay token".
- **Standing**: (c) the fail-loud clause (blank identity root / absent on disk = typed error, no spawn; silent `existsSync` skipping forbidden) is not superseded — §9.4's configuration-fault class inherits it and extends it to all contract-input roots; (e)'s model-visible write-root semantics and §7.2's batch-snapshot semantics (D2) are not superseded — the requirement that foreground (`bash.ts`) and background (`defaultBackgroundSpawn`) of the same wave consume the **same fence policy** is kept in new words (CONTEXT's "sandbox discipline" unchanged).

#### 9.4 Typed fail-loud classes for allowlist misses and the EXIT clause (d)

- **Configuration-fault class (contract inputs, fail loud before spawn)**: an allowlist contract root is **blank or absent on disk** — `installRoot` / `projectIdentityRoot` / `taskRoot` / tmp / node toolchain root (the writable roots of §9.2 items 2, 4, 5, 6). Throw a typed error (of the `ToolExecutionError` family, aligned with Amendment 2026-09-05 (c)'s discipline), **do not spawn**, no silent `existsSync` skipping. Error surface: the tool execution throws directly and bubbles to the caller. **EXIT = the tool call fails**; the session does not silently degrade.
- **Runtime-observable class (toolchain breakage)**: a non-allowlisted binary unreachable (e.g. a `~/.nvm`-shaped node chain), a command not found because verbatim-PASSED home PATH entries dropped at the mount surface (§9.2's "PATH passthrough" — no pruning/reassembly at the env assembly layer), git identity missing, or the optional git global config absent (§9.2 item 7). The command exits non-zero and stderr bubbles normally through the tool result — **no silent degradation and no automatic allowlist extension**. Error surface: the model observes the failure at the tool-result layer. **EXIT = the single command fails**, observed and handled by the model at the tool-result layer (switch command / reroute / report).

## Consequences

### Positive

- Concurrent sessions no longer trample each other: under ON, the first mutate gives the session a physically isolated write directory, and the main checkout stays read-only.
- Default OFF guarantees a zero-regression path; behavior changes only on explicit operator opt-in. (**Marked superseded by the 2026-09-06 reopen**: the fence inversion is an all-tier semantic change; the OFF tier's bash fence is equally closed-world, see §9.1. **Default FS posture superseded by ADR-0092**: default global tier.)
- The git worktree ≠ workspace multi-root boundary is written down, keeping this switch from being tangled up with serve's main root / `workspaceRoot` semantics.
- With the model-provision contract and the live `taskRoot` in place, the whole "block → tool creates the tree → mutates land within the same run" chain needs zero operator intervention, and fail-closed never degrades.

### Negative / Trade-offs

- Under ON, the first mutate adds tree-creation cost and a session root switch, and the operator must be able to tell which tree is currently bound (the display surface is left to implementation).
- When a task worktree / branch of the same name already exists, fail-closed errors — a leftover orphan tree must be cleaned manually before a same-named task can proceed.
- Live-root semantics impose a new "takes effect across waves" constraint on consumers: a consumer must tolerate the root value changing between batches within one run, must take the root per batch snapshot, and must never resolve different roots across multiple calls inside one handler. The gate itself follows §7.2 in sync.
- The "commit → push → PR" product wizardry and GitHub / `gh` authentication are outside this ADR's scope, handled on a separate track.

### Reversibility

- Switching OFF fully restores today's behavior; created task worktrees are standalone directories — deleting one reclaims it without affecting the main checkout or other worktrees.
- §7's live-root mechanism can be switched off through the same root-SSOT interface (the writer reverts to a one-time assembly-time freeze) without breaking the four session-root roles.
