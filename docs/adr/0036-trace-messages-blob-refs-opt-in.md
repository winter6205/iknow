# 0036. Trace messages blob reference mode (opt-in, default full)

Date: 2026-08-28
Status: accepted

Background: measurement showed that 98.2% (226.5 MB) of the 263.5 MB `trace/` directory is byte-for-byte duplication of the full cumulative message history embedded in `llm_call` lines (largest single line 891 KB). The write side's "no size cap" is a deliberate choice that preserves "what the model actually saw"; truncation is off the table. Decision: add an opt-in storage mode `IKNOW_TRACE_MESSAGES=blob` (default `full`, byte-shape fully compatible with current behavior) — in blob mode each messages element is replaced by a content-addressed reference `{sha, bytes}`, and the body, after masking, is written to `<traceDir>/blobs/<sha>` (write-if-missing). `messages_captured` semantics are unchanged: what gets captured is still the complete message set the model actually saw; only the physical storage changes (deduplication).

**Why not write-side delta/off modes**: either would substantively amend the "what the model sees is what gets recorded" invariant, and would break the `messages_captured===true` assertion in `tests/e2e/subagent-foreground-trace.test.ts:164`; the reference mode eliminates the same redundancy while preserving the invariant. **Why not read-side projection only**: the O(n²) disk bloat and maskJsonLine's per-line rebuild CPU on multi-MB lines can only be cured by write-side deduplication.

**Negative / Trade-offs:** in blob mode message bodies are no longer directly greppable inside JSONL lines (bodies live in `blobs/<sha>`, reachable by sha) — ADR-0003's "JSONL the dev can grep" continues to hold under the default `full`; blob users trade a discoverable sha reference for a 7x disk win; `blobs/` needs a reclamation policy (rotation of orphans, to be worked out during implementation planning).

## Amendment 2026-09-08 (ADR-0071)

This ADR's core decisions (messages elements replaced by content-addressed references, bodies masked then written to `blobs/<sha>`, write-if-missing, `messages_captured` semantics unchanged) **stand as originally written**. Three items are revised below:

**1. Dedup granularity: whole message → `content` (`role` stays inline).** The original design replaced the entire message element with `{sha, bytes}`, dropping `role` along with it. That was a **design error**, not a trade-off: the read side `query_trace` consumes raw rows directly (`query-trace-core.ts:225-244`), and `messageRole()` (`project-tool-results.ts:48-51`) returns undefined for `{sha,bytes}`. Switching to `{"role":"user","content":{"sha":…,"bytes":…}}` lets `messageRole()` classify correctly with **zero changes**; the read side only needs content-level dereferencing added at the single preview site (reusing the existing `dereferenceTraceMessages`). The dedup win is unchanged — the body is what repeats; `role`'s few bytes are negligible.

**2. opt-in → sole mode.** `IKNOW_TRACE_MESSAGES` / `MessageStorageMode` / `resolveMessageStorageMode` are retired. Basis: nine days after this ADR was accepted, measurement found the `blobs/` directory **absent on disk** and `trace/` still 337 MB / 82 files — **a switch that defaults off is functionally a feature that doesn't exist**.

**3. Remove the failure fallback, but leave the exception contract untouched.** When blobs cannot be written, **never emit an inline full row** (the original "falls back to the masked full row" path is retired). But the throwing layer stays pinned at the **inner blob IO**: swallowed by the existing `safeTrace` / recordFailure warn-once → `recordLlmCall` returns `undefined` → zero rows land for that call → the turn survives; per ADR-0003 **D14**, the downstream `recordToolCall` still records with `parent_llm_call_id: null`. **ADR-0003 D13 (`recordXxx` MUST NOT throw) is inherited verbatim, not amended.**

**The cost this ADR failed to record at the time (recorded now)**: the Trade-offs section noted only "blob mode makes message bodies non-greppable inside JSONL lines" and **missed the silent read-side breakage caused by the granularity error** — `first/last_message_preview` would render as dead `{"sha":…}` previews, and `last_assistant_preview` would **silently disappear**; and because `query-trace-core.ts:235-238` explicitly documents "absent field = legitimate state (no assistant message)", **the failure and the legitimate empty state were indistinguishable**. What broke was exactly the flow `:230-232` describes: "an external agent fetching the final assistant conclusion". Assessment: this is the real reason the feature shipped default-off back then, and it never made it into Trade-offs. With the granularity fix (item 1), this breakage is gone.

**The open item was picked up**: this ADR's note "`blobs/` needs a reclamation policy (rotation of orphans, to be worked out later)" was never worked out. ADR-0071 puts `blobs/` inside the **session folder**, lifetime = the session's, so reclamation degenerates to "delete the folder" — no reference counting and no global GC, and no state where the trace survives while its blobs are rotated away. Side simplification: `traceDir` can be derived from `dirname(traceFilePath)`, removing the error-prone parameter pair that forced the `options.traceDir!` non-null assertion at `project-tool-results.ts:161`.

**Mis-citation correction**: this ADR's Why-not section sourced the "what the model sees is what gets recorded" invariant to a deliberate decision in ADR-0014's acceptance discipline. In fact `docs/adr/0014-subagent-foreground-spawn-default.md` is "Subagent spawn semantics: foreground sync as the default contract" and never contains that phrase; the invariant wording **appears only in this ADR's own text across the whole repository** — it is this ADR's own formulation. ADR-0014 `:46` merely treats trace as acceptance ground truth (the `messages_captured` assertion checks the system prompt the model actually saw); that does not make ADR-0014 the owner of the invariant. Citations from now on point to this ADR.

**Positive / Applied (added now)**: the granularity fix shrinks read-side work from "all three preview fields broken + no role classification" to "dereferencing at one preview site"; sole mode plus session-folder lifetime together take 348 MB down to roughly 62 MB (−82%).

**Negative / Trade-offs (added now)**: ADR-0035's crash-forensics completeness gains a **content-side** precondition (`blobs/` writable); the lifecycle side carries no message bodies and is unaffected, so the two sides' sensitivity now diverges — during forensics one must know "`llm_call` absent ≠ that call didn't happen".

Evidence pointers: 2026-08-28 quantitative analysis (99 files, 263.5 MB, 98.2% duplication, 37 MB after dedup); ADR-0006's domain distinction behind its rejection of persisting (regenerable tool output ≠ trace storage format); ADR-0071 (session-folder consolidation and content-addressed trace bodies); 2026-09-08 re-measurement (`trace/` at 337 MB / 82 files, `blobs/` absent; same session trace 41 lines 264K vs transcript 88 lines 72K).
