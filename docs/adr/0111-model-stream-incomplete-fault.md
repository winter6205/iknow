# 0111. Typed fault for incomplete upstream streams: ModelStreamIncompleteError and codified worker exit-code semantics

Date: 2026-09-20
Status: accepted

Amends ADR-0094 (the transport-cause summary surface extends to model-stream transient breaks that carry a cause; viewport discipline unchanged). Amends the parent-side terminal attribution vocabulary of ADR-0101 / ADR-0102 (envelope reason union 4 values → 5; see Decision 2's explicit amendment of the SC9 freeze). Codifies the worker exit-code semantics of archived spec 356-subagent-v1 assumption 16 / SC13, and adjudicates two wording differences in the originals (see Decision 3). **Amends SC9's "reason enum frozen at four values in V1"**: this ADR explicitly approves adding the fifth value `modelTransient` (envelope-freeze.test.ts expectations update accordingly — a contract change, not a weakened assertion).

## Context

When the upstream SSE stream ends without producing a complete assistant message (empty stream / mid-stream break), the SDK throws a bare `Error` (`stream ended without producing a Message with role=assistant`). The fault vocabulary had no "upstream stream incomplete" slot, so this transient fault is systematically misclassified as protocol corruption in three places:

1. the `nonClockFaultOf` default arm collapses it to `protocol_error` (anthropic-adapter.ts:898-915, default :914) → `classifyFault` default → `none` (fault-class.ts:159-160) → zero retries;
2. the bare Error misses loop-engine's catch arm (:1949-1952 only recognize `ProtocolError` / `TransportRetryExhaustedError`) and escapes `run()`;
3. in the worker scenario it lands in cli.ts's catch-all (:615-626) → `[subagent-worker] fatal` + **exit 2** — misusing the code that assumption 16 / SC13 reserve for envelope-protocol crashes; the parent (manager.ts:1512-1543 SC16) marks it `crashed`, indistinguishable from "the envelope is broken".

No new retry mechanism: `withTransportRetry` itself gets zero changes (file diff empty or comments-only, hard gate); the retry budget / backoff / `retry-after` / `transport_retry` stream events are all carried by the existing machinery (with-transport-retry.ts:125-156).

## Decision

### 1. Typed error class = `ModelStreamIncompleteError`, extends `ProtocolError`

- Defined in `src/harness/errors.ts` (typed family :27-60), carrying `readonly visible: boolean` + `readonly cause: unknown` (the original SDK error), mirroring the cause shape of `TransportRetryExhaustedError` (:51-60).
- Extending `ProtocolError` reuses loop-engine :1949-1952's existing `instanceof ProtocolError` clean catch (precedent: `PromptTooLongError extends ProtocolError`, errors.ts:43-45; loop :1912 branch-order convention — **the subclass arm must precede the generic `ProtocolError` arm**). Being caught means a clean round failure with stopReason `protocolError`: no bare throw, and the whole step is not committed (D8).
- `visible` semantics reuse the `clock_timeout` precedent (fault-class.ts:77-85; the criterion comes from race-timers.ts:50-55,112-118's `hadVisibleDelta`): **not visible** (this attempt produced no model output delta at all) → whole-step retry is safe; **already emitted text** → no automatic retry; land as a typed failure.
- Production point: the adapter stream arm `stepStreamArm` catch (anthropic-adapter.ts:561-565, currently only `translatePromptTooLong` :516-525) recognizes this SDK form and throws this class instead. `visible` is read by the stream arm from `wireStreamEvents`' measurement (extend the existing `{start,end}` timing object at :541-542 with one "saw a non-empty visible delta" flag; it is set at the same sites as the measurement marks — text :620 / thinking :637 / input_json :646 — and empty deltas never set it, aligning with the existing empty-delta discipline).
- The SDK's bare Error has no typed class to instanceof → match by message shape (`/stream ended without producing a Message/i` + not an APIError + no network error in the cause chain). The mapping test doubles as an **SDK-upgrade sentinel** (pins the current `@anthropic-ai/sdk` shape; an upgrade turns it RED for human review).

### 2. New envelope reason value = `modelTransient` (explicit amendment of the SC9 frozen enum)

- Do not reuse `protocolError` + a cause field: parent-side attribution must explicitly separate "upstream transient, continuable" from "true protocol corruption"; a cause buried inside a string is not a decision surface.
- Three touchpoints stay in sync: the `SubAgentEnvelope.reason` TS union (envelope.ts:167-168), `PARENT_SCHEMA.properties.reason.enum` (:316-318), and the manager consuming union (manager.ts:67, plus the two casts at :1466-1478).
- **Conflict record (baseline → correction):** envelope.ts:173-176 and `tests/subagent/envelope-freeze.test.ts:72-76` pin the reason enum as "frozen four values for V1" (SC9's decision surface; values outside the enum are rejected :156-163). Adding a fifth value directly conflicts with this ADR's baseline (adjudication 2). Minimum-change adjudication: **this ADR is the explicit amendment authorization for SC9's freeze**; the freeze test's expectation updates to 5 values (still a closed-enum validation, not a weakening). Cross-version degradation: an old parent receiving a new worker's `modelTransient` envelope → ajv rejects → the parent attributes `crashed` as it does today (no worse than status quo); in a single-repo CLI parent and child share the version, so this is a theoretical state.
- Emission points (this adjudication also pins the mapping mechanism; see the reachability facts in Decision 5):
  (a) Inside `runWorkerOnce`'s normal-return derivation arm worker.ts:1229-1241 (`stopReason === "protocolError" || "emptyFinalResponse"` → `toFailedEnvelope("protocolError", ...)`) branch by **the presence of `RunResult.apiError`**: present → `modelTransient`; absent → keep `protocolError`. The existing invariant behind this criterion: the only place in the whole repo that attaches apiError to stopReason=protocolError is loop :1961 `transportApiErrorOf(err)`, and the :1953-1955 comment states it explicitly (only TransportRetryExhaustedError carries a cause → attach); the RunResult.apiError definition is at loop-engine.ts:2273-2275.
  (b) run()'s escape catch (worker.ts:1285-1293): the `instanceof ModelStreamIncompleteError` arm **must precede** the :1289 `instanceof ProtocolError` arm (subclass-order convention, same as loop :1912) → `toFailedEnvelope("modelTransient")`. Verified via Decision 5: normal paths through a step are caught by loop and never reach this arm; this arm serves escapes outside the step-catch surface (e.g. this class thrown by loop epilogue/finalization calls).
  (c) Supporting micro-extension: `transportApiErrorOf` (errors.ts:391-395) also extracts an `{message}` summary when this class is thrown directly (the visible=true no-retry path), with the raw cause passed through `summarizeTransportCause` (:368-384); this makes the invariant "apiError present ⇔ a transient model-stream/transport failure carrying a cause". Effect: the host viewport draws the verbatim "API error" per ADR-0094 (citation convention in the last paragraph of Decision 3), and the existing TUI invariants (protocolError+apiError → dedicated copy; protocolError without apiError → generic copy; tests/tui/error-stop-notice.test.tsx) hold.

### 3. ADR carrier = this ADR (0111); two invariants codified

**Invariant (a): the fault vocabulary contains `stream_incomplete` (visible discipline).**
Append to the `FaultEvent` union (fault-class.ts:71-99): `| { readonly kind: "stream_incomplete"; readonly visible: boolean }`; in `classifyFault` (:146-162) add an arm mirroring the `clock_timeout` row (:155-156) with the same criterion: `visible ? "none" : "retry"`. The default arm `{kind:"protocol_error"}` is **not deleted, only narrowed**: the exact criteria (including this class's instanceof arm) are inserted before it (the nonClockFaultOf discrimination-order contract is documented at anthropic-adapter.ts:881-896), leaving the default for genuinely unknown shapes only.

**Invariant (b): worker exit-code semantics.**

- **exit 2 = envelope protocol errors only**: `parseWorkerEnvelope` throws `ProtocolError` (stdin JSON parse failure / WorkerEnvelope field missing) → no envelope can be written → `[subagent-worker] fatal` + exit 2 (cli.ts:615-626 already carries this semantics; this ADR codifies it and narrows the catch surface).
- **run-phase escape errors → best-effort failed envelope (stdout) + exit 1**: no longer misusing 2. Structured typed escapes map by reason (Decision 2(b)); **unstructured escapes** (unknown errors from assembly/finalization and other sites outside the loop catch surface) → best-effort envelope reason=`crashed` (a process ending in error = this ADR's narrowed "process-level abnormal death" vocabulary) + exit 1 — not contradicting parent-side SC16's "exit≠0 without envelope → crashed" layering: with an envelope, attribute by its reason.
- exit 0 + failed envelope = a structured failure derived by run() (reason within the 5-value enum); the parent attributes by envelope.
- **SC13 / assumption 16 wording-difference adjudication**: both originals pin only "exit ≠ 0" and **neither pins the code value 2**; the difference is on the parent-side marker — SC13 says the parent manager marks `crashed`, assumption 16 says `reason=protocolError`. The implementation takes assumption 16's **envelope-derivation side** (worker.ts:1141-1148 doc + :1289: run() throws ProtocolError → envelope reason=protocolError), while the parent marks `crashed` for **exit≠0 without envelope** (manager.ts:1512-1543 SC16 + :1205-1214 settleCrash, i.e. the SC13 side) — no contradiction; the layering holds: _protocol-layer crash (no envelope) → parent-side crashed; with an envelope → by envelope reason_. This ADR sets that layering as contract text; the accurate wording of "returning exit 2" is "returning assumption 16's protocol-layer-crash **dedicated code**", and `crashed` narrows back to "process-level abnormal death (non-zero without envelope / killed by signal)".
- **ADR-0094 citation convention** (fixing the evidence §5.2 drift): the body of ADR-0094 carries no literal SC4/SC5 numbers (a single-paragraph Decision, docs/adr/0094-…md:6). Code comments reading "ADR-0094 SC4-SC5" refer to its two sentences: "Vendor/API failures are drawn for the human in the conversation stream (thin shell `API error (status):` + verbatim message), not appended to the session transcript; `StopReason` / `protocolError` are not UX copy." The literal SC4/SC5 numbers come from the live spec `specs/transport-continue-persist.md:43-44` (round persistence + sticky notice, a different surface). New documents/comments should cite "ADR-0094's viewport API-error clause (corresponding to SC4/SC5 in `specs/transport-continue-persist.md`)", not bare "ADR-0094 SC4-SC5".

### 4. Default-arm observability = a console.warn diagnostic inside the `nonClockFaultOf` default

Verified: `nonClockFaultOf` / `translateAnthropicTransportFault` are pure functions (no injected log/trace channels, anthropic-adapter.ts:862-873, :898-915); the sole consumer `withTransportRetry` throw site :134 and rethrow :141 are bound by the **zero-change** hard gate, so "log at the consumer" is infeasible; `classifyFault` is likewise pure and its default→none semantics do not change. The adjudication takes the least-invasive form: **a `console.warn` diagnostic before the default arm returns** (`err.name` + `errorMessage(err)`, message truncated to ≤200 characters with the name not counted against the budget; no stack, no request body); classification is unchanged (still `protocol_error`). Precedent: harness diagnostics go through console.warn (trace/jsonl.ts:239, memory/prefetch.ts:184); worker stdout is the envelope protocol surface so warn goes to stderr without polluting it, and the parent reads stderr only for forensics when exit≠0 (CONTEXT's "stderr pointer" discipline). Tests capture via spy — no new mechanism, no injectable knob.

### 5. Reachability confirmation (code-verified conclusions)

evidence §5.5 holds and was extended to full coverage:

- **`TransportRetryExhaustedError` (invisible stream break, retries exhausted)**: thrown at with-transport-retry :139 → caught at loop :1951 → stopReason `protocolError` + apiError (cause summary) → runWorkerOnce :1229-1241 derives the failed envelope → **exit 0**. No bare throw; never reaches the worker catch or cli exit 2. The worker-side adapter is isomorphic (worker.ts:533-544 assembles `withTransportRetry({ translate: translateAnthropicTransportFault })`).
- **`ModelStreamIncompleteError` (visible=true direct throw)**: rethrown at :141 → loop :1950's `instanceof ProtocolError` hits (the extends relation guarantees it) → the same catch arm → stopReason `protocolError` (apiError attached per Decision 2(c)).
- **Existing derivation path**: when run() returns normally with stopReason=protocolError, the envelope is derived at worker.ts:1229-1241 (`toFailedEnvelope("protocolError", "", observabilityFields(result, …))`, and the stop_reason observability field carries `protocolError`). **After landing, the exit-2 misuse disappears on its own** (the bare Error becomes typed and loop catches it).

**Scope conclusion**: this is not purely "tests pinning existing behavior" — pinning existing behavior only guarantees reason=protocolError, while Decision 2 requires the parent to receive `modelTransient`; so the worker product code needs small changes (Decision 2(a)'s branching + 2(b)'s defensive ordering arm), plus narrowing cli.ts's catch-all (Decision 3's invariant b). loop-engine zero changes (:1949-1963 as-is), withTransportRetry zero changes.

## Consequences

- (+) "The API jittered" and "the envelope is broken" become distinguishable on two surfaces: exit code (0/1 vs 2) and envelope reason (modelTransient vs protocolError vs crashed). ADR-0102 Decision 1's continuation gate (failed + transcript is enough to continue, docs/adr/0102-…md:16) takes over this fault without any new mechanism; its "Why not accept only completed: failure/crash are the main drivers of continuation" (:25) is precisely this fault's exit.
- (+) The default arm no longer silently flattens unknown shapes; an SDK upgrade that changes shapes → sentinel test RED + a live diagnostic signal.
- (−) The reason enum 4→5 is an explicit loosening of SC9's frozen decision surface; any third-party consumer relying on an old parent's strict-four-value assumption (if any) must sync; inside the single-repo CLI this ADR governs.
- (−) Retries amplify API usage (stream break × ≤5 attempts): bounded by the visible discipline and the existing attempt budget; `transport_retry` events (with-transport-retry.ts:146-151) are user-visible.
- (−) Message-text criteria are fragile: the sentinel test is the guard rail.
