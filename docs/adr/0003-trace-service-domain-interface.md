# 0003. Trace Service domain interface (A-scenario local debug observability)

Date: 2026-07-31
Status: accepted

## Context

GH issue #64 (winter6205/iknow) — spawned from #51 Session API migration. When an AI run goes wrong, the developer has no content-level record (LLM messages, tool arguments, tool results) to inspect. The existing `LoopTrace` at `src/harness/loop-trace.ts` (017 spec) records _loop health_ metadata only (turn index / supplier stop / tool call kind / duration / timeout / signal aborted) and **strictly excludes payload** (per `docs/CONTEXT.md` `LoopTrace` _Avoid_ "在 trace 里塞 input/output/token/cost（B 层字段）"). The new TraceService fills the _content_ gap for **A-scenario (developer local debug)** — a JSONL file the dev can `grep`. B-scenario (production OTel export) is explicitly out of scope; 017 spec's "conditional remediation layer" includes "OTel-span-metric 树 017 显式禁止", and OTel GenAI semconv is still shifting (v1.37 / v1.41 / v1.42 between 2024-2026, with messages moved from event to attribute and `execute_tool` span name forced to include tool name).

## Decision

14 decisions settled in 2026-07-31 grilling session:

1. **Turn semantics = one AI response = one turn record.** A run produces N turn records (N = turnCount). Per `CONTEXT.md` `turnCount` definition.
2. **Underlying data model = OTel span tree; top-level API = domain-driven.** A trace record is a span (with start/end, parent_id, attributes). Method names use business language (`recordLlmCall` / `recordToolCall` / `recordTurn`), not OTel `startSpan` / `addEvent` / `setAttribute`.
3. **B-scope留位 = business fields in JSONL + separate `otel-translator.ts`.** A-scope writes iknow business field names; B-scope fills the translator that maps them to `gen_ai.*` OTel attributes. A-scope ships the translator as a stub (function body throws "B-scenario not implemented"), wrapped by `safeTrace` so the harness survives.
4. **`conversation_id` is required on all three methods.** CLI `ask` auto-generates a UUID per invocation; Session API uses `session.id`. The field is always present in JSONL (never null) — preserves multi-turn correlation.
5. **IDs are generated by TraceService and returned.** `recordLlmCall` returns `llmCallId: string | undefined`; `recordToolCall` receives `parentLlmCallId: string | undefined` (required slot) and returns `toolCallId`; `recordTurn` returns `turnId`. Caller chains via return value; no `crypto.randomUUID()` in `loop-engine.ts` trace code.
6. **Error double-track.** `status: "ok" | "error"` AND `error: { type, message }`. `error.type` reuses iknow's existing `kind` enums (`ToolExecutionResult.kind` values + `cancelled` / `timeout` / `protocol_error` / `api_error` / `rate_limit` / `context_length_exceeded` / `content_filter` / `internal` / `unknown`). B-scope OTel translation maps these to `gen_ai.error.type` strings via the translator.
7. **Generic `parent_id` slot, not `parent_llm_call_id` only.** A-scope uses `parent_llm_call_id` (tool→llm); the field shape is general so any future call site (tool→tool, llm→llm) uses the same slot. Matches OTel `parent_span_id` model.
8. **Field naming: snake_case in JSONL, camelCase in TS.** `camelToSnake` lives in one file (`src/harness/trace/jsonl.ts`). Two conventions reconciled centrally, not by parallel schemas.
9. **Postel's Law schema design.** JSONL records only fields that are **currently fillable** (e.g. `guardrail_trigger` while iknow has no guardrail mechanism, `context_window_usage` while iknow does not compute it — **not** pre-declared). Added when the underlying capability exists.
10. **CLI scope: `ask` + `serve` only.** `chat` TTY REPL explicitly excluded (interactive; trace-write boundaries — ctrl-c / session switch — deferred). Default-on trace, not opt-in.
11. **Call timing: `recordTurn` writes at step end (实时写盘).** Each turn writes its record before the next step's model call. Process crash preserves all completed turns. Write is `fs.appendFileSync` (sync, not fsync'd); caller `await`s and chains IDs. B-scope can introduce an in-memory queue if performance becomes a concern — recorded as future work.
12. **Flush strategy: no fsync, rely on OS buffer.** Disk-full / power-loss may lose the last few records; process crash does not (OS buffer survives). fsync is B-scope.
13. **Failure contract: `TraceService.recordXxx` MUST NOT throw.** Interface annotated `@throws never`. Implementations wrap IO in try/catch, log `console.warn`, return `undefined` for ID-returning methods. Centralized via `safeTrace(asyncFn): Promise<T | undefined>` in `src/harness/trace/safe-trace.ts`. Loop-engine埋点 code uses `await safeTrace(...)` — never calls `traceService.recordXxx` directly.
14. **When `recordLlmCall` returns `undefined`, `recordToolCall` is still called** with `parentLlmCallId: undefined` → JSONL `parent_llm_call_id: null`. A partial tree is more useful than a silently dropped subtree.

**Why not alternatives:**

- _Use OTel SDK directly (`@opentelemetry/*`)_: A-scope is single-process local JSONL; OTel SDK installs heavy infra (TracerProvider / SpanProcessor / OTLP exporter) for no immediate value. Domain-driven interface + reserved B-scope translator gives 80% of the benefit at 5% of the dependency weight. B-scenario can swap in OTel SDK behind the same `TraceService` interface without breaking A-scope埋点 code.
- _Extend `LoopTrace` to carry content_: violates `CONTEXT.md` `LoopTrace` _Avoid_ + 017 A7 field-set lock. TraceService is a separate module precisely so LoopTrace can stay payload-free.
- _SQLite / database / external storage_: heavier dep, schema migrations, no win for A-scope "dump everything to a file the dev can `grep`". JSONL is the right primitive.
- _Trace in `chat` REPL too_: A-scope deferral. REPL trace write boundaries (ctrl-c, session switch, terminal resize) introduce test surface without clear debugging value — developers reproduce bugs via `ask` / `serve`, not interactively.
- _Pre-declare all OTel fields as null placeholders_: violates Postel's Law. Consumers cannot distinguish "field declared but not yet filled" from "field absent because capability does not exist". The dev's mental model is "what's in the JSONL is the truth about what happened", not "what's in the JSONL is the predicted schema".
- _Caller-generated IDs (`crypto.randomUUID()` in loop-engine)_: spreads ID format policy across harness code. B-scope OTel translation would need to convert UUID v4 → 16-byte hex in two modules instead of one. (Was considered as the lighter option; rejected because TraceService is the only place that needs to know ID format.)
- _Caller-side try/catch at every埋点 site_ (alternative to `safeTrace` wrapper): every new埋点 must remember to wrap, and a forgotten wrap crashes the harness. Wrapper centralizes the contract; new埋点 are `await safeTrace(() => ...)` only.

## Consequences

- (+) Independent module preserves 017 A7 lock. `src/harness/loop-trace.ts` byte-identical across any "trace service" PR. LoopTrace and TraceService are two bounded contexts with separate responsibilities.
- (+) B-scenario path is concrete and localized: one file (`otel-translator.ts`) + a mapping table. A-scope ships the stub so the留位 is real, not aspirational.
- (+) Default-on trace matches the "local debug" use case — the dev doesn't have to remember a flag. `trace.jsonl` in `.gitignore` avoids pollution.
- (+) A-scope adds zero new runtime deps. JSONL is plain text, `grep`-able, no tooling required.
- (+) Span-tree model is forward-compatible with any future nested call pattern (tool→tool, llm→llm) without changing the interface.
- (−) Loop-engine埋点 code grows ~20 lines (4 `await safeTrace(...)` sites). Mitigated by `safeTrace` wrapper being a single function.
- (−) JSONL file grows monotonically; no rotation. B-scope will need rotation (by size or time) — recorded as future work.
- (−) Two field naming conventions (camelCase TS / snake_case JSONL) — reconciled by one function in `jsonl.ts`, not by parallel schemas.
- (−) `recordXxx` "must not throw" is a contract enforced at the implementation layer, not the type layer. A future OTel TraceService that forgets to wrap will break the harness. Mitigated by integration test (`tests/harness/trace-integration.test.ts`) and explicit `@throws never` JSDoc.
- (−) `recordLlmCall` failure produces `parent_llm_call_id: null` orphan records in JSONL. Intentional (decision 14), but the dev must learn to recognize the pattern as "trace write failed" not "business semantics".
- 回退 = delete `src/harness/trace/`, remove the optional `trace` field on `LoopEngineDeps`, remove `--trace-out` flag, remove `trace.jsonl` from `.gitignore`. Low cost; the module is opt-in by default but additive.

## Amendment 2026-09-08（ADR-0071）

**「JSONL the dev can grep」在 messages 正文维度收窄。** ADR-0071 把 blob 内容寻址从 opt-in 改为唯一模式，`llm_call.messages[].content` 从此是 `{sha, bytes}` 引用，正文在会话文件夹内的 `blobs/<sha>`。**收窄只及这一个维度**：事件行本身、`tool_call` 参数、`status`、`error`、`turn` 决策、`verification` 判定全部仍内联可 grep。按 sha 取回正文的读法有两条既有面：`get_record`（字符窗口分页）与 `query_trace`（投影 + preview）。

**D13 / D14 原样继承，不 amend。** 这条刻意写明，因为 ADR-0071 Decision 5「删故障回退」极易被误读成「让 trace 向调用方抛错」：

- **D13**（`TraceService.recordXxx` MUST NOT throw，接口 `@throws never`，经 `safeTrace` 集中，loop-engine 埋点只 `await safeTrace(...)`）**不变**。blob 写入失败仍走内层 IO 抛出 → `safeTrace` / recordFailure warn-once 吞掉 → 返回 `undefined`。
- **D14**（`recordLlmCall` 返回 `undefined` 时 `recordToolCall` 仍被调用，落 `parent_llm_call_id: null`）**不变**。

被删掉的只是**存储形态上的第二条路**：不再有「blob 写不进去就退回写内联全量行」这个分支。异常契约与调用方可观察行为一字未改。

**D10 scope 的两面敏感度分化。** content 面（`llm_call.messages` 正文）从此以 `blobs/` 可写为前置；D10 排除范围经 ADR-0035 收窄后剩下的**生命周期面**（`subagent_spawn` / `subagent_state_change` / `subagent_stop`）不含 messages 正文，`toBlobReferences` 对其从不触发，故不受该前置影响。详见 ADR-0035 的同日 Amendment。
