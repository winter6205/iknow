# 0083. Skill bodies bypass the generic executor output cap

Date: 2026-09-11
Status: accepted

ADR-0006's executor backstop gate (a 20000-character hard truncation plus a lead-in telling the model to re-invoke with a more precise input) rests on the premise that tool outputs are mostly **re-generable queries** — file reads, content searches, and the like. `skill()` does not meet that premise: its output is one assembly product (frontmatter stripped + `Base directory` line + `<skill_files>`), single-source and semantically whole; once truncated there is no "re-invoke with a more precise input" recovery path. And the three consumption paths (TUI slash / session-api `loadSkillBody` / ACI `skill()`) already share one assembly point — when the body grows large, only the third path forks off. A half skill program is more dangerous than none: the model executes the half as if it were whole, and a same-name re-invocation hits the second-call short circuit (ADR-0079), unrecoverable within the session.

Therefore: `skill()` bodies move out of the executor `OUTPUT_HARD_CAP`'s scope. The exemption is a **static declaration at assembly time** (an optional field on the Foundation `ToolDef`, set by `createSkillTool`, read by the executor's `safeContent` / `applyOutputCap`) — not a runtime field, not tool self-report; contract X, "the executor is the sole authority on truncation metadata", is unchanged. MCP tools are **structurally unable to obtain it**: `toAciToolDef` maps only name / description / inputSchema, and `registerExternal` forces the `mcp__` prefix. The numeric value and semantics of `OUTPUT_HARD_CAP` for all other tools stay untouched.

**Why not a skill-specific limit / read_file re-read after truncation**: a specific limit is still truncation, just a different number, and the half-program problem stands unchanged; `read_file` is under the same 20000 backstop gate, so it is no escape hatch (it would take multiple reads, total volume undiminished, and would route around the second-call short-circuit gate). **Why not runtime enforcement of body size**: body-size discipline is an authoring contract (keep the body concise, put details in `references/`, which cost nothing until read); the mechanism deliberately sets no limit, keeping discipline on the authoring surface.

This exemption is a behavior contract; ADR-0006's applicability narrows here, and its rulings for all other tools remain in force.
