# 0125. 替换类语法终局政策：递归检查 + 组合墙

Date: 2026-09-24

Status: accepted

## Context

现行 command-substitution 墙是"出现 `$(`/`${`/反引号/`<(` 即拒"的裸子串扫描（引号盲），issue #1132 的四类误杀（引号内数据、heredoc 文档体被当代码）证明政策不可持续。ADR-0123 已建语法级解析地基（tree-sitter 原生绑定、`parseForSecurity`），ADR-0124 已定六态判定契约。本 ADR 在其上定替换类语法的终局政策——`$(...)`、反引号、`<(...)`、`${var}` 各自的归宿，以及分类 id 的演化。

## Decision

1. **递归检查**：`$(...)`、反引号、`<(...)` 的内层命令被提取出来，走与顶层命令**完全相同**的权限判定（硬墙 → 分层规则 → 模式）。任何一层 ask → 整条命令升格 ask（理由写明内层内容）；任何一层 deny → 整条 deny。不为内层另设只读 allowlist。
2. **嵌套深度上限 2 层**：替换嵌套允许到第 2 层，出现第 3 层按"过复杂"→ ask（与 ADR-0124 态 2 口径一致）。内层出现分析不动的结构直接跟随六态契约归宿，不另立标准。
3. **`${var}` 拆出独立 id `parameter-expansion`**，按名字三桶：secret 模式名（API_KEY/TOKEN 等）→ 硬拒（占位符代管通道 `<<<SECRET_N>>>` 是唯一正路）；`BASE_ENV_WHITELIST` 内 → 放行；其余未知名字 → ask。变体形态（`${var:-word}`、`${#var}`、`${var%后缀}`、`${arr[i]}`、`$((...))`）：名字部分走三桶，**任何位置**嵌的 `$(...)` 走递归检查（bash 数组下标做算术求值、算术里可藏命令替换）。静态判定不赌运行时条件：`${X:-$(curl …)}` 按"会执行"分析。
4. **组合墙 `interpreter-procsub`**：解释器（bash/sh/zsh/python/node…）直接执行 `<(...)` 产出内容 → 硬拒，不问内层是什么。理由：内层输出在运行时才变成将被执行的代码，ask 时用户看到的只是内层命令（如 curl）而非脚本内容，full_auto 下更是直接放行——属于 ADR-0068 定义的"围栏拦不住、用户无法有效裁决"的意图类别。
5. **heredoc 正文定性看接收者**：接收者是用文本的命令（cat/tee/grep -f…）→ 带引号定界词（`<<'EOF'`）的正文是数据，墙无视其中的替换字符；接收者是解释器 → **正文一律是代码**，不论定界词带不带引号，逐行走与内层命令同一套判定。
6. **惰性文本**：单引号字符串内、注释内、（非解释器接收的）带引号 heredoc 正文内的替换字符一律是数据，永不触发墙；unquoted heredoc（`<<EOF`）正文按活跃代码区判。口径：**bash 执行什么，墙才检查什么**。
7. **分类 id 演化**：command-substitution 收窄为真执行替换（`$()`/反引号/`<()`，递归检查判归宿）；新增 `parameter-expansion`（决策 3）、`interpreter-procsub`（决策 4）、`unparseable`（ADR-0124 判定层硬拒：畸形/中止/超容量/前置否决）。SC3 reason 渲染随新 id 扩展。

## Considered Options

- **维持出现即拒**：保守零误放，但良性替换（`$(date)`、`diff <(sort a) <(sort b)`）永远走不通，解析地基的价值只剩引号感知，#1132 只解决一半。
- **H4 降级为 ask、改测试期望**：少一条墙规则，但 full_auto 下"下载远程脚本直接执行"畅通，且 ask 展示的信息不足以裁决。
- **内层单独只读 allowlist**：要多养第二份清单，产生"同一条命令顶层能过、进括号被拒"的不一致，且与 full_auto 语义冲突。

## Consequences

**正面：**

- #1132 四类误杀在政策层根治；良性命令替换、进程替换、heredoc 文档写法全部存活。
- 安全意图钉子保绿：C5.a（`${ANTHROPIC_AUTH_TOKEN}`→secret 桶硬拒）、H4（`bash <(curl …)`→组合墙硬拒）、rm 变体、反斜杠转义、敏感路径重定向不受影响。
- 误杀钉子翻转（这正是目的）：`echo $(whoami)`、`echo $(cat pid)`、`$(which grep)` 从 deny 变 allow；permission.test.ts 的 id 渲染测试改用 `echo $(rm -rf /)` 触发，渲染覆盖不丢。逐条盘点清单进 spec。

**负面 / Trade-offs：**

- 组合墙需要维护一份解释器清单（与 map 雾区"allowlist 是否合并为单一事实源"直接相关）。
- 未知变量名、深度超限、内层 ask 会让部分良性命令多一次确认；default 模式下的摩擦换取 full_auto 下的可辩护性。
- 判定路径增多（递归 + 组合 + 三桶），测试面扩大；迁移与旧扫描器影子对照策略归 usp-5。
