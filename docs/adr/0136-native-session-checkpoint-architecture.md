# 0136. Publish native execution checkpoints within the existing session history

Date: 2026-10-03
Status: accepted

**Implementation state:** Accepted design; product implementation and crash/PTY acceptance have not started. The active contract is [Native session checkpoint architecture](../../specs/session-checkpoint-architecture.md). Its three implementation plans live in [storage and host recovery](../implementation-plans/session-checkpoint-storage-recovery.md), [runtime and workers](../implementation-plans/session-checkpoint-runtime-workers.md), and [effective-input trace](../implementation-plans/session-checkpoint-trace-evidence.md).

Existing session events, checkpoint markers, per-write code snapshots, and trace blobs cover parts of recovery, but an interruption index or a transcript projection is not a saved executable state. Extend these mechanisms with fully published native execution checkpoints and durable intermediate operation facts. Keep session event IDs, parents, and the selected head as the sole history/branch authority; immutable state is referenced payload, not a second history or execution engine. The cost is additional correctness-critical persistence and versioned state validation, in exchange for preserving completed work across host-process loss without reconstructing context or replaying effects.

## Decision

1. **Publish complete native state.** Save accepted user input and its native context/state before the dependent model request. Save complete tool-batch state only after all calls have settled and their results have entered context in protocol order. Persist each independently settled result promptly even when an earlier parallel result is outstanding. Compaction retains prior history/checkpoints and publishes its exact new context on the existing event-history branch. A settled terminal outcome with no outstanding operations may close the saved state under ADR-0126.
2. **Reuse history authority.** Select a published checkpoint reachable on the chosen event/head chain, never by newest timestamp. Do not add an independent current-checkpoint clock, branch registry, duplicate restore anchor, or universal next-node schedule. Publish required immutable bodies before their references. Preserve each worker transcript's own writer and chronology.
3. **Save applicable file evidence before mutation.** Reuse raw `code-snapshots/`. With capture enabled, persist preimage/prior absence, expected postimage, target/root identity, and every per-file operation association before writing. Publish suitable ordinary writes through same-filesystem staging and per-file atomic replacement. Multi-file publication is not a transaction. Preserve the existing explicit capture opt-out and report disabled evidence as unverified.
4. **Recover when the corresponding session is opened.** Display progress and recovered/needs-handling state; load the exact saved native context and reconcile later facts. Retain a verified expected postimage at its recorded live root even without a whole-tool result, but keep the overall outcome unknown. Leave drift, missing evidence, root mismatch, ambiguous cross-writer order, and uncaptured/external effects untouched. Recovery is idempotent, does not depend on old memory, and performs no model/tool retry, graph continuation, worker relaunch, or automatic code rewind.
5. **Retain logical runtime progress.** Checkpoints and applicable intermediate facts preserve validated graph outcomes/outputs, worker identity/progress references, native provenance and frozen assembly, and pending continuation state. Live handles, secret registries, credentials, and process-memory permission grants are not restored. Later explicit execution uses current permission admission.
6. **Stop owned subagents after abnormal host exit.** Include foreground and `wait:false` subagents. Verify the original spawn/process identity has stopped before continuation; a reused numeric PID is not authority to signal another process. Unconfirmed cleanup requires handling. This does not change ordinary foreground-interrupt behavior or unrelated/persistent Bash-service lifecycle.
7. **Share immutable represented content within a session.** Extend the existing `blobs/` pool for native recovery bodies and trace-permitted representations; identical retained representations reuse a body. Raw and differently redacted bodies remain distinguishable, and different sessions stay independent. Shared physical storage does not merge consumer authority: trace readers follow trace-permitted references and must not expose or export the entire raw recovery pool.
8. **Capture each actual SDK invocation.** Capture the exact dispatched system instructions, complete advertised tool definitions, and ordered effective messages after final adapter projection. Distinct invocations retain distinct call identity even if bodies are shared; rejected attempts remain failed-attempt evidence, not inferred successes. Apply existing trace masking before content addressing. Reuse trace readers and the trace-plus-referenced-bodies layout; add no export UI or command.
9. **Keep failure contracts separate.** Required recovery-state or enabled file-evidence persistence failures block dependent execution/mutation and surface typed failures. Trace remains best-effort/non-throwing and reports evidence gaps; its failure must not cause an additional SDK dispatch. Existing transport retry policy is separate. A corrupt selected published checkpoint fails visibly without reconstructing history or silently selecting another checkpoint/branch.
10. **Keep session lifetime and adoption boundaries.** No age-based expiry, quota deletion, selective pruning, cross-session deduplication, or new global collector. Explicit session deletion remains the reclamation boundary. Preserve old session data without migration or compatibility; positively identify new-format sessions before applying this contract. Session tmp is reread, not snapshotted. Process-termination recovery does not establish a new power-loss/fsync guarantee.

## Why this shape

- Rebuilding native context from a transcript or rerunning compaction can drift from what was saved; retain exact native snapshots instead.
- Process-local ledgers and success-only file associations lose already completed effects during interruption; save durable facts without claiming whole-tool success.
- A shadow workspace, second journal, or independent branch clock would duplicate authority and complicate reconciliation; extend the existing session chain.
- Storing full repeated request bodies wastes space, while hashes without payloads lose evidence; retain immutable bodies and exact per-invocation manifests.

This decision has meaningful persistence/interface reversal cost, contains non-obvious authority and failure boundaries, and chooses among genuine architectural alternatives. Physical type names, serialization fields, and helper layout remain implementation choices bounded by the unified spec. Three worktrees may implement in parallel; their merged system must pass one combined acceptance matrix before completion is claimed.
