# 0097. Egress proxy seam: `--unshare-net` always on + domain-allowlist proxy, replacing the per-call `network:true` full pass-through

Date: 2026-09-16
Status: accepted

> **Amended (ADR-0104 / 0107)**: a preset/defaults tier is now in place. **0106 once superseded this entire decision; 0107 has overturned 0106.** Currently: `--unshare-net` + domain-allowlist proxy still holds; **the clause "socat is a host prerequisite dependency" is abolished** (the relay ships built-in, see ADR-0107). The first-time approval flow, the address guard, and violation feedback all remain.

## Context

The egress semantics of the bash fence have long been binary: `--unshare-net` cuts the network by default (`src/harness/sandbox/bwrap.ts:162`), and the per-call `network:true` opt-in removes it = full pass-through of the host network with **zero filtering** (ADR-0022); there was no middle tier able to express "allow these few domains". Meanwhile `STATIC_NETWORK_WHITELIST` / `NetworkPolicy.assertDomain` (`src/harness/sandbox/network-policy.ts:4`) were **declared but never implemented** dead code (`bwrap.ts:224` directly does `void opts.networkPolicy`) — the repo carried the name of a mechanism that did not exist.

ADR-0022 judged "domain filtering will not be done" on the grounds of "no kernel-level hook, anything built is decoration" — that judgment holds for **kernel-level** filtering, but it under-rated the **proxy route**: full netns cut + one seam through the filesystem (unix socket bound into the sandbox), with domain adjudication done by a host-side proxy (HTTPS only looks at the CONNECT host, no decryption), needing no TUN forwarder, no user-space TCP/IP stack, no TLS termination, no self-built CA — not one of the four components ADR-0072 listed. ADR-0072's reopen trigger condition 3 (a user-facing promise of domain-level allowlisting) is thereby hit.

## Decision

`--unshare-net` becomes a **constant** of the argv (never removed by any path); the only egress route = the **egress proxy seam**: the unix socket of a host egress proxy (HTTP CONNECT + SOCKS5) is bound into the sandbox, socat bridges one segment on **each of the host and sandbox sides** (host: unix socket → proxy TCP; inside the sandbox: local port → unix socket), and env vars such as `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` point at it. Domain adjudication = the **domain allowlist** (forward only when the CONNECT host matches; `*.x` is a strict sub-domain that excludes the apex, optional `:port` suffix, deny takes priority); the address guard (rejects loopback / private / link-local / metadata) is orthogonal to the domain set. The allowlist honors **user-layer** settings only (ADR-0084 discipline; project files are not adopted).

**`socat` is a host prerequisite dependency and is not distributed by this repo** (measured: the package's `vendor/` holds only seccomp / srt-win / java-proxy-agent, no socat; when missing, the upstream reports `socat not installed`). When absent, network capability is **fail-closed** (never silently degrading to "no network"), with installation guidance given.

**The proxy's rejection copy is a hardcoded constant** (measured: `ALLOWLIST_DENY` in `http-proxy.js`, no options injection point): the 403 body is always `Connection blocked by network allowlist` + `X-Proxy-Error: blocked-by-allowlist`. "Actionable violation detail" (the rejected domain + the allowlist's provenance + configuration guidance) is **owned by this repo** — recorded in the `filter` callback passed to the proxy and fed back through the bash tool_result's `stderr`, with the prefix reusing the existing `VIOLATION_PREFIXES.networkDenied` (this prefix is **kept and upgraded** so the mid-tier escalation path stays effective). This is a decision, not an implementation detail: violation-copy ownership stays in this repo; the proxy is only the adjudication executor.

The per-call `network:true` field and its ask rule (`code-ask-bash-network`) are **abolished wholesale** — not old-and-new coexisting, no escape hatch left. The dependency surface takes only the **network half** of `@anthropic-ai/sandbox-runtime` (Apache-2.0, pinned version) (proxy + bridge + matcher + address guard); the bwrap argv is still assembled by this repo itself (fsMode / workspace mount / argv-order discipline unchanged).

**The first-time domain approval flow is a structural component, not an option**: interactive entries seeing a new domain for the first time → ask once through the existing ask surface; approval = session-level pass + optional persistence to user-layer settings; non-interactive entries (background / verify / no ask surface) cannot ask = **fail-closed rejection** (the violation carries the missing domain and configuration guidance). A configured allowlist (`isolation.network.allowedDomains` / `deniedDomains`, user layer only) is the **preset** path, for CI and interruption-free scenarios — the two coexist; configuration does not replace the approval flow. Rationale: configuration-only would degrade daily use into "rejected → hand-edit config → rerun"; approval-flow-only leaves CI unable to pre-declare the boundary. **No** "preset fallback set of common domains" — that equals silently widening the boundary.

**Proxy lifecycle / dispose contract (adjudicated 2026-09-17, the explicit interfacing of the spec's "Ownership / dispose contract")**: the three shapes share one interface shape "start bridge → bind socket → inject env vars → teardown cleanup", and **the abnormal paths (spawn failure / execution throw / task abort) go through the same release channel as the normal path** — a leaked socat / proxy process is the stale-socket source for the next call. Per-shape timing:

| Shape                      | Start                                                                                                              | Bind + inject                                                                                          | Release                                                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| foreground bash call (per-call) | during bash-handler fence assembly, and started only when this call is egress-eligible (allowlist non-empty or the approval flow can ask) | the bridge socket enters the sandbox via bwrap `--bind`; `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` injected via `--setenv` | at call teardown (success / failure / exception share the same finally): kill proxy + socat processes, clean the socket           |
| background task (per-task) | started at task-spawn assembly, lives with the task                                                                | same as above; injection goes through the manager's fenceEnv                                           | hooked on `settle()` (the single terminal-state transition point, shared by the exit event and the shutdown cascade); the spawn-failure path cleans directly before settle fires |
| verify (rides the host)    | module-level singleton, lazily started on first use, reused across calls                                           | same as above                                                                                          | with host-process exit; the shutdown hook cleans as backstop                                                                        |

Stale-socket defense (matching the spec's Failure paths): the socket path carries a per-session random id + pre-start cleanup; connection failure to a residual socket is classified as infrastructure failure, not misreported as a domain-allowlist rejection.

**Approval persistence granularity (2026-09-17 single adjudication)**: approval = **session-level pass always succeeds** (enters the session-grants mirror container, alive in process memory); writing back to user-layer settings (`isolation.network.allowedDomains`) is an **optional attached action** of approval, not a necessary condition — a failed write-back degrades to session-only pass + a one-time warning, and the already-approved call executes normally without rollback. Non-interactive entries have no approval flow and can only use preset configuration.

## Considered Options

- **TUN + user-space stack (the ADR-0072 route)**: pays a subsystem's price for "kernel-level enforcement + content inspection"; a domain allowlist (no content inspection) does not need it. Rejected.
- **Keep the per-call ask, only add domain filtering**: the ask is "one approval = environment trust", a different axis from the allowlist's "standing boundary"; stacking them would leave the model facing two interfering egress languages. Rejected.
- **IP allowlisting (nftables + DNS pinning)**: domain→IP is N:M and drifts with CDN rotation, equivalent to false blocks and leaks coexisting. Rejected.

## Consequences

**Positive / Applied:**

- Egress becomes expressible and fail-closed: no allowlist match = proxy rejection (with violation detail fed back); "approve once = fully open" no longer exists.
- Single structural point: `--unshare-net` is always present, egress eligibility is answered in exactly one place (domain adjudication), and non-interactive entries (background / verify / no ask surface) follow the same rules as interactive ones.
- Dead-code settlement: `STATIC_NETWORK_WHITELIST` / `NetworkPolicy.assertDomain` are replaced by the real matcher (the interface shape is kept and upgraded, no second parallel set).

**Negative / Trade-offs:**

- The "run a service in the sandbox → reachable from the host" capability dies (the core use case of the old ADR-0022): with the netns permanently cut there is no reverse channel; the proxy handles outbound only. Reverse visibility, if ever needed, opens a separate axis, outside this decision.
- **domain fronting is undefendable**: the proxy only sees the client-reported host, no decryption; allowing `github.com` permits exfiltration through that domain. This decision addresses "where it can connect", not "what is transmitted after connecting" — it must never be phrased as content-level control.
- Non-proxy-aware programs (raw sockets / tools that do not read `HTTP_PROXY`) inside the sandbox = no network; proxy/bridge process death = fail-closed (cannot connect). A user-visible behavior change that must be backstopped by violation-feedback quality.
- Introduces `@anthropic-ai/sandbox-runtime` (beta 0.0.76, API may drift): only the network half is used. The spike verified **the matcher and address guard import independently** (`domain-pattern` / `address` / `resolved-address-guard` / `parent-proxy` depend only on `node:*`); the proxy server components need a full dependency install before import and **hard-depend on `node-forge`** (the MITM module cannot be trimmed from the module-load graph even when TLS is not terminated at runtime). **The package has no `exports` field** = deep-path imports work but carry no contract stability → funnel through a single adapter layer; upgrades touch only that file.
- One more host dependency: `socat`. Absent means no network (fail-closed + guidance); this decision does not take on socat distribution.

Rejection copy hardcoded (`http-proxy.js:10-13`); `socat` not vendored (`linux-sandbox-utils.js:437-438` reports `socat not installed`); this machine's `which socat` = none.
- **The address guard's private-network tier is opt-in**: the reused `DENIED_CLASSES` deliberately **excludes** RFC 1918 / ULA / CGNAT (`resolved-address-guard.js:52-65` comments state "allow-listing an intranet hostname is legitimate"), which must be passed explicitly via `deniedResolvedAddresses` — this decision requires rejecting private networks, so the adapter layer must pass it, otherwise the defense is void.
- Measured signal separability: no match → 403 + `X-Proxy-Error: blocked-by-allowlist`; matched but upstream dead → 502; malformed → 400 (no crash).
- Measured domain-matching semantics: `*.example.com` matches sub-domains but **not** the apex; `evilexample.com` does not match (suffix anchoring is correct); case-insensitive; illegal port values (`:0` / `:65536` / `:abc` / empty) **do not throw** and silently degrade to never-match (→ the configuration layer must reject them).
