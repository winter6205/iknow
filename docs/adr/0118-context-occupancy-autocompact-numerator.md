# 0118. The usage bar and the auto-compact gate share one occupancy numerator

Date: 2026-09-21
Status: accepted

The denominator is already the policy budget window (ADR-0100). The numerator had forked: the bar used API / `countTokens`, while the proactive gate used `estimateMessagesTokens` (thinking=0, image ≈1). The hoolycheck session `8582d3fc` showed the bar at 955.6k/256k with 34 calls and zero compaction. The gate now consumes **context occupancy**; the 2026-10-21 amendment below refines its priority chain: an anchored projection when the request carries images → this beat's finite, >0 `countTokens` (image-free) → an anchored projection when measurement is absent → the previous beat's occupancy → the chars estimate. When pre_call cache fields are absent, occupancy = `inputTokens` — never add cache on top of a total that already includes it. The display may now show a **marked** (`~`) projected occupancy; an estimate still never substitutes for the confirmed value (ADR-0008 2026-10-21 amendment). The compactors and manual `/compact` bypassing the token gate keep their semantics.

Amends ADR-0008 D6 (estimation is no longer the primary compaction criterion) and ADR-0100 (numerator and denominator now come from the same occupancy ledger, not just the denominator).

> **Amendment 2026-10-21** (image-aware pricing and projected numerator): image blocks are priced by **pixels, not base64 length**. The shared estimator reads a bounded prefix of the image header (64 KiB max; PNG IHDR, JPEG SOF0/1/2, GIF logical screen descriptor; WebP through VP8X/VP8L when the header is present, otherwise the ceiling), scales the long edge to 1568 px when larger, then `round(width × height / 750)`, clamped to `[1, 3072]`. Malformed, unknown or truncated input reads the 3072-token ceiling. Both top-level `image` blocks and images nested in `tool_result.content` use the same formula; the base64 payload length never drives the estimate. The estimator is `src/harness/compress/image-tokens.ts`; the message-level total keeps its existing padding.
>
> **Side effect, pinned:** `estimateMessagesTokens` also sizes the epilogue summary tail, so a nested `tool_result` image goes from 1 token to up to 3072 and an image-heavy tail may now be cut where it previously was not. That is the correct direction — the tail budget is real tokens — but it does change compaction-summary input.
>
> **Projection priority** (replaces the chain in the paragraph above): anchored projection when the request carries images → this beat's finite, >0 `countTokens` (image-free) → anchored projection when measurement is absent → previous-beat occupancy → unanchored estimate. An absent measurement still never collapses into `below_token_threshold`. The projection is the last confirmed API `usage` (`occupancyFromUsage` + `outputTokens`) plus the estimated appended messages; it resets to the unanchored estimate when a compaction or any other history replacement invalidates the anchor. The anchor is only used while the exact frozen assistant message is still in `messages`; a structurally equal but non-identical object is not an anchor (it would double-count the whole history).
>
> **Residual trade-off:** the projection is an estimate, so an image-heavy history just under the threshold can be slightly under-read. Two bounds keep it acceptable: image pricing is pixel-based, so the degradation is in the text heuristics rather than a per-image inflation; and the anchored base is exact API usage, so between compactions the reading is `measured base + estimated delta` and cannot under-read by more than the appended text. The reactive `PromptTooLongError` path (ADR-0013) remains the backstop, including the first beat after a compaction where the anchor is null and the projection degrades to the unanchored estimate. Confirmed usage stays exact: a projected reading never enters the trace, `lastUsage`, or billing.
>
> **Display note (2026-10-22):** the bar half of "the display may now show a **marked** (`~`) projected occupancy" (top paragraph) is superseded by ADR-0008's 2026-10-22 amendment — the TUI context-usage bar now consumes measured beats only; projections remain on the wire purely as the image-bearing gate's numerator. **The gate is unchanged.**
