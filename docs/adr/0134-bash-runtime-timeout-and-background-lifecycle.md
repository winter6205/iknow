# 0134. Expose Bash runtime timeout while preserving persistent background execution

Date: 2026-09-30
Status: accepted

For issue #1170, expose optional positive integer `timeout_ms` on Bash. Foreground commands default to a 10-second execution deadline; a validated model value replaces that default and must not be clipped by the legacy Bash build-tier timer. Add no fixed root-search 30-second ceiling or ordinary-command 300-second ceiling. Read-only root traversal reaches normal permission checks and this common execution contract; mutating searches gain no search exemption. The host retains control of deadline enforcement, cancellation, and protected operations, and rejects unrepresentable input rather than silently shortening an accepted timeout.

For explicit background launch, a supplied timeout establishes a finite job's launch-time deadline; omission preserves the existing persistent-service lifecycle. Returning a task handle and polling never reset a finite deadline. Keep foreground blocking and background launch explicit, with no automatic transition or command-text lifecycle heuristic. Reuse bounded TERM/grace/KILL cleanup and distinguish confirmed process-group exit from unconfirmed cleanup; timeout is still a per-call failure under ADR-0091, not a turn stop. This partially supersedes ADR-0004 Decision 1's statement that Bash timeout is not exposed to the model; other tools' timeout tiers and the executor's timing ownership remain unchanged. The choice permits the model to allocate execution time while avoiding a new set of command-category ceilings; persistent background work continues to require its existing explicit stop/shutdown lifecycle. Acceptance is defined by [Hard-wall denial alignment](../../specs/hard-wall-denial-alignment.md).
