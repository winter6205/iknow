# 0119. `--yolo` no-sandbox mode: the fence retires entirely (the single explicit, operator-locked counter-example)

Date: 2026-09-18
Status: accepted
Deciders: operator (issue #1035 ballot: the locked five-dimension spec + the eight-question list)
Related: ADR-0092 (precedent: runtime in-place holder flips), ADR-0097 (this mode is the explicit exemption face of its invariant #1), ADR-0037 / ADR-0096 (the worktree-gate axis, orthogonal), ADR-0109 (the in-fence main-checkout ro-bind rides the exemption; the which-tree axis does not), ADR-0084 (user-layer settings discipline), ADR-0139 (permission axis is fence-independent — amends this ADR's ruling 1 and Amendment 2026-09-20 (ii)), ADR-0141 (presets on one session overlay — amends this ADR's ruling 1, ruling 6's channel, ruling 8's shape, and Amendment 2026-09-20 (ii), and amends a named carrier inside ruling 2, ruling 5 and ruling 7; rulings 3 and 4 stand verbatim)

Adds `--yolo`: a **no-sandbox mode** — the bwrap fence retires entirely and all four routes (foreground bash / background spawn / verify sandbox-run / subagent worker) run bare; `fsMode: workspace` is forced back to `global` on entry; the mode row carries a persistent red marker. There are exactly two entry points: the CLI flag `--yolo` before entering the TUI, and in-session `/yolo` + a confirmation modal. Non-TUI entries carrying `--yolo` fail with a typed error and a non-zero exit. The state is not persisted. _(The original summary also stated "the permission face becomes `full_auto`"; that clause is **withdrawn by ADR-0139** — yolo writes the fence axis only. **ADR-0141 re-grants it at a different layer**: `--yolo` names a **preset** that declares `full_auto` alongside the retired fence, while the fence primitive itself still never writes permission. What `--yolo` means from 2026-10-15 is the preset; the fence-only posture this ADR-0139 amendment left is reachable as `--no-sandbox` — the yolo preset's new **sibling**, and what `--yolo` itself has done since ADR-0139.)_

Spec: `specs/yolo-mode.md` (operator-locked five-dimension table + input contract + EXIT).

## Context

The ballot itself is the operator-locked spec: issue #1035's open item #2 already set the direction — **run fully bare**, with YOLO as its explicit counter-example. This collides head-on with two standing clauses, which this ADR adjudicates in one place:

- `docs/CONTEXT.md` "sandbox discipline": "the product path **must not** offer an unfenced bare background run".
- ADR-0097 Decision: "`--unshare-net` becomes a **permanent item** (never removed by any path)" / its spec's Settled invariant #1 "there is no second exit and no escape hatch" (the landing comment + flag in `src/harness/sandbox/bwrap.ts` are that invariant's physical form).

Neither reopening is "the judgment went stale"; both are **adding one named exemption face**: the operator explicitly demands "no sandbox = no fencing at all", and demands it consistently across the four routes. This ADR's product is the shape and the boundaries of that exemption face.

## Decision

**yolo is not "sandbox stays but permission lets through" — the fence retires as a whole.** The landing shape is the yolo branch of the single SSOT factory: `createBwrapFence` (`src/harness/sandbox/bwrap.ts`) emits a bare argv under yolo (no bwrap prefix), so all four routes inherit it transparently; there is no "foreground-only" half-bare mode (that would create a second fence shape).

Entry action = a state combination: `fsMode: workspace` switched to `global` (**flip holders only, never rewrite user-layer settings**, aligned with ADR-0092 "runtime in-place flips go through the holder"); exit action = restore the pre-entry snapshot, immediately, without confirmation. A `runTui --yolo` startup carries the same entry contract: the session must be entered **through the enter action** (fsMode → `global`), not merely a display seed — the startup path applies the same state combination that `/yolo` confirmation applies. _(The original Decision also listed "permission set to `full_auto`" as part of the entry combination; that clause is **withdrawn by ADR-0139**.)_ _(ADR-0141 replaces the entry/exit **channel**: the enter action becomes a declarative write of the session overlay with no snapshot taken, and exit is a whole-overlay clear rather than a restore (ADR-0141 rulings 2, 3, 9). The combination this sentence forces — fsMode → `global`, fence retired — is unchanged; see ruling 6's amendment.)_

The per-clause shape of the operator-locked five dimensions (naming / entry / in-session switch / display / semantics) and the input contract lives in `specs/yolo-mode.md`; this ADR locks only the rulings and their basis.

## Rulings (the eight questions, recorded item by item)

### 1. Relation to `full_auto`: an independent boolean state axis, not a fourth `PermissionMode`

> **AMENDED by ADR-0139 (2026-10-06).** The first clause stands verbatim: yolo is an independent boolean state axis, **not** a fourth `PermissionMode`; `full_auto` keeps its name, the value domain / badges / `PermissionModeContext` face are untouched. The second clause — "Entering yolo **implies** setting the permission holder to `full_auto`" — is **withdrawn**. Yolo's entry writes the fence axis only (`fsMode → global`, `yolo → true`); the permission holder is never touched. The Basis line's claim that "the orthogonality of the two axes is also what guarantees Shift+Tab still works under yolo" is also **retired**: Shift+Tab already changes the permission mode under yolo today (ADR-0030's cycle freezes graph mode at whatever value is current), and what keeps a mid-session change safe is the entry snapshot, not the orthogonality claim. Why the coupling is dissolved rather than merely reversed — including the named posture it newly makes reachable, and the re-adjudication of ADR-0130's structural-parity sentence — is ADR-0139's subject; this entry is the record of what this ADR originally ruled.

yolo is an **independent boolean state axis** (mirroring the `FsModeContext` holder shape), **not** a fourth `PermissionMode`; `full_auto` keeps its name, the value domain / badges / `PermissionModeContext` face are untouched.

> **AMENDED by ADR-0141 (2026-10-15).** The first clause is now implemented **literally**: the fence layer's single input is the boolean `fenceRetired` (the `createBwrapFence` option is renamed from `yolo`, `src/harness/sandbox/bwrap.ts:215` / `:724`), and `yolo` is the name of a **preset**, not of the axis. That is the separation ADR-0139's withdrawal was reaching for, carried one layer further: the axis the primitive reads is named for what it does, so the label no longer travels with the exemption. The `full_auto` clause ADR-0139 withdrew is **re-adjudicated, not reversed in place** — the fence primitive still never writes permission, and the object that writes `full_auto` is the yolo preset's overlay declaration (ADR-0141 §1). The "not a fourth `PermissionMode`" ruling is untouched. Cross-references: ADR-0141 ruling 1 and its §Relations to the ADRs this revises.

**Basis (original, superseded in part):** `PERMISSION_MODES` three values (`src/harness/permission/modes.ts:28`); the Shift+Tab three-state cycle stays; the blast radius of renaming (or squeezing yolo into the value domain) — settings value domain / fail-loud validation / `docs/CONTEXT.md` / all tests — far outweighs the gain.

### 2. The physical boundary of no-sandbox: all four routes bare, landing on the single factory

**All four routes run bare**: foreground bash / background spawn / verify sandbox-run / subagent worker. Landing shape = the yolo branch of `createBwrapFence` (`src/harness/sandbox/bwrap.ts`); the four routes inherit it transparently. No "foreground-only" half-bare mode. _(**ADR-0141 ruling 2** renames that branch's input to `fenceRetired`, computed from the effective configuration; `yolo` survives only as a **preset** name. The four-route landing shape, the single factory and the no-half-bare ruling are unchanged — and this ADR's Decision paragraph above names the same branch with the old spelling.)_

**Basis:** the assembly points all call the same factory (`src/harness/aci/tools/bash.ts` / `src/harness/background/manager.ts` / `src/harness/verify/sandbox-run.ts`); the subagent worker reaches the same `createBashTool` via the registry. One branch at the factory covers four routes — that is the reason for branching at the factory rather than at the call sites.

**Wire hygiene (post-review amendment):** the subagent-worker `IKNOW_YOLO` env wire is normalized parent-side — holder wired → `"1"` / `"0"` both written (same discipline as `IKNOW_WORKTREE_GATE_ON`), and an inherited ambient `IKNOW_YOLO` is always scrubbed from the child env — so a stray host value can never retire a worker's fence under a non-yolo parent (fail-closed). _(**ADR-0141 ruling 6** renames the key to `IKNOW_FENCE_RETIRED`, because after that ruling the wire carries a fence fact and `--no-sandbox` spawns must inherit it without being labelled YOLO. The value domain, the both-values-written discipline, the ambient scrub, and the fail-closed direction are byte-identical; the scrub covers **both** spellings while the change lands — key `src/harness/sandbox/yolo.ts:106`, ambient scrub `src/harness/subagent/spawn.ts:237`, write `src/harness/subagent/spawn.ts:253-255`, read `src/harness/subagent/worker.ts:540-546`, fail-closed parse `src/harness/sandbox/yolo.ts:119-124`.)_

### 3. Relation to the network axis: the egress seam is skipped wholesale

Under yolo the **egress seam is skipped wholesale** (no unix socket bind, no proxy env injection): no fence = no netns → the network is naturally wide open and the domain allowlist does not intervene. Non-yolo keeps egress as-is (ADR-0097 unchanged); **yolo is its explicit exemption face** (the Amendment lives in the ADR-0097 file).

**Basis:** `egress` is a `BwrapFenceOptions` field; `specs/network-egress-allowlist.md` "Out of this spec" already carves `--yolo` out of that spec's scope (the two axes are orthogonal; the exemption is adjudicated here).

### 4. Relation to the worktree gate: not skipped

**Not skipped.** The gate manages "which tree receives writes"; the fence manages "whether a process can escape the sandbox" — two orthogonal axes, and yolo changes no gate semantics.

**Basis:** `src/harness/isolation/worktree-gate.ts` (read once per wave, never mid-wave); the orthogonality declaration lives in the `docs/CONTEXT.md` Relationships section ("filesystem isolation tier vs worktree isolation mode"); ADR-0037 states the two axes are orthogonal.

### 5. Red display placement: the mode-row badge slot, no new bottom-bar row

With yolo ON the **mode row** carries the red YOLO text (reusing `pal.error`, `src/tui/theme.ts:87`); no new bottom-bar row. _(**ADR-0141 ruling 5** keeps this slot and puts **two** derived indicators in it — the YOLO badge (unmodified yolo preset only) and a persistent 无沙箱 marker computed from the **effective configuration**, never from which entry raised it; the concatenated per-axis projection of today's `modeRowText` (`src/tui/app.tsx:910-919`) is replaced, not relabelled — when the preset is unmodified the row shows **YOLO + 无沙箱** without concatenating per-axis labels, and since suppression is keyed to what a visible indicator already states rather than to "a preset is active", the **`--no-sandbox` preset keeps its permission label** (ADR-0141 ruling 5), and the marker's light condition includes live descendants spawned while the fence was retired (ADR-0141 ruling 5); today's concatenating projection in full: `modeRowBaseLabel` (`src/tui/app.tsx:879-887`) + marker in `modeRowText` (`:910-919`), rendered at `:5965` / `:5972`.)_

**Basis:** the mode-row render site in `src/tui/app.tsx`; the `chromeReserveRows` line accounting — riding an existing row makes the row cost zero; `pal.error` red precedent (`src/tui/context-bar.tsx` `contextColor`).

### 6. Exit path: re-entering `/yolo` exits, restoring the snapshot

In a TUI session, `/yolo` re-entry exits (**no confirmation** — the asymmetry with entry is deliberate: exiting is always safe); permission / fsMode restore the pre-entry snapshot. A session that started yolo (`--yolo`) lands back on `default` / project `plan` after exit (snapshot = the startup initial values). _(**ADR-0141 replaces this mechanism.**)_

> **AMENDED by ADR-0141 (2026-10-15).** The **outcome** stands (exit is immediate, unconfirmed, and lands back on the pre-preset values); the **channel** is replaced: there is no snapshot and nothing to re-apply. Both presets live in a memory-only **session overlay** tier between the startup flag and persisted settings (ADR-0141 §2), and exit **clears the overlay**, letting the lower tiers show through — which reproduces this ruling's "lands back on `default` / project `plan`" by construction, and is the fix for the defect ADR-0141 records as F4: a snapshot restore re-applied unconditionally over a `/config` write that had already persisted a different `fsMode` left runtime and file disagreeing (this ruling's "restore the pre-entry snapshot", `src/harness/sandbox/yolo.ts:373-375`). The idempotency basis ("re-entry does not snapshot twice; repeated exits do not overwrite") survives as a property of a boolean overlay: it is either present or cleared. The clause this replacement makes **new work** is ruling 3's: a user change of an axis **the preset declares** must clear the whole overlay (ADR-0141 §3) — `fsMode` under both presets, permission under the yolo preset only, and by any channel (`/config`, `/permissions`, Shift+Tab) — and the permission axis has no settings write-back channel today (`src/config/persist-settings.ts` exports none), so one must be added — user-layer only, per ADR-0090. The full replacement face, per ADR-0141 rulings 3 and 9: the in-preset user change of a declared axis **exits the preset** — clear the whole overlay, write the user's choice to settings, recompute the effective values, drop the preset's markers — and that single action is what closes defect F4, the runtime/persisted disagreement reproducible across `src/tui/app.tsx:1110-1121` and `src/harness/sandbox/yolo.ts:373-375`; the idempotency this ruling guarded is now a construction property, not a guarded one. This section's **heading** ("restoring the snapshot") and the **Basis** line below are the retired half of the ruling; they stay verbatim as the record of what was ruled, and are stale on this reading only.

**Basis:** snapshot restore = least astonishment; user-layer settings are never rewritten (ADR-0084 discipline); entry and exit are both idempotent sets (re-entry does not snapshot twice; repeated exits do not overwrite). _(**ADR-0141**: the snapshot is deleted, not guarded — see the amendment above. Least astonishment and the never-rewrite-user-layer discipline both survive on the whole-overlay clear.)_

### 7. Non-interactive entries: TUI only; the five other public commands fail at parse with a typed error

**TUI only.** `chat` / `serve` / `ask` / `oneshot` / `trace` carrying `--yolo` → a parse-time **typed error** (not a silent ignore); the `__subagent_worker__` early-return path does not count as an entry, only the parent agent triggers it.

**Basis:** operator lock "only before entering the TUI"; the `--auto-mode` silent-ignore precedent (`src/cli.ts`) is **not adopted** — a dangerous flag silently swallowed is worse than a typed error; `trace` is an independent public branch in `src/cli/parse-args.ts` and must appear in the entry enumeration.

> **AMENDED by ADR-0141 (2026-10-15), ruling 7 — extended, not widened.** `--no-sandbox` joins the same typed refusal set on `chat` / `serve` / `ask` / `oneshot` / `trace`; the enumeration grows by one entry, its kind — parse-time typed error, non-zero exit, nothing started — does not. The guardrails that ride the extension are ADR-0141 ruling 7's: a root refusal is **new** (no uid check exists anywhere in `src/` today), the non-TTY refusal is current and already implemented for the renderer (`src/tui/run.tsx:429-437`) and now covers the preset entry as such, and a `yolo` / `no-sandbox` field appearing in settings is ignored **with a warning** — which is **new**, because unknown keys are dropped silently today (`src/config/settings.ts:1494-1508` reads declared fields only).

### 8. Persistence: none

**Not persisted**: never enters settings, never enters session files, no config-panel row. Startup `--yolo` is supplied per session explicitly; in-session switches are memory-holder only. _(**ADR-0141 ruling 8's half is replaced; this no-persistence ruling continues to bind.**)_

> **AMENDED by ADR-0141 (2026-10-15).** The **no-persistence** ruling stands verbatim and is inherited by the new carrier: the session overlay is memory-only, never a settings key, never a session-file field, and it must not be routed through native session state either (whose exclusion rules already refuse a `/…|yolo/i` field — `src/session-api/store/native-state-store.ts:294-297`). Two consequences of that inheritance: the marker is a **derived display** value (ADR-0141 §5), so no new persisted field is needed for it; and a `yolo` / `no-sandbox` key that a user writes into settings is **ignored with a warning**, where today an unknown key is ignored silently (`src/config/settings.ts:1494-1508` reads declared fields only). The **snapshot half of the "memory-holder only" mechanism is replaced** — see ruling 6's amendment: provenance lives in which tier the value came from, not in a remembered copy. Ruling 6's replacement is the only part of this ADR that makes a `/config` choice **durable**: an in-preset `/config` change clears the whole overlay and writes the user's choice to settings (ADR-0141 §3), which is the user layer's own persistence, not the preset being persisted.

**Basis:** permission / fsMode / graph / worktree are all pure-holder precedents (reseeded from settings or defaults on restart).

## Conflict resolutions (two, both named)

**(a) `docs/CONTEXT.md` "sandbox discipline"** — the absoluteness of "the product path must not offer an unfenced bare background run" is **named-exempted exactly once** by this ADR: yolo is the **only** explicit, operator-locked counter-example; the discipline itself (the same `bash` input → foreground and `background:true` share one fence parameter set) remains word-for-word effective on non-yolo paths. **Relation = amend (the entry gains an exception line pointing here), not supersede** — the discipline is not overturned, only annotated with one named exemption face. The entry revision lives in `docs/CONTEXT.md` ("sandbox discipline" + the new "yolo mode" entry).

**(b) ADR-0097 Settled invariant #1** (`--unshare-net` permanent, no second exit, no escape hatch) — yolo is an **explicit exemption face, not a silent override**: under yolo the fence retires wholesale, `--unshare-net` disappears with the rest of the flags, and the egress seam has nothing to carry (no socket bind, no proxy env). **Relation = Amendment 2026-09-18 (appended to ADR-0097), not supersede** — on non-yolo paths the permanence, sole-egress property, and byte-for-byte argv shape of `--unshare-net` all hold; every other clause of ADR-0097 (domain allowlist, approval flow, address guard, socat prerequisite) stands.

The common shape of both resolutions: **an exemption must be explicit, named, and greppable to a pointer**, never "a conditional branch silently in force" (that is precisely what the `--unshare-net` landing comment "No conditional, no escape hatch" guards against — yolo is that hatch's **explicit named version**, not it smuggled back in).

## Amendment 2026-09-29 (eval state)

**Ruling 7 is qualified, not overturned.** `--yolo` remains a parse-time typed refusal on `chat` / `serve` / `ask` / `oneshot` / `trace` (`src/harness/sandbox/yolo.ts:79`), and yolo still has exactly two entry points. ADR-0130 adds a separate named posture — **eval state** — which reuses this ADR's **fence** state-combination verbatim (`fsMode: workspace` → `global`, fence retires wholesale, egress seam retired, all four routes bare) but is reached headlessly through an explicit, non-default, named opt-in. _(This paragraph originally said eval reuses the combination "verbatim (permission → `full_auto`, …)". **ADR-0139 §3 re-adjudicates that clause:** the permission posture is no longer shared carrier evidence — eval writes `full_auto` from its own entry, because an operator cannot answer questions mid-run.)_ Basis: benchmark evaluation has no use for the fence, and invariant #1's constant `--unshare-net` would make install-dependent tasks structurally unsolvable for reasons unrelated to the model, destroying the score's attribution. _(**ADR-0141 §1** changes eval state's carrier only, not its posture: `--eval-state` is now the **declarative application of the yolo preset** at startup, so eval's own `full_auto` write (`src/harness/sandbox/eval-state.ts:234`) is absorbed into the preset it already reached by delegation. The resulting triple (`full_auto` + `global` + fence retired) is unchanged, which is why no ADR-0130 §2 measurement claim moves and published numbers stay comparable.)_

Three consequences for this document's own wording:

- The defense line this ruling relied on — entry enumeration plus the parity tests — holds against what it was written to prevent, a _silent_ extension. - The title's "the single explicit, operator-locked counter-example" and Conflict resolution (a)'s "named-exempted exactly once by this ADR … yolo is the **only** explicit, operator-locked counter-example" (`:93`) stay verbatim as the record of what this ADR did, and are qualified here: there are now **two** named counter-examples to `沙箱纪律` #653 G3 / ADR-0097 invariant #1 — yolo mode and **评测态** (ADR-0130). ## Amendment 2026-10-10 (bare TTY launch enters the TUI)

**Ruling 7 is qualified, not overturned.** The operator approved one CLI routing exception (issue #1234; approved matrix: `plans/issue-1234-bare-launch-compatibility.md`): a bare `iknow` on a TTY now starts the TUI in default mode, and a bare `--yolo` / `--auto-mode` on a TTY modifies that same launch by carrying its own posture. YOLO remains a **fence-axis** choice and never suppresses permission asks — ADR-0139's permission / fence axis independence is untouched here. _(**False for `--yolo` from ADR-0141 (2026-10-15)**: the bare `--yolo` launch carries the **yolo preset**, which does set `full_auto`, so it does suppress permission asks while the hard wall still intercepts; the fence-axis-only sentence stays true of `--no-sandbox`. Ruling 7's **refusal** set is extended to that flag too. ADR-0141 touches no routing: every route declared in this section stands verbatim. Whether a bare `--no-sandbox` on a TTY follows the same declared route as bare `--yolo` — a TUI start carrying its own posture — is **undeclared in ADR-0141** (its ruling 1 names the flag as a launch entry with **no modal**, and its P6 leaves the flag's in-session surface open); recorded as open, not inferred here.)_ What ruling 7 refused and still refuses verbatim: `chat` / `serve` / `ask` / `oneshot` / `trace` carrying `--yolo` → a parse-time **typed error**, non-zero exit, nothing started. Yolo's entry points keep their number and kind — the launch flag before the TUI starts, plus in-session `/yolo` with its confirmation modal; what changed is only which bare invocation reaches a TUI launch. _(Before this ruling the handling of bare `--yolo` had to be declared but could be satisfied by a display path; `specs/yolo-mode.md`'s CLI `--yolo` row and its EXIT now declare it as a TUI start.)_

**Explicit routes keep their own contract.** `iknow chat` keeps the REPL route and explicit chat resume stays `iknow chat --resume <id>`; `iknow tui [session-id]` keeps positional resume. Every headless and evaluation entry is unchanged — `iknow ask <query> --eval-state`, the explicit oneshot / query evaluation paths and the other headless evaluation entries keep their semantics, stdout JSON, stderr notices, exit status, `runState`, invalid-combination handling and the eval-state gate, and an explicit evaluation request is never routed to a TUI. `-h` / `--help` / version remain pure display paths that start no session — a display path produces no query and no session (ADR-0130 §7) — and bare `--eval-state` with no query remains that display path on either TTY state, not an eval-state execution. Off a TTY, bare `iknow` keeps its existing help / no-session behavior, and non-TTY bare `--json` / `--resume` keep their existing contract.

**Legacy chat flags and TUI-only postures do not mix silently.** On a TTY, bare `--json` and bare `--resume <id>` keep the chat route: they are neither mapped onto the TUI nor refused when used alone. On a TTY, a legacy-chat flag combined with a TUI-only posture (`--json --yolo`, `--resume <id> --auto-mode`, or any other such mix) is an **actionable typed conflict raised before startup**, and neither request is silently discarded — the same fail-loud principle ruling 7's Basis states for a dangerous flag. Off a TTY there is no route to contradict: the bare invocation stays the declared help / no-session display path of the paragraph above, so nothing starts and nothing is discarded. Within the TUI namespace the refusals are typed as well, on either TTY state: `iknow tui --resume <id>` is refused with positional guidance and `iknow tui --json` with `iknow chat --json` guidance, both before a session starts. The parser keeps reading posture flags only from option positions, so a query word spelling `--yolo` or `--eval-state` remains query text (ADR-0130 §7's consumption-derived rule).

**The Bun fallback is bounded.** When Bun is missing, a TUI launch falls back to chat **only** for an ordinary implicit bare TTY launch carrying no TUI-only requirement; bare `--yolo`, bare `--auto-mode`, and explicit `tui` fail loudly before startup rather than degrading to a route that cannot honor what they asked for.

**Nothing else moves.** Rulings 1-6 and 8, both conflict resolutions, the no-persistence ruling, the non-goals, and the Consequences' defense line (entry enumeration on the five public commands + the `tests/harness/sandbox/yolo-probe-parity.test.ts` face) stand as written. This amendment records an operator-approved routing outcome: it creates no new posture, no new entry, and no new exemption face — the count of named counter-examples to `沙箱纪律` #653 G3 / ADR-0097 invariant #1 stays two (yolo mode, eval state). _(**ADR-0141 (2026-10-15) is not covered by this sentence** — it adds a **named entry** and re-grants this ADR's original posture at the preset layer; see the Amendment 2026-10-15 section.)_

## Amendment 2026-10-15 (ADR-0141: presets, one session overlay, and `fenceRetired`)

ADR-0141 amends this ADR **without superseding it**. What it takes from this document is the identity between the fence-retiring primitive and the name `yolo`; what it leaves standing is most of the rulings. Clause by clause:

**Stands verbatim.** Ruling 2 (all four routes bare, one SSOT factory branch, no half-bare mode), ruling 3 (the egress seam skipped wholesale, ADR-0097's exemption face), ruling 4 (the worktree gate is not skipped), ruling 5's **slot** (the mode row carries the indicator, no new bottom-bar row), ruling 7's **shape** (TUI-only interactive entries, typed non-zero refusals on the other public commands), ruling 8's **no-persistence**, both conflict resolutions, and every non-goal. Ruling 1's "independent boolean state axis, not a fourth `PermissionMode`" stands and is finally implemented literally, because the primitive's input is now named `fenceRetired`.

**Replaced.** Ruling 6's snapshot/restore channel and ruling 8's snapshot half: the two presets live in a memory-only **session overlay** between the startup flag and persisted settings, exit clears the whole overlay rather than re-applying a remembered copy, and any user change of an axis the preset declares clears it too — `fsMode` under both presets, permission under the yolo preset only (ADR-0141 §3). That is the fix for the defect ADR-0141 records as F4 — an unconditional `exit()` restore over a `/config` write that had already persisted a different tier (`src/harness/sandbox/yolo.ts:373-375` vs `src/tui/app.tsx:1110-1121`) left holder and settings file disagreeing, and the holder could not tell "forced by the posture" from "chosen by the user" because both facts sat in one field.

**Re-adjudicated, not reversed in place.** Ruling 1's `full_auto` clause (withdrawn here by ADR-0139) is re-granted **at the preset layer**: `--yolo` means fence retired + `fsMode: global` + `full_auto`; the fence primitive itself still never writes permission, which was ADR-0139's mechanism ruling and survives untouched. The posture ADR-0139's withdrawal produced — no fence, questions still on — is not discarded; it is **named for its content** as `--no-sandbox`, so the word `yolo` stops meaning something other than what the flag does.

**Renamed.** `BwrapFenceOptions.yolo` → `fenceRetired` (no `yolo` judgment remains in `bwrap.ts`), and the parent→worker env wire `IKNOW_YOLO` → `IKNOW_FENCE_RETIRED` with the value domain, the both-values-written normalization, the ambient scrub, and the fail-closed direction byte-identical (ruling 2's wire hygiene, in kind). The scrub covers both spellings while the change lands.

**The count, precisely.** This section, unlike the 2026-10-10 one, **does** add a named entry. What it does not add is a new posture or a new exemption face: the yolo preset re-grants this ADR's original combination, and `--no-sandbox` is the name for the posture ADR-0139's withdrawal left reachable since 2026-10-06 — reached through a new flag, not opened by a new decision. ADR-0141 itself does not restate the count of named counter-examples to `沙箱纪律` #653 G3 / ADR-0097 invariant #1. What its rulings do fix is the structure: **one face** — wholesale fence retirement at the one factory branch — reached by **three named entries**: the yolo preset, `--no-sandbox`, eval state. Whether the canonical sentence should henceforth say "two counter-examples" counting postures or "three" counting entries is **pending**, not decided by ADR-0141 and not decided here. What holds on every reading is the qualification Amendment 2026-09-29 already made — the scoping, not the count: every entry reaching the face is explicitly named, greppable to a pointer, markered in the UI, refused with a typed error on non-TUI commands, and never persisted, which is exactly why ADR-0141 rejected "a second un-fenced switch with no marker."

**What ADR-0141 adds that this ADR never had.** A root refusal (none exists in `src/` today), a derived-from-effective-config 无沙箱 marker with a spawn-time fence fact registered on live subagent and background descendants, an asserted invariant (`workspace` tier and a retired fence are never simultaneously effective) that raises a typed error rather than correcting silently, and a permission settings write-back that does not exist today and must be user-layer only per ADR-0090. Their rulings are ADR-0141's; the spec disposition and the copy sweep live in `specs/yolo-mode.md`.

**The records stay, qualified as before.** The title's "the single explicit, operator-locked counter-example" and Conflict resolution (a)'s "named-exempted exactly once by this ADR … yolo is the **only** explicit, operator-locked counter-example" stay verbatim as the record of what this ADR did on 2026-09-18, qualified here exactly the way Amendment 2026-09-29 already qualifies them: what survives in both sentences is their scoping — the counter-example is explicit, named, and operator-locked, never a silent branch — and their count describes the entries of that date, not a standard later entries must meet. ADR-0141's preset structure keeps the scoping intact; the entry enumeration is what grew.

## Deletion / non-goals

**Out of this decision's scope** (named item by item, so later implementations cannot casually extend it):

- The `web_fetch` / `web_search` **network-guard stack** — a different defense line; yolo does not touch it (same declaration as `specs/network-egress-allowlist.md` "Out of scope").
- **The worktree gate** (`worktreeOnMutate` / `src/harness/isolation/worktree-gate.ts`) — orthogonal axes; yolo neither changes gate semantics nor skips it.
- **The hard wall** — the hard wall still pre-filters, in every permission mode including `full_auto` (ADR-0068 / ADR-0090 unchanged). _(Reworded by ADR-0139: the wall's independence never depended on yolo implying `full_auto`; it is a pre-filter that runs before any mode grants anything.)_ _(ADR-0141 leaves this untouched: a preset is an axis combination, never a guardrail bypass — the hard wall and security review intercept as before, in every preset and outside one.)_
- **The `PERMISSION_MODES` value domain** — still three values (`src/harness/permission/modes.ts:28`); no fourth value, `full_auto` keeps its name.
- **No persistence** — never enters settings / session files / config-panel rows (ruling 8). _(ADR-0141 ruling 2 keeps this binding on the new carrier: the session overlay is memory-only, has no snapshot, and never becomes a settings key — see ruling 8's amendment.)_
- **No unconfirmed silent in-session switch** — in-session entry must pass the confirmation modal. _(ADR-0141 keeps this ruling and narrows its **scope** to in-session entry: the modal belongs to no launch flag, since the flag typed in a shell is itself the explicit act (its ruling 1), and `--no-sandbox` has no in-session entry yet, so today the clause binds `/yolo` alone (its P6). `--eval-state` remains excepted, being headless by design.)_
- **No half-bare mode** — there is no "foreground bare + background still fenced" second fence shape (ruling 2).
- **ADR-0097 is not revoked** — egress works as usual on non-yolo paths.

## Consequences

**Positive / Applied:**

- Four-route consistent bare execution is realized by a **single SSOT branch** (`createBwrapFence`); no second fence assembly exists; the new `BwrapFenceOptions.yolo` field being absent (`undefined`) = non-yolo, argv byte-identical to before. _(**ADR-0141** renames that field to `fenceRetired` and states the same absent-means-fenced default: the option is computed from the **effective configuration**, not from an entry label. The bullet's content — one branch, absent = fenced, byte-identical argv — is unchanged and is what the V1 baseline pins.)_
- The exemption face stays auditable: the yolo argv checks are certified by `tests/harness/sandbox/yolo-probe-parity.test.ts` against real factory output (see Amendment (iii) for the probe disposition).

**Negative / Trade-offs:**

- "no unfenced bare run" is demoted from an absolute discipline to "discipline + one named exception"; the moment the exception is copied or silently extended to non-TUI entries, the discipline is dead — the defense line is the entry enumeration (typed errors on the five public commands) + the parity tests, not the wording.
- Without netns the domain allowlist does not intervene: a yolo session's egress has **no boundary at all**. This is the cost the operator accepted; copy and docs must never phrase it as "controlled".
- Host-without-bwrap races are first-class citizens: symmetric probes on both enter and exit sides (refuse entry/exit when bwrap is gone); the residual race has no fence-assembly face under yolo (no route invokes bwrap mid-session) and the generic non-yolo failure surface stays byte-pinned out of scope (see `specs/yolo-mode.md` Contract §"Runtime failure surface under yolo").
