# P1 两脆点纸面复盘（Phase 2 协议韧性验证）

> 来源：P2-plan.md §3 要求。本文为纯纸面复盘，不写代码、不改 ADR/tool-schema。
> 结论类型：协议改 or 标 Phase 3。

## 脆点 1：隐性治理依赖降级（kb_retrieve 的 A filter 在线治理检查）

**现象**
ADR 规定 `kb_retrieve` 的 A filter 在检索时做在线实时治理检查（C 退预计算路径）。这意味着 retrieve 运行时隐性依赖 governance 能力——若 governance 服务不可用，retrieve 的"实时过滤"语义就悬空。

**当前协议缺口**
ADR 只标了 Phase 3 降级路径（C 退预计算），**未定义"在线检查超时/不可达时的默认行为"**。可能取值：
- (a) 降级到无过滤返回（可用性优先，但牺牲治理零容忍）
- (b) 降级到拒绝返回并显式声明"治理不可用"（安全性优先，牺牲可用性）
- (c) 带 stale 快照返回并打标（折中）

**纸面结论：标 Phase 3，不在此改协议**
- 该默认行为是**实现层 failure mode 决策**，依赖 gbrain governance 实际可用性特征（超时阈值、熔断策略），纸面无法定论。
- 但需在 eval 集补一条**对抗 case**（治理服务超时降级），让 Phase 3 实现时必须显式处理并测试。见 eval-set `qa-edge-006`（已补）。
- ADR 待决项登记：§5 已记"§7 安全冲突留痕 / 鉴权模型 / 异步交互"为 Phase 3；本脆点默认行为追加为 Phase 3 待决，不擅自改 ADR 已决项。

## 脆点 2：护栏负面 case 缺失（G2 缺失 / hops>5）

**现象**
../protocol/walkthrough-b-test.md 只验 happy path + 基础多跳，未验两项硬约束的负面路径：
- G2 缺失时强制不返回用户
- hops>5 强制"无法确认"

**纸面结论：协议无需改，eval 已覆盖**
- 这两项硬约束在 ADR §2/§3 已明文（G2 必填、max_hops=5），协议本身无缺陷。
- 当前 eval-set 已含对应对抗 case：
  - `qa-edge-001`：敏感文档 G2 缺失 → 强制不返回用户（requireApprovalFor 拦截）
  - `qa-edge-005`：八部门历史决议 → hops>5 截断并声明范围限制
- 结论：护栏负面路径**已在 eval Edge 层覆盖**，协议韧性验证通过，无需提 ADR 修订。

## 总评

| 脆点 | 协议缺陷？ | 结论 | 下一步 |
|------|-----------|------|--------|
| 1 隐性治理降级默认行为 | 否（实现层决策） | 标 Phase 3 | eval 补对抗 case + ADR 待决项登记 |
| 2 护栏负面 case | 否（已明文） | eval 已覆盖 | 无需改协议 |

P2 范围内两脆点复盘**闭合**：脆点 2 验证通过，脆点 1 明确为 Phase 3 实现层待决并已在 eval 留对抗 case。
