**Accepted policy:** Confirmed dangerous behavior, including a confirmed nested command, stays in the non-overridable deny tier. When a security-relevant pattern is present but execution, data ownership, heredoc receiver, or bounded recursive analysis cannot be resolved, `default` and `full_auto` both require a fresh interactive decision for that call. A subagent may satisfy this requirement through a parent-owned review broker that displays the request in the foreground UI and relays the one-call answer. If no such end-to-end interaction route is available, return a typed deny. Proven inert data follows the ordinary permission flow; a clean `full_auto` call keeps its automatic allowance. This is a separate pre-mode review gate, not an `ask` arm of deny-only `HardRuleSpec`. Existing pre-parse vetoes and `malformed`, `aborted`, and `over-cap` hard denies remain unchanged.

C1's #1148 source cleanup covers the fork-bomb doc claim, duplicate receiver-ownership claims, the receiver predicate's name/doc mismatch, the false implication comment, and the duplicated heredoc span validity check. **C2 input and failure contract:** An empty valid command creates no review requirement. A non-string command, missing required command word, or negative/out-of-bounds source span is an invalid input and yields a typed deny. Existing `over-cap`, `malformed`, `aborted`, and `vetoed` hard denies remain in force. A parser exception keeps the typed `aborted` deny; an attribution-evaluator exception yields a typed evaluation-failed deny. Both carry non-empty reasons and can exit only after the input or evaluator is repaired. Concurrent calls have no shared or persisted approval. Recursive budget exhaustion with relevant dangerous content requires review. Route worker requests through the owning parent session's broker, with isolated request IDs and per-call answers; never let one approval satisfy another worker or call. Broker absence, disconnection, cancellation, or timeout yields a typed deny with the unresolved span and an exit of interactive retry or command revision; detect this before invoking any permissive callback. Interactive approval applies to one call only. C2 tests must cover empty valid input, invalid input including a negative span, overflow, concurrent calls, parser and evaluator exceptions, recursion budget exhaustion, a `wait:false` background worker request shown in the parent UI and answered back to the correct worker, two concurrent workers with approval for only one call, and typed denial for each of missing broker, broker disconnection, cancellation, and timeout. With no broker, an injected callback returning `true` must not be invoked.

No unexplained divergence survives; the security-bypass replay file stays byte-unchanged and passes.
