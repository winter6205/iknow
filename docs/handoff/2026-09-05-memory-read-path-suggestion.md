# 建议：自动记忆读路径减负（2026-09-05）

给 **iknow**（coding agent）的只读建议，不是 ticket、不是实施。写路径（抽取 N≥2、dream 24h∧5、`source: auto|dream`、机械 GC、默认 OFF）可以不动。要动的是 **system 里摊了太多记忆**。

对照：图「轻量只读问句的上下文卫生」G2 曾选「停下令，留目录，留 prefetch」。目录留在 system 后，模型仍会把标题当必须 recall 的清单。本建议是 G2 的收紧，不是重开抽取。

## 现象

`autoExtract === true` 时同时存在：

1. system：**全库** `memory_catalog`（title + 钩子）
2. system：recall 满 2 个 session 后的 **promote** 正文
3. 用户消息：BM25 预取最多 5 条 **正文**（零词命中不要；会话 id 去重）——这一条是对的

(1)(2) 让模型过度考虑记忆；(3) 才是跨会话真正生效的读路径。lifetime `recall_count` 买 system 席位，会把「当天正在做的题」写成长期指令。

## 建议（读路径）

| 留                                               | 改                                                                                         | 去掉（至少先做 A/B）         |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------ | ---------------------------- |
| `EXISTENCE_POINTER` 一句（有库；预注入不是指令） | 预取载荷改成 **title + 第一行钩子**，最多 **3** 行，仍用户侧、仍 BM25、仍去重、仍零命中=空 | **全库 catalog 进 system**   |
| 抽取 / dream / GC                                | 钩子用 body 第一行 ≤80 字；不新加 summary 字段                                             | **promote 进 system**        |
| `usage.json` 给 GC 效用                          |                                                                                            | 用 recall 次数当 system 奖励 |

向量检索不要为记忆先做。库小，词法够；漏改写再加第二路打分。记忆不要接到文档 retrieve。

## 验收（证明过度注意下降）

- 轻量只读问句：零预取或预取与问句无关则为 0；不因目录标题去 `memory_recall`。
- 本轮用户句撞词：≤3 行短索引出现在用户侧，不进 system。
- 当天密集做某题：那些 fact 不因为 recall 次数进入下一会话的 system。

## 不是本建议

改默认 ON；改抽取 N / dream 双闸；把 catalog 纪律句再写长一点当主修（已证明压不住）；在本仓实施 fin 的档案 deny list。
