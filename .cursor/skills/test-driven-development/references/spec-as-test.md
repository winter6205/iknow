# S4 测试即规约 - 详细规范

## 二元判据 (任一违反 = FAIL)

- [ ] 测试先于实现 commit (红测试必先 commit)
- [ ] 测试用例覆盖 spec 全部验收点
- [ ] 无 mock 替代真实代码 (除非外部依赖不可避免)
- [ ] 测试失败时报告的是"功能缺失"而非"拼写错误"
- [ ] 重构后所有原测试仍通过

## 出处

Kent Beck 《TDD: By Example》(2002) 三大法则 | Fowler 《Refactoring》2nd ed. | Google SE@G Ch.12

## AI 易违反痛点

LLM 直接生成大批生产代码再补测试, 跳过"先写最简失败测试"的节奏, 测试耦合在既有实现而非需求上。
