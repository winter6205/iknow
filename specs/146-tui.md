# Spec: iknow tui 子命令 · 交互骨架（#146）

> 来源：`wayfinder:grilling` #146（TUI 设计 grilling，Q1–Q5 收口 + Q6 库选型在本 spec grilling 会话收口）+ 操作员逐题裁决（2026-08-04）。
> **blocked by `specs/120-session-persistence.md`**：共享池 / 命名空间 / summary / schema v2 是 server 侧交付，本 spec 只消费。
> 视觉稿（banner / markdown 渲染 / 运行指示器）= issue #154（blocked by 本 spec），交互与视觉分离。
> 流式渲染 = #147（独立票，不阻塞本 spec；本 spec 落「整段返回 + spinner」）。

## Objective

新增 `iknow tui` 子命令：终端里的多会话交互界面，与 web UI（serve）共享同一会话池（#120 α 直连 SessionStore）。核心价值 = #120 Q6 验收标准在 TUI 入口成立：**TUI 写入的会话，serve 能读回并续跑，反之亦然**。

用户 = iknow 开发者。心智对标 Claude Code（启动即新会话、slash 命令、会话可切换续接）。成功 = Q6 双入口验收通过 + 交互骨架可用（列表 / 切换 / 新建 / 续接 / 打断 / 退出）。

## Glossary（CONTEXT.md 原样引用）

- **append-only messages**：权威历史，不可变追加；TUI 外壳与 chat 外壳同等纪律（`ReadonlyArray` + `Object.freeze`）。
- **turnCount**：回合计数；TUI 显示会话元信息（`/info`）时引用。
- **iknow serve**：共享会话池的另一入口（对照物）。

## Architectural Constraints（按编号引用 ADR）

- **ADR-0003**：TraceService。**TUI 接入 trace**（#146 决策 5 = 10a 裁决）：trace 埋点在 hub 层（`postMessage` 内按 conversation 建 `JsonlTraceService` 实例，hub.ts:238-249），TUI 走 hub 自动继承，零 UI 层埋点。D10 排除 chat 的理由（REPL 交互边界增加测试面无调试价值）不适用于 TUI——边界在 hub 不在 UI。
- **ADR-0007（候选，随 specs/120 落档）**：整 JSON + tmp/rename、共享根 `~/.iknow` + sha1(cwd)[:12] 命名空间——TUI 的会话池即此池。
- **#120 server spec**：SessionFileV1 v2 / sanitize / summary / ReadonlyArray 纪律——TUI 全部消费，不重新定义。
- **#146 grilling 收口（真值）**：Q1 = A 分时切换（active-one）；Q1a = 后台继续执行（三态状态机）；Q2 = C 默认新建 + banner 设计要求；Q3 = A slash 主导；Q4 = 列内容 / 无 emoji / 无删除（D1）/ lazy create；Q5a = C 完整 markdown（降级条款）；Q5b = B 摘要行 + diff 增强；Q5c = /reset 废除 /info 保留；流式时序 = 方案②（整段 + spinner，流式归 #147）。
- **#146 决策 4（本会话收口 = 9a）**：本期**不做文件锁**。TUI 分时切换 + 单活跃会话，进程内冲突面小；跨进程（vs serve）最坏后写覆盖先写丢一个 turn，tmp/rename 保证不写坏文件。文件锁另立 issue（#114 / #120 grilling 一致倾向）。
- **#146 决策 5（本会话收口 = 10a）**：TUI 接入 trace（走 hub 自动继承）。

## Code Style

```tsx
// 状态机三态（Q1a 裁决）：idle / running-fg / running-bg；视图两态：ListView / ChatView
type SessionRunState = "idle" | "running-fg" | "running-bg";

// 消息纪律与 Q3（#120）一致：整体替换 + 冻结，永不 mutate
state.messages = Object.freeze([...result.messages]);

// slash 优先于普通消息：输入以 "/" 开头先过词表，未命中再当消息（或按 /help 提示）
```

无 emoji 约束落到渲染层：交互层 UI 元素（spinner / 标记 / 分隔线）纯 ASCII 字形；
banner 字形属 #154/#171 视觉定案（智慧之眼 braille 变体 C，非 ASCII 几何/盲文
字形、非 emoji，见 `docs/design/DESIGN-BANNER.md`）——2026-08-05 实施期按
操作员逐题定稿回填本条（原「banner 纯 ASCII」被视觉定案显式覆盖）。
会话内容（LLM 输出）是数据，原样渲染不受限。

## Testing Strategy

- **Unit**：状态机转换表（Q1a：任何会话态可自由切换；running-fg 被切走 → running-bg；Ctrl+C 仅打断 running-fg → idle；running-bg 不受 Ctrl+C）；slash 词表解析（6 命令 + 未知 `/xxx` 行为）；lazy create（发出第一条消息才建档，启动即退出不留空壳文件）。
- **Component（ink test renderer，仓库新增基建）**：ListView 列内容（summary + 相对时间 + 运行指示）；`+ 新建会话` 伪条目 Enter = /new 等价；Esc 返回聊天视图；ChatView 输入框 + 历史消息渲染。
- **Integration（Q6 验收的 TUI 半边）**：tmpdir 池 + stub adapter：TUI 桥接 hub 创建会话 + postMessage N 轮 → 独立 serve 侧 hub load 断言一致 → serve 续跑第 N+1 轮 → TUI 再读可见。（与 server spec 的 Integration 互为镜像，共用 fixture。）
- **手工验证（进 handoff）**：真实 TTY 下 `iknow tui` 启动 banner / spinner / markdown 渲染 / Ctrl+C / `/quit`；WSL2 终端兼容性。
- 不测：跨进程并发写（已知边界，另立 issue）；视觉像素级（归 #154 设计稿）。

## Boundaries

- **Always**：走 SessionHub（conditionalSave / DROP_REASONS / inflight 一份逻辑，TUI 不另写保存路径）；`TuiSessionState.messages` 从第一天 `ReadonlyArray` + `Object.freeze`；无 emoji UI 字形（banner 例外 = #154/#171 定案的 braille/几何字形，见 `docs/design/DESIGN-BANNER.md`）；lazy create；列表视图纯导航（↑↓ + Enter，无第二输入框 / focus 系统）。
- **Ask first**：slash 词表增删（快捷键别名后补可以，命令语义先问）；markdown 渲染降级触发（Q5a 条款：回退 B 要记录，不为此换库）；banner 定稿（#154 视觉稿产出，操作员过目）。
- **Never**：TUI 暴露会话删除入口（D1）；并行分屏 / 多 pane（Q1 已否决，状态机保留演进可能但不实现）；本期做流式渲染（#147）；`/reset`（Q5c 废除，持久化语境语义危险）；Ctrl+C 打断 running-bg 会话。

## Success Criteria（全部二进制可测）

1. `iknow tui`（无参数）启动 = 新会话聊天视图 + 启动 banner（Q2=C）；首条消息发出前 SessionStore 无该会话文件（lazy create）。
2. `iknow tui <session-id>` 直接 resume 该会话（历史 messages 渲染 + 可续跑）。
3. `/sessions` 打开列表视图：列 = summary + 相对时间 + 运行指示，updatedAt 降序；首行 `+ 新建会话` 伪条目；↑↓ + Enter 导航，Esc 返回。
4. `/new` 新建会话（聊天视图键入 或 列表伪条目 Enter，两条路径等价）。
5. 三态状态机：turn 运行中切走 → 该会话转 running-bg 并在后台跑完落盘；列表行显示 `[运行中]` 静态标记 + 全局状态栏 `后台运行中 · <summary>`；回前台恢复 spinner。
6. Ctrl+C 仅打断 running-fg 当前 turn（落回 idle），不影响 running-bg。
7. `/info` 显示会话元信息（conversation_id / turnCount / updatedAt / jsonMode）；`/help` 列词表；`/quit`（`/exit`）退出。
8. Q6 验收 TUI 半边（上述 Integration）通过。
9. `TuiSessionState.messages` 类型 `ReadonlyArray`，`npm run typecheck` 零错误。
10. 渲染无 emoji（UI 元素层）；markdown 渲染 spike 结论落档（可行 / 降级 B）——spike = 实施计划的**第一个任务**（ACR note），降级 B 的渲染输出形态在 spike 结论里显式定义（保留 fence 标记的等宽代码块 vs 纯文本剥离，二选一），使本条可审计。
11. `npm test` 全绿。
12. TUI 的 slash 解析**不复用** chat 的 `processChatLine`（后者已 Deprecated for CLI path），TUI 自建本地 slash 词表（`/sessions` `/new` `/quit` `/exit` `/help` `/info`）；`/reset` 不在词表内即天然不可达（ACR note 6）。
13. 列表视图数据源 = `SessionStore.list()` 返回条目里的 `summary` 字段（由 specs/120 SC 12 提供），不做 per-id 重读（保列表响应性，ACR note 7）。

## Open Questions

1. **banner 具体字形**（已收口）：#154/#171 视觉定案 = 智慧之眼 braille 变体 C（双色分层 / 图案居左 + info 栏居右 / 窄终端降级），落档 `docs/design/DESIGN-BANNER.md`；「纯 ASCII」要求由该定案显式覆盖（非 emoji 约束保留）。
2. **工具调用摘要行 + diff 渲染形态**（Q5b 增强）：write_file / edit_file 的「生成了什么 / before-after」呈现细节留实施（受无 emoji 约束）；依赖 #141 工具层重写落地的工具集形态。
3. **退出 TUI 时存在 running-bg 会话的语义**（Q1a 附注）：倾向「退出不打断后台 turn，进程退出前等待完成或显式确认」——留实施细化，不阻塞本 spec 骨架。
4. **markdown 渲染 spike 结果**：若降级 B（代码块区分），回填本 spec Success Criteria 10 并同步 #146。
