# Spec: Repair the backslash-whitespace veto (#1188)

**Status:** ratified implementation contract — the roster and EXIT rules below are the implemented, documented contract (ADR-0124 Amendment 2026-10-04; `docs/CONTEXT.md` 解析分歧字符). The success criteria are the acceptance record for that implementation.
**Issue:** [#1188](https://github.com/winner6205build/iknow/issues/1188).
**Basis:** ADR-0123, ADR-0124, ADR-0127; [investigation](../docs/evidence/1188-backslash-whitespace-investigation.md).

## Objective

Ordinary escaped spaces and modeled, unquoted word-separator line continuations reach the existing permission flow without a parse-fidelity hard denial. Actual or unresolved parser/Bash disagreement remains non-overridable. Remove the generated rewrite that changes arguments or operators, and make this distinction falsifiable in offline tooling.

This is a bounded repair to the foundation's veto roster, not a change to parse-state destinations or to the permission hierarchy. The two reported firings establish two false positives in one session, not a population-wide rate.

## Inherits / Changes

- CONTEXT defines **hard-wall** as: "A pre-execution shell-intent filter over enumerated syntax; a matched deny cannot be overridden by a session grant, while a clean scan does not certify an interpreter's runtime effects."
- ADR-0127 Decision 1: "Existing pre-parse vetoes and the `malformed`, `aborted`, and `over-cap` hard-deny outcomes remain hard denies."
- The foundation spec defines `WordFact.value` as "the statically-known literal after quote-and-backslash folding". A complete AST without `ERROR` does not establish this property.
- Preserve the verdict union, `VetoClass` identity, synchronous entry, resource limits, exact-original-command cache keys, source offsets, terminal binding-load failure, and the parser-unavailable-only legacy fallback.
- Change ADR-0124's blanket backslash-plus-whitespace membership and its rewrite compensation. The amendment must distinguish the supported spellings below from retained fidelity denials and cite reproducible measurements. ADR-0127's destination ordering remains intact.
- No new domain term is introduced. The roster amendment is recorded explicitly in ADR-0124 (Amendment 2026-10-04), which supersedes that ADR's blanket membership and its rewrite compensation in place and points back here; the CONTEXT entry is aligned to the same roster. Nothing is superseded silently: the superseded clauses carry the amendment's pointer.

## Boundaries

### Does

- Admit escaped U+0020 in ordinary unquoted words and already modeled literal single/double-quoted words when command boundaries, word boundaries, and static values agree with real Bash.
- Admit ordinary unquoted LF continuations used between words, including the issue's long-option continuation. An admitted continuation must not concatenate parts of a lexical word. Leading or operator-adjacent continuations may be included only with equivalent evidence and downstream assertions; they are not required to solve the two incidents.
- Keep mid-word LF joins and double-quoted LF continuations denied in this repair. Measurements show wrong word boundaries in the former and wrong static values in the latter.
- Keep backslash+TAB, backslash+CR, backslash+FF and backslash+VT conservative. TAB and CRLF have measured disagreements; FF/VT still hit the separate control-character veto. Pin the class precedence instead of requiring every branch to return `backslash-whitespace`.
- Make escaped-LF facts and all directly affected consumers agree. Inspect quote context and escape parity; a test of only the previous character is insufficient.
- Finalize a candidate exemption only for an `ok` parse with complete evidence at every affected lexical site: static word values are complete, or independently modeled expansion/code-bearing facts account for the dynamic parts and their ownership. A missing `WordFact.value` is not evidence of agreement. Incomplete affected facts or `unknown-syntax` retain `vetoed / backslash-whitespace`; ordinary expansion handling outside the affected site keeps its existing rules.
- Gate the new exemptions on an available parse foundation. If initial binding load fails, retain the old conservative veto for these newly supported spellings; do not send them to an unproven legacy allowance. Preserve the terminal unavailable state and warning, and the existing legacy route for commands outside this repair's exemption surface.
- Replace automatic command rewriting with a bounded diagnostic that names the retained fidelity limitation and does not suggest a reconstructed executable command.
- Add committed, synthetic incident-equivalent and adversarial corpus rows with independent expected outcomes. Extend the existing divergence tool rather than create a second parser or a second authoritative report.

### Out of this spec

- Moving `vetoed` to ordinary `unknown-syntax` or adding grants/approval bypasses for fidelity disagreement.
- Parser replacement/upgrade, global source normalization, offset remapping, cache normalization, dependencies, lockfile, or settings changes.
- Fixing every legal Bash escape form, including mid-word or quoted LF folding.
- Other veto classes, #1170's denial wording/violation accumulator, runtime timeout policy, or broader hard-wall redesign.
- Executing captured historical commands or dangerous samples. Real execution oracles use harmless, fixed argument-printing fixtures only.

## Open Questions

Implementation choices remain open: how to represent the context-aware veto predicate, how to share escape classification with newline facts without importing ACI code into `permission/`, and how to represent independent expectations in existing offline tooling. The supported surface and conservative EXIT behavior above are settled recommendations, not invitations to broaden the repair.

ANSI-C quoting and additional continuation positions are outside the mandatory supported surface. If an implementer includes them, the same Bash/facade and downstream proof is required; otherwise retain the appropriate conservative outcome and record it explicitly.

**Operator-confirmed adoption gate (2026-10-04):** The operator explicitly agreed to the explained #1188 exception to the boundary skill's TP-improvement condition: **danger/fidelity TP must not decrease, benign FP must decrease, and required behavior must not regress**. This exception applies only to #1188; it does not edit the installed skill. Axis1 must freeze the same labeled population and metric definitions for both refs before measurement. Axis2 uses this task-specific gate and records its authorization alongside the result. A stable TP count is acceptable here; losing any required dangerous/fidelity denial is not. No relabeling after A/B measurement is permitted.
