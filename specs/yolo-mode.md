# Spec: yolo-mode — the `--yolo` and `--no-sandbox` presets on one session overlay

**Status:** active — re-issued 2026-10-15 against ADR-0141. The issue #1035 lock (five dimensions, contract, input table, EXIT) is preserved as an **amendment record** where ADR-0141 changes it, not silently rewritten.
**Decision SSOT:** `docs/adr/0141-yolo-and-no-sandbox-are-presets-on-one-session-overlay.md`, inheriting ADR-0119 (the fence rulings that still bind), ADR-0139 (the axis mechanism ruling that still binds), ADR-0130 (eval state — §1's permission sentence corrected there).
**Surface:** `src/harness/sandbox/` (`bwrap.ts` factory branch + the overlay + the derived `fenceRetired` + `requireBwrap` pre-check in `runner.ts`), `src/harness/build-engine.ts`, `src/harness/aci/tools/bash.ts` + `registry.ts`, `src/harness/background/manager.ts`, `src/harness/verify/` (sandbox-run / verify-loop), `src/harness/subagent/` (parent-side env wire + worker read side), `src/harness/sandbox/egress/` (credential assembly posture branch), `src/config/` (settings read + the new permission write-back), `src/cli/` (parse-args / cli dispatch / usage / runtime), `src/session-api/hub.ts`, `src/tui/` (slash + confirm modal + mode row + persist sites), `tests/harness/sandbox/yolo-probe-parity.test.ts`.
**Plan:** `plans/yolo-mode.md` (ACR rev3 PASS — historical: it planned the original single-flag build, not this re-issue).

## Goal

Two **presets** retire the sandbox fence, and each is named for what it actually does:

| Preset           | Fence     | `fsMode`  | Permission    | Entries                                                                   |
| ---------------- | --------- | --------- | ------------- | ------------------------------------------------------------------------- |
| **yolo**         | retired   | `global`  | `full_auto`   | `--yolo` (launch, **no modal**), in-session `/yolo` + confirmation        |
| **no-sandbox**   | retired   | `global`  | **untouched** | `--no-sandbox` (launch only, **no modal**; no in-session command — P6)    |
| — not a preset   | untouched | untouched | `full_auto`   | `--auto-mode` (`src/cli.ts:1095`) — permission axis alone                 |
| declarative form | retired   | `global`  | `full_auto`   | `--eval-state` — the yolo preset applied headlessly                       |
| — composition    | retired   | `global`  | `full_auto`   | `--no-sandbox` **+** `--auto-mode` — allowed, and **not** the yolo preset |

A modal belongs to **in-session** entry and never to a launch flag: the flag the operator typed is itself the explicit act (verified — the launch path `applyYoloLaunchSeed` → `enterAtLaunch` has no modal face, `src/tui/run.tsx:411-416` / `:722` / `src/harness/sandbox/yolo.ts:350-359`; only `/yolo` opens one, `src/tui/app.tsx:2162`).

A preset is a **session overlay** in memory: it is never persisted, it has no snapshot and no restore, and the fence layer reads exactly one derived boolean out of it (`fenceRetired`) rather than a product label. Entering a preset never bypasses a guardrail: the hard wall and security review intercept in every preset and outside one, because both are pre-filters ahead of the mode branch that consumes `full_auto` (`src/harness/permission/policy.ts:413` then `:422`, layered rules `:427`, mode branch `:431`).

**The composition row is the one the table must not hide.** `--no-sandbox` with `--auto-mode` arrives at the yolo preset's triple from **two tiers** (the flag writes the startup permission tier at `src/tui/run.tsx:684`, the overlay writes fence + tier) and is refused nowhere — refusing it would reverse ADR-0139's mechanism ruling, which this spec inherits. It is displayed as what it is: **无沙箱 + `Auto`, no YOLO badge** — the `--no-sandbox` preset _is_ active and keeps its own clear, while a permission change clears nothing because no preset in the pair declares the permission axis. That is also why the yolo preset's name still carries information: one declared act with one exit, versus two flags with two separate ways back.

**Semantic boundary (inherited from the issue #1035 lock, unchanged in kind):** "no sandbox" means the fence layer is absent wholesale, not that the permission layer relaxes. ADR-0141 adds the second half of that sentence: **the two are now separately selectable**, because the fence-only reading got its own flag (`--no-sandbox`) instead of being the content of the name `--yolo`.

> **Amended 2026-10-06 by ADR-0139 (operator ruling).** The original text continued: _"Setting permission to `full_auto` is an **entailed consequence** of the entry action … it is not the definition of yolo."_ That clause was withdrawn, and yolo wrote the fence axis only.
> **Re-amended 2026-10-15 by ADR-0141.** `--yolo` again reaches `full_auto`, **as a preset declaration one layer above the fence**, not as a side effect of retiring it. ADR-0139's mechanism ruling stands verbatim and is what keeps that legal: the fence primitive still never writes the permission axis; the object that writes it is the preset. The posture ADR-0139 produced (no fence, per-call questions) is not discarded — it is `--no-sandbox` (§2 of that ADR named it, this spec gives it an entry).

**Users:** the local operator who wants "no sandbox and no questions" under the name that says so, and the one who wants the fence gone while still approving each command; the model, working under unfenced bash with no bwrap prefix in argv.

## 1. The carrier: three tiers, and the overlay is memory-only

**Effective value = persisted settings < startup flag < session overlay.** The overlay is a per-session object in `src/harness/sandbox/` (its file name is the implementer's choice inside that module; its read surface is the derived `fenceRetired` plus the declared axis values).

| Tier               | Written by                                                                                                               | Survives a preset?               |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------- |
| persisted settings | `/config` writes, user layer only (`src/config/persist-settings.ts`); settings-resolved `fsMode` (`src/tui/run.tsx:704`) | yes — this is the user's choice  |
| startup flag       | `--auto-mode` (`src/cli.ts:1095`), the permission chain `src/cli/runtime.ts:60-73` (no `fsMode` startup flag exists)     | yes                              |
| session overlay    | a preset entry, launch or in-session (`--yolo`, `/yolo`, `--no-sandbox`, `--eval-state`); a launch preset lands here, not in the startup-flag tier and not in settings (`src/tui/run.tsx:401-413`) | no — cleared on exit or override |

- **No snapshot and no restore.** The snapshot channel is deleted, not guarded. Exit **clears the overlay**, and the lower tiers show through — which reproduces ADR-0119 ruling 6's observable outcome ("lands back on `default` / project `plan`") without a remembered copy re-applying itself over a user's later choice. That re-application was the defect ADR-0141 records as F4 (`src/harness/sandbox/yolo.ts:373-375` vs `src/tui/app.tsx:1110-1121`).
- **Whole clear, or none — and the trigger is a declared axis.** A user change to an axis **the preset declares** clears the entire overlay and drops the preset's markers; a change to an axis it never declared does not. yolo declares all three (fence, `fsMode`, permission) and exits on any; no-sandbox declares two and **survives a permission change**, because a clear resolves a _contradiction_ between declaration and choice, and `--no-sandbox` + a permission change contradicts nothing — it is the posture ADR-0139 §2 named, so revoking it there would make the flag's own meaning unreachable one keystroke after the operator asked for it. The trigger is a user act on a declared axis, however it arrives (`/config` panel, `/config <set>`, `/permissions`, Shift+Tab), not a screen. A partial clear is what would manufacture the illegal `workspace` + retired-fence state, so it is forbidden by invariant 7, not discouraged.
- **Clear before write-back; a failed write-back never rolls back.** On a `/config` `fsMode` change the overlay clears **synchronously before** the settings write-back is issued (today persistence is fire-and-forget after the holder flip, `src/tui/app.tsx:1110-1121`). If the write-back fails, a notice is shown; the effective value stays the user's choice and the overlay is **not** re-seeded.
- **Read Shift+Tab as its result, not as a press.** The wheel cycles `default → full_auto → full_auto + graph → default` (`nextShiftTabAgentMode`, `src/harness/graph/mode.ts:149-159`), so the `full_auto → full_auto + graph` step (`:155-157`) changes **only the graph axis**, which no preset owns, and must leave any preset intact; the other two steps change permission and so exit the yolo preset. A hook keyed on the keystroke would revoke a dangerous posture for a reason the posture never claimed. **Its read side is pinned too:** the flip **must take** its starting point from the effective permission value — today it reads the same holder it writes (`permission.get()` at `src/harness/graph/mode.ts:183`) — or a press inside the yolo preset steps from the pre-preset value to `full_auto`, visibly nothing, and still clears the overlay (ADR-0141 §3).
- **The clear hook sits at every site that applies a user's choice to a declared axis** — two kinds of site, not one. For `fsMode` they are the persist sites (`src/tui/app.tsx:1117-1118` panel toggle, `:1356-1360` `/config <set>`) and no others: the sibling writers for `subagentCap` (`:1157`) and `worktreeOnMutate` (`:1192`) persist undeclared axes and carry **no** clear hook. For permission there is **no persist site to hook** until the new write-back exists, so the hook sits at the two holder-flip surfaces — `/permissions set` (`src/harness/permission/permissions-command.ts:110`, via `src/tui/app.tsx:1429-1443` and `src/cli/chat-session.ts:2153`) and the wheel (`permission.set` at `src/harness/graph/mode.ts:189`) — and flip + settings write + clear become one action. A setter-side-only hook misses "the user chose this" vs "the preset forced it"; a persist-site-only hook leaves a mid-preset keystroke **shadowed by the overlay**, which is F4 in a new axis. Naming trap: the live wheel face is `applyShiftTabAgentModeFlip` (`src/harness/graph/mode.ts:172-191`); the single-axis `applyShiftTabModeFlip` (`src/harness/permission/modes.ts:168-180`) is exported at `src/harness/permission/index.ts:51` and **has no caller in `src/tui/` or `src/cli/`** — hooking it buys a hook that never fires.
- **Never persisted, in any shape** (ADR-0119 ruling 8 continues to bind): not a settings key, not a session-file field, and **not routed through native session state either** — whose exclusion rule refuses a field matching `/…|yolo/i` (`src/session-api/store/native-state-store.ts:294-297`, enforced at `:319`) and must be widened to cover `no-sandbox` / `fenceRetired` spellings, or a preset could survive into persisted state.
- `IKNOW_FS_MODE` and the renamed `IKNOW_FENCE_RETIRED` are **parent→worker wires** (`src/harness/subagent/spawn.ts:248`, `:253-255`; read only in `src/harness/subagent/worker.ts:508`, `:540-546`), not startup layers. A host value cannot seed a session; an ambient one is always scrubbed.

## 2. Boundaries

- **Does:**
  - Retire the fence wholesale at the one SSOT factory branch, now keyed on `fenceRetired` (`src/harness/sandbox/bwrap.ts:215` field, `:724` branch) — all four routes (foreground bash / background spawn / verify sandbox-run / subagent worker) inherit it transparently, and `bwrap.ts` contains **no `yolo` judgment at all** afterwards.
  - Declare the preset's axis combination in the overlay (`fence retired` + `fsMode global`, plus `full_auto` for yolo only), read through one effective-value computation.
  - Assert invariant 7 on every effective-value computation, raising a typed error.
  - Enter from `--yolo` (launch) / `/yolo` (TUI, modal), from `--no-sandbox` (TUI launch, no modal, no in-session command in this scope), or declaratively from `--eval-state` (headless, no controller, no exit semantics).
  - Clear the overlay as a whole wherever a user applies a choice to a **declared** axis (§1's hook bullets), and add the **new permission settings write-back** (the permission axis has no write-back at all today: no `onPersist*` / `persist*` permission export exists in `src/config/persist-settings.ts`, and `/permissions` plus Shift+Tab flip the holder only — `src/tui/app.tsx:1429-1443`, `src/harness/graph/mode.ts:189`), user-layer only per ADR-0090.
  - Render two derived indicators in the existing mode-row slot: the YOLO badge (unmodified yolo preset only) and the persistent 无沙箱 marker (any retired fence, from effective configuration).
  - Register the fence posture **at spawn** on subagent and background descendants, so a live bare descendant keeps saying "no sandbox" after the preset that spawned it left.
  - Refuse a root launch, refuse a preset on a non-TTY (except `--eval-state`), and warn (not silently ignore) on a `yolo` / `no-sandbox` key found in settings.
  - Keep the probe-parity pins in `tests/harness/sandbox/yolo-probe-parity.test.ts` (renamed arms, same checks).
- **Does NOT (named one by one):**
  - The `network-guard` stack behind `web_fetch` / `web_search` — a separate line of defense.
  - The worktree gate (`worktreeOnMutate`) — orthogonal; a preset changes no gate semantics and skips nothing (ADR-0119 ruling 4).
  - The hard wall, security review, or the which-tree axis — every preset intercepts exactly as a fenced session does; writes still resolve against the live `taskRoot`.
  - The `PERMISSION_MODES` value domain — still three values (`src/harness/permission/modes.ts:31`); `full_auto` keeps its name and badge; a preset is not a fourth mode.
  - Any persistence of a preset (settings key, session field, config-panel row).
  - A half-bare shape (foreground bare, background fenced) — there is still exactly one fence shape and one retirement.
  - An in-session `/no-sandbox` command — **not in this round** (ADR-0141 P6, decided); the slash vocabulary and its exhaustive table stay unchanged (`src/tui/slash.ts:77`, `:130`).
  - A `/status` command (ADR-0141 P1, decided): the posture is carried by a new `SessionRecord.posture` field and one `/info` line instead (§5).

## 3. Settled invariants

1. **Retirement is wholesale or absent, across all four routes.** No preset reads "sandbox on with permissions relaxed"; there is no second fence shape.
2. **`fenceRetired` is the fence layer's only input.** It is derived at **exactly one site** — the overlay module's effective-value computation in `src/harness/sandbox/` (§1) — from the effective configuration; every convergence site reads that result and none recomputes it. It is never derived from which entry raised the posture and never from a product label; a descendant's spawn-time registration feeds the same derivation. The convergence surface is ADR-0141 §6's table; holder **threading** sites rename with the carrier and decide nothing.
3. **Zero change when no preset is in force:** argv, `requireBwrap` behavior, the always-present `--unshare-net`, egress assembly and the credential mask are byte-identical (ADR-0097 is named-amended, never revoked).
4. **Entries are exhaustive and typed-refused elsewhere.** `chat` / `serve` / `ask` / `oneshot` / `trace` carrying `--yolo` **or** `--no-sandbox` → parse-time typed error, non-zero exit, nothing started. This invariant is only as strong as the list being complete — a new preset entry with the list left stale is the failure mode, not an acceptable gap.
5. **Nothing persisted.** Overlay only; markers are derived display; a posture key in settings is ignored **with a warning**.
6. **The overlay clears as a whole or not at all**, and clearing it is the only way a user overrides a preset. The trigger is a user change to an axis **the preset declares** — yolo exits on a fence, `fsMode`, or permission change; no-sandbox exits on a fence or `fsMode` change and **survives a permission change** (§1's hook bullets; ADR-0141 ruling 3).
7. **`fsMode: workspace` and a retired fence are never simultaneously effective.** Asserted on every effective-value computation; a violation is a **typed error, never a silent correction**. Reaching `global` is declared by the preset, so on the implemented entry paths the assertion has nothing to correct — it exists to catch a later path that retires the fence without declaring the tier.
8. **Axis separation at the primitive, combination at the preset** (ADR-0139's mechanism + ADR-0141's product): entering a preset writes its axes as one declaration; the fence write never produces a permission write, and **no primitive reads permission to decide a fence**. The only path from a permission act to the fence is a **preset revoking its own declaration** (invariant 6) — one layer up, with the badge and the marker changing in the same action as the state. So `--auto-mode`, Shift+Tab and `/permissions` never retire the fence and never un-fence a session: under the yolo preset they end it, and everywhere else they change the permission axis alone.
9. **Symmetric probing and fail-closed.** bwrap presence is rechecked on **every fenced call** (foreground, background, verify, subagent), not only at assembly (today the only probe is `src/harness/aci/tools/bash.ts:1184`); a missing bwrap returns a typed error and the command is not executed; a host without bwrap refuses preset entry **and** exit alike with zero state change; an absent holder, an absent wire, or an unparsable wire value all keep the fence **up**.
10. **Exemptions must be named.** Three named entries retire the fence (`--yolo` / `/yolo`, `--no-sandbox`, `--eval-state`) and each is greppable, markered, and refused off its own surface. One exemption **face** exists at one factory branch; the count that grew is the entry enumeration, and the enumeration is the defense line.
11. **A fence change reaches only commands started after it.** Granularity: foreground bash re-reads per call and freezes it at handler entry (`src/harness/aci/tools/bash.ts:418`, `:1307-1312`); background inherits that frozen snapshot per spawn (`:1535-1538`); a subagent worker gets its own value per spawn (`src/harness/subagent/spawn.ts:254`); verify reads at `src/harness/verify/sandbox-run.ts:152`, i.e. **per `runVerifyLoop` entry (≈ per user turn)**, because the closure is built once (`src/harness/verify/verify-loop.ts:1556-1557`) despite a comment claiming per-round rebuild (ADR-0141 Pending P2 — a comment defect, not a behavior to re-adjudicate).

## 4. Operator-locked specification (per preset; implementers no longer choose)

| Dimension  | yolo preset                                                                                              | no-sandbox preset                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Naming     | `--yolo` / `/yolo`; the flag name keeps the issue #1035 meaning: fence gone **and** questions gone       | `--no-sandbox`, named for its content: fence gone, questions unchanged        |
| Entry      | `--yolo` before the TUI starts (no modal), in-session `/yolo`                                            | `--no-sandbox` at a TUI launch only, no modal; no in-session command in scope |
| In-session | entry always passes the confirmation modal; exit is immediate and unconfirmed                            | none (P6); the posture ends with the preset clear                             |
| Exits on   | a user change of `fsMode` **or** permission (fence has no other switch), or `/yolo` again                | a user change of `fsMode` only — **not** a permission change                  |
| Display    | YOLO badge **and** 无沙箱 marker (preset unmodified)                                                     | 无沙箱 marker only; no YOLO badge, never derived from the entry               |
| Semantics  | fence retired wholesale + `fsMode` declared `global` + `full_auto`; hard wall and review still intercept | fence retired wholesale + `fsMode` declared `global`; permission untouched    |

Locked and shared by both: in-session entry needs confirmation and launch entry never opens a modal; nothing persisted; no half-bare shape; no new bottom-bar row (the mode-row slot is reused, ADR-0119 ruling 5); `--auto-mode` stays permission-axis-only and is not a preset.

## 5. Contract (input / error)

- **The overlay is constructed in the TUI or by `--eval-state`, and by nothing else.** This is a **wiring** rule, not only a parse rule: the engine seam accepts a holder unconditionally (`src/cli/runtime.ts:133-140` → `src/harness/build-engine.ts:501`), so "the parse layer refuses it" is not by itself why `chat` / `serve` cannot reach a bare route today (`src/cli.ts:681-727` carries no key; `src/cli/chat-session.ts` has none).
- **Both presets declare `fsMode: global`; neither forces a shared holder.** The old force (`src/harness/sandbox/yolo.ts:326-331`, conditional on the current value differing from `FS_ISOLATION_MODE_DEFAULT`) is replaced by a declaration in a tier the user cannot write, so the tier is recoverable by clearing the overlay.
- **Permission write-back is new and user-layer only.** `src/config/persist-settings.ts` exports patches for thinking / memory / fsMode / worktreeOnMutate / subagentCap / model (`:174`, `:209`, `:278`, `:312`, `:351`, `:429`; writers `:510`, `:518`, `:537`, `:558`, `:579`, `:599`) and **none for permission**. The new patch must carry the fail-loud value-domain shape `fsMode`'s patch already has (`:278-291`) and must respect ADR-0090: the project layer may not self-grant `full_auto` (`src/harness/permission/project-settings.ts:156-164`). **Key and location (P3, decided):** the existing `permissions.defaultMode` field of `IknowSettingsPermissions` (`src/config/settings.ts:679-685`), written to the **user** file `~/.iknow/settings.json` (`src/config/settings.ts:2101`). Today the user layer's whole `permissions` section is ignored with a warning (`src/config/settings.ts:2115-2118`) and `defaultMode` admits only `"default"` / `"plan"` (`:681`); the change admits **`permissions.defaultMode` alone** at the user layer with the full `PermissionMode` domain (`src/harness/permission/modes.ts:31`), keeps the warning for every other user-layer `permissions` key, and keeps the project layer's `defaultMode` domain at `["default", "plan"]` (`src/harness/permission/project-settings.ts:48`). Precedence becomes explicit flag > `IKNOW_PERMISSION_MODE` > project `defaultMode` > user `defaultMode` > `default` (`src/cli/runtime.ts:60-73`).
- **The env wire renames with its carrier:** `IKNOW_YOLO` (`src/harness/sandbox/yolo.ts:106`) → `IKNOW_FENCE_RETIRED`. Value domain, both-values-written normalization, ambient scrub, and the fail-closed direction are byte-identical (`src/harness/sandbox/yolo.ts:119-124` → `src/harness/subagent/worker.ts:542-545`); no compatibility shim, because writer and reader ship in one binary and there is no cross-version child. **The scrub covers both spellings while the change lands.**
- **The descendant registration is derived out of existence, not deleted.** Background tasks are never removed from their map (`src/harness/background/manager.ts:1098`), so liveness comes from the existing status filter (`isLiveTask` `:956-958`, `listLiveTasks` `:959-968`); subagent rows keep terminal entries (`src/harness/subagent/manager.ts:3228-3270`). Neither `BackgroundTask` nor `SubagentInfo` has a fence field today (`:109-176`, `:155-207`), so the registration is new state read through those existing filters — the spec does not promise a delete-on-exit hook the registries lack.
- **Display is a pure function of effective configuration plus live descendants.** Today's concatenated projection (`modeRowText` = `modeRowBaseLabel` + marker, `src/tui/app.tsx:910-919`, base `:879-887`, marker `:898-900`, slots `:5965` / `:5972`) is replaced: an unmodified preset shows the preset's own form and **does not** concatenate the labels **an indicator on the row already states** — the yolo badge states all three axes, so `全局档` / `full_auto` drop out; `--no-sandbox` has no badge, so its row keeps the permission label, an axis that preset never declared (ADR-0141 ruling 5). The entry-derived mirror (`seedYoloOn` reading a holder into cached state — `src/tui/app.tsx:2087-2090`, `:2640`, written at `:2157` / `:2298`) is removed, because a mirror of which entry fired is exactly what invariant 2 forbids.
- **The posture is recorded, not only displayed.** No posture field exists today on `SessionRecord` (`src/harness/trace/types.ts:243-255`, assembled at `src/harness/loop-engine.ts:4506-4514`, the `recordSession` call), `TurnRecord` (`:213-237`) or `SubagentSpawnRecord` (`:426-444`). Per ADR-0141 P1 (decided), a `posture` field is added to `SessionRecord` only, filled at that call, and `/info` (`src/tui/app.tsx:6201-6210`) gains one posture line; no `/status` command is added, and any number or log produced under a preset names its state (the ADR-0130 §5 reporting invariant, generalized).
- **typed-error catch contract** (`.claude/rules/code-quality.md`): refusals and invariant violations go through the typed discriminated union (`kind`), rendered `${kind}: ...`; `err instanceof Error ? err.message : String(err)` is forbidden (a plain object prints `[object Object]` and hides `kind`).
- **Runtime failure surface under a retired fence (scoped, unchanged in kind):** no route assembles a fence while a preset is in force, so "bwrap disappeared mid-preset" has no fence-assembly face inside the session; the only face that re-assembles is the clear, which probes symmetrically. The generic `server_unreachable` → `"tool execution failed"` surface (`src/harness/sandbox/server/index.ts`, `src/harness/tools/executor.ts`) is **pre-existing non-preset behavior** byte-pinned by invariant 3 — a typed upgrade there is out of scope.

## 7. Display

- **YOLO badge** — only while the yolo preset is unmodified. A user change to any axis it declares clears it with the overlay.
- **无沙箱 marker** — persistent, independent, and true whenever the fence is retired: the main process's effective config retires it, **or** a live subagent was spawned while it was retired, **or** a live background process was spawned while it was retired. Derived, never entry-sourced.
- **Per-axis labels are suppressed only for an axis a visible indicator already states** — never because "a preset is active". The unmodified yolo preset shows **YOLO + 无沙箱** and does not also print `全局档` / `full_auto`, because one word states all three axes; the `--no-sandbox` preset shows **无沙箱 with no badge**, which is "no badge", **not** a hidden permission label. So the `--no-sandbox` + `--auto-mode` composition shows **无沙箱 + `Auto`**: suppression keyed to the badge would be the same bug as keying it to a retired fence (ADR-0141 ruling 5).
- Mode row only; `chromeReserveRows` cost stays zero; narrow (`cols < 40`) and wide forms both keep their tested shapes (`src/tui/app.tsx:898-900`).
- Notices: entry text names **every** axis the preset changed (fence and `fsMode` tier for both, `full_auto` for yolo only); exit text names what the clear restores (the settings value the user owns, not a snapshot). The modal is `/yolo`'s today (`src/tui/yolo-picker.tsx:32-51`, its copy in the disposition list below) and is required of **in-session** entry for whichever preset has one — of no launch flag, and `--no-sandbox` has no in-session entry in this scope (P6).

## 9. EXIT

- Non-TUI `--yolo` **or** `--no-sandbox` (`chat` / `serve` / `ask` / `oneshot` / `trace`) → **non-zero exit, nothing started**, rendered through the typed union as `${kind}: ...`.
- A non-bare TUI launch carrying a preset off a TTY (e.g. `iknow tui --yolo`), or a preset under root → **exit 1 before any session exists**, with the refusal naming the supported form (non-TTY: `src/tui/run.tsx:429-437`).
- `/yolo` entry or clear **refused on a host without bwrap** → zero TUI state change + notice, session continues (no crash, no quit).
- Invariant 7 violated by a path no preset declared → **typed error from the effective-value computation**; the tier is never silently rewritten and the fence is never silently re-raised.
- A user change of a **declared** axis during a preset (yolo: `fsMode` or permission; no-sandbox: `fsMode`) → overlay cleared as a whole, user value persisted, badges dropped, **exit 0** (this is a success path, not a refusal). A no-sandbox preset meeting a permission change is **not** in this list: nothing clears, the permission write lands, 无沙箱 stays lit.
- `-h` / `--help` / `-V` / `--version` → pure display path, exit 0, no session, preset flags or not. Bare `--yolo` / `--no-sandbox` on a TTY starts the TUI holding that preset; off a TTY it is the `help` display path — usage printed, nothing started, **exit 0** (`src/cli/parse-args.ts:430-448`, `src/cli.ts:1016-1019`). Bare `--eval-state` with no query stays the display path on either TTY state.
- Bun missing: an ordinary bare TTY launch falls back to chat with one stderr notice; a launch carrying **any** preset, and an explicit `iknow tui`, fails loudly rather than quietly starting a session without the posture (ADR-0119 Amendment 2026-10-10).
