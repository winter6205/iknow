**Status:** draft
**Basis:** wayfinder map `unified-shell-parsing` handover ("Not yet specified" list) + ADR-0123 / ADR-0124 / ADR-0125 + ADR-0068 (2026-09-24 amendment) + usp-5 migration table. This is the migration slice **after** the parse foundation and the substitution matrix; it is a planning artifact — the spec only, no code, no other file.
**Surface:** `src/harness/permission/hard-walls.ts` (destructive-rm / destructive-disk / bare-metachar / root-find-walk walls, the sensitive-path command scan `commandContainsSensitivePath` (`:918`) + `SENSITIVE_PATH_FRAGMENTS` (`:116-139`) — **assigned to this spec's Stage 2**, `splitShellSegments`), `src/harness/permission/declarative.ts` (`splitCommandSegments`), `src/harness/aci/tools/bash-readonly.ts`, `bash-read-extract.ts`, `role-substitution.ts`, plus a new permission-context command-name table. **New test files this spec creates and that its diff-scope gates therefore account for (round 8's Low: SC-S2-8, SC-S2-9, SC-S2-7 and SC-GATES-6 each demanded a table/pin test whose file was named in the criterion but not enumerated here, while SC-S2-3 forbids editing `permission.test.ts` and `bare-metachar-hard-wall.test.ts` is Stage-3-anchored — an unnamed pin is unbuildable):** `tests/harness/permission/sensitive-path-command.test.ts` (SC-S2-7's twelve new assertions), `tests/harness/permission/destructive-roster-ast.test.ts` (SC-S2-8's 16-id roster table **and** SC-S2-9's declared-code-operand keep-denied pins — same id family, one file), and `tests/harness/permission/deny-reason-golden.test.ts` (SC-GATES-6's one-representative-command-per-id golden-reason table).

## Objective

Finish the unification started by the two sibling specs so that **every** spawn-before decision that today reads raw command text reads the same parse instead. Concretely: move the remaining five text-scanning walls (destructive-rm, destructive-disk, bare-metachar, root-find-walk, and the sensitive-path command scan) onto quote-aware AST judgment (Stage 2-3); retire `splitShellSegments` as a wall input and re-home its three external consumers plus the deliberately-separate `declarative.ts` splitter onto the parse (**Stage 4a**); and consolidate the interpreter list (born in Stage 1), `ALLOWED_COMMAND_TOKENS`, and the readonly command set into one declarative source of truth (**Stage 4b** — its own PR, because it changes no decision input).

Success is binary per PR: the named anchor tests stay green, the listed quote/heredoc flips actually flip, no divergence survives review, and **each of the four PRs (Stage 2, Stage 3, Stage 4a, Stage 4b) is independently revertable — one PR, one `git revert`, no flag to unwind** (SC-GATES-2). The user-facing effect — and Stage 2 is **the** stage that delivers it, not Stage 1 (Stage 1's Assumption 10 explicitly leaves it here): `echo "rm -rf /"`, `echo 'rm -rf /'`, `cat <<'EOF' … rm -rf / … EOF`, dangerous text in a comment, and `echo rm -rf` (a substring inside a non-destructive word's operand, SC-S2-1) stop denying, while `rm -fr /x`, `sudo -u root find /`, `r\m -rf /`, `;`, `bash <(curl …)`, `python3 -c "…rm -rf…"` and `bash -c 'shutdown now'` (interpreter code operands — the case SC-S2-9's declared-code-operand rule is written to guarantee, not a side effect), and `powershell -c Remove-Item …` (replay C2.f — kept by that same rule, not by luck), and — for the sensitive-path wall, whose excision set is narrower by design (SC-S2-7) — `echo "cat ~/.ssh/id_rsa"`, `cat '/etc/shadow'`, `cp '/home/u/.ssh/id_rsa' /tmp/x`, `sh -c 'cat /etc/passwd'`, `echo a > '/etc/passwd'` (a **quoted** redirect target) keep their existing verdict.

This spec is **migration plumbing**: it changes _how_ a verdict is computed, and the only _what_ it changes is the quote/heredoc-class flips already ruled by ADR-0125 — including the half of them Stage 1 disclaimed (its inert-text guarantee covers the substitution ids only) and the sensitive-path arm the operator assigned here on 2026-09-24 — narrowed further by one thing it must _not_ relax: a quoted span that is a real operand or a redirect target stays judged (SC-S2-7's four exclusions). It opens no new security policy, **newly allows no real operand access, and newly denies nothing at all** — every criterion below is written so a today-allow stays an allow, and SC-S2-6 / SC-S2-7's no-widening pins are the evidence for that, not the prose. **Read "at all" as scoped to this spec's own rules, and to nothing else:** the migration's one ADR-sanctioned strictness is `malformed` / `over-cap` 比现状更严（今天落正常流程） (`docs/adr/0124-parse-verdict-contract.md:35`), which is Stage 1's to own and is pinned there (its SC20), and SC-GATES-3 states exactly which corpus rows that fact licenses and what this spec may never do with them. An implementer who reaches one of those denies in a Stage-2/3/4 diff has violated this sentence, not found the exception.

## Success Criteria

Every criterion is binary and maps to a `vitest` command or the Stage 0 divergence tool. **"Green" / "passes" / "no expectation edits" means, throughout this spec, "no new failures against the PR base"** — never "the suite is green on this branch", because each stage's base is the tree the previous stage PR left, so an absolute-green claim is not something a stage PR can state about itself. **Round 6 blocked the reason this spec used to give for that rule, and the reason was false:** it asserted the base _itself_ is already red at `tests/harness/aci/tools/role-substitution-boundaries.test.ts` (B12, "POSIX bracket classes ride on the modifier-group signature"), with a live count of `1 failed | 13 passed`. Re-measured in both trees: in the main checkout and in a worktree that has been provisioned, that file is **`14 passed (14)` — nothing is red**; the only way to reproduce the red case is to run it in a worktree with no `vendor/ripgrep`, and `git ls-files --others --exclude-standard` cannot show it because `/vendor/*` is gitignored (`.gitignore:195`), so every fresh worktree starts without that binary. `resolveInstallRoot()` (`src/harness/session-roots.ts:251-266`) then resolves the install root to the **worktree itself** (it walks up to the nearest `package.json`, which a linked worktree has), so `<installRoot>/vendor/ripgrep/…` does not exist there, and `grep.ts` falls back to "a built-in Node scan … [that] matches with JavaScript RegExp and may answer differently from ripgrep" (its own contract text at `:202`) — and JavaScript RegExp does not understand `[[:space:]]`, which is the whole of B12's `AssertionError`. **The remedy is provisioning, not an exclusion: `cp -r <main-checkout>/vendor/ripgrep <worktree>/vendor/`** (an untracked copy, invisible to every diff-scope gate in this migration), after which the file is green. Consequences: B12 is **struck from every "excluded by name" clause in this spec** (SC-S4-1's intro and role-substitution bullet, SC-S4-4's behavioral binary, SC-GATES-2's re-pass binary — all now read "no new failures against a **provisioned** base"); this spec neither fixes nor re-pins a case it does not own; and **only a failure that survives provisioning counts as a failure at all** — a red that everyone has agreed to ignore is the mirror image of a green that cannot fail, which is the defect class round 6 was grading. "Keep green" = the existing named test file passes with **no expectation edited in this spec's stages**; "flip" = an expectation this spec is _allowed_ to edit and must land the other way. **A keep-green claim about a file Stage 1 already edited is measured from Stage 1's post-flip state, never from today's bytes** — `tests/harness/aci/permission.test.ts` and `tests/harness/permission/bare-metachar-hard-wall.test.ts` are in that set, so the anchors below are named by _entry / assertion content_, because Stage 1's edits shift line numbers inside them. The replay suite (`tests/harness/aci/security-bypass-replay.test.ts`) is the whole-file cross-stage gate — all its cases green at every stage and the file byte-unchanged (SC-GATES-1). **Input classes (the repo's convention is the explicit pin at `permission.test.ts:371`):** `empty`, `overflow` and `exception` are carried by the criteria above (`SC-S2-7`'s `findDangerousPattern("")` neighbour at `bare-metachar-hard-wall.test.ts:146-148`, SC-S4-5's over-cap exclusion, and every non-`ok` declaration in SC-S4-1); **`negative` — the "must NOT start firing" half of the boundary, the class `permission.test.ts:353-358` carries as its fifth row and this bullet used to omit while listing only four — is carried by the no-widening pins named here rather than left implicit: SC-S2-9's `cmd /c 'echo one & echo two'` → `null` (a code operand with no dangerous word must stay an allow, so arm (b)'s whole-operand text rule cannot be widened to any-word matching), SC-S3-1's whole "must not start denying" anchor set (the `bare-metachar` deny side stays the same shape after the move), and SC-S2-7's three no-widening non-goal pins (`echo a > /tmp/x.pem && notify` → `false`, `cp app.key '.bak'` → `false`, `cp app.key # backup` → `false`)** — a reviewer can now see `negative` was considered and where; **`concurrent` is declared N/A for Stages 2-4 by that same convention — an explicit N/A pin, and this spec declines to add a filler test** — `parseForSecurity` is _fully synchronous_ (Stage 0's single entry point, 解析地基: 全同步), so no two parses interleave inside one Node turn, and the only shared mutable state in the path is Stage 0's bounded LRU, which this spec neither owns nor extends (adding a concurrency assertion would test Stage 0's cache in a spec that "assumes all of it exists and cites it", Boundaries/Out-of-this-spec). If Stage 0 ever makes that entry point async, the class re-opens there, not here.

### Stage 2 — destructive-rm / destructive-disk

- **SC-S2-1 (flip — this is where inert-text dangerous substrings stop denying; Stage 1 does not deliver it).** Stage 1's guarantee is the substitution ids only (its Assumption 10, restated in its first Out-of-this-spec bullet): every shape below is denied **today** by id `destructive-rm` (verified against the live scanner) and must return `null` from `findDangerousPattern` after Stage 2:
  - `echo "rm -rf /"` — double-quoted operand of `echo`: no `rm` command node exists.
  - `echo 'rm -rf /'` and `printf 'rm -rf /'` — single-quoted.

- **解析判定 vs hard-wall**: 判定是墙的输入契约（六态 + 前置否决清单），墙只消费判定结果做政策；判定层的"硬拒"（畸形/中止/超容量）发生在墙之前，不可被 grant 覆盖（ADR-0124）
- **递归检查 vs hard-wall**: 硬墙从"认字符"变"认意图"——command-substitution 收窄为真执行替换（归宿由递归检查定），新增 parameter-expansion / interpreter-procsub / unparseable 三 id；墙的不可覆盖性不变（ADR-0125）
- **组合墙 vs heredoc**: 同为"解释器拿到脚本"，`<(...)` 内容运行时才生成 → 硬拒；heredoc 内容白纸黑字 → 逐行检查后放行干净的（ADR-0125）
