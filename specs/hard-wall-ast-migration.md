## Objective

Finish the unification started by the two sibling specs so that **every** spawn-before decision that today reads raw command text reads the same parse instead. Concretely: move the remaining five text-scanning walls (destructive-rm, destructive-disk, bare-metachar, root-find-walk, and the sensitive-path command scan) onto quote-aware AST judgment (Stage 2-3); retire `splitShellSegments` as a wall input and re-home its three external consumers plus the deliberately-separate `declarative.ts` splitter onto the parse (**Stage 4a**); and consolidate the interpreter list (born in Stage 1), `ALLOWED_COMMAND_TOKENS`, and the readonly command set into one declarative source of truth (**Stage 4b** — its own PR, because it changes no decision input).

Success is binary per PR: named anchors pass against a provisioned base, intended inert-data flips occur, all other divergence is explicitly classified, and the merged Stage 2 PR, each Stage 2 closure follow-up, and the separate Stage 3, Stage 4a, and Stage 4b PRs are independently revertable (SC-GATES-2). Stage 2 makes inert dangerous-looking text stop denying when its data ownership is proven; it keeps real destructive argv and confirmed executable code denied; and it routes security-relevant uncertainty through ADR-0127's Security review requirement before ordinary grants or mode handling. A clean command continues through the ordinary permission flow, so clean `full_auto` calls remain automatically allowed. The valid code-operand replay `powershell -c 'Remove-Item -Recurse -Force C:/Temp'` remains denied. For the sensitive-path wall, only proven inert comment and heredoc-body text is excised; real operands, redirect targets, and executable code remain judged under SC-S2-7.

This spec changes the parse-based decision path while preserving the legacy parser-unavailable scan. Its bounded behavior changes are: proven inert dangerous-looking text may fall through to ordinary permission flow; unresolved security-relevant text requires a per-call interactive review in `default` and `full_auto`, or a typed deny when explicit interactive capability is unavailable; and the two named code-bearing fork-bomb variants in SC-S2-8 become hard denies. No uncertain pattern may become an ordinary automatic allow, no real executable operand may be newly allowed, and no allow-to-deny change is permitted except those named fork-bomb variants and a typed deny when the Security review requirement has no interactive capability. Existing `malformed`, `aborted`, `over-cap`, and pre-parse `vetoed` hard denies remain owned by the parse contract.

## Success Criteria

Every criterion is binary and maps to a named test or the Stage 0 differential tool. "Green" and "passes" mean no new failure against the stage's provisioned PR base; linked worktrees used for the role-substitution suite must have `vendor/ripgrep` provisioned so the test exercises the same scanner as the base checkout. A keep-green claim for a file edited by Stage 1 is measured from Stage 1's post-flip state. The replay suite is byte-unchanged across this spec's stages (SC-GATES-1). Input classes are covered by the named boundary pins: empty and negative cases by SC-S2-7 / SC-S2-9 and the Stage 3 no-widening set; overflow and exception cases by SC-S4-1 / SC-S4-5. Concurrent review calls are isolated: each has its own source span and approval, and one call's approval cannot satisfy another; pin two concurrent unresolved calls with an approval for only one.

### Cited from CONTEXT.md (verbatim, not redefined)

**解析地基**: 权限决策前的语法级 shell 解析层——tree-sitter 原生绑定、全同步 `parseForSecurity(command)` 单一入口（`shell-parse.ts`），按命令字符串有界缓存，policy/handler 两道门共享一次解析。只供给语法事实（引号内外、替换结构、heredoc 语境），不做 deny 决策；各墙与切分器是它的消费者。ADR-0123。

**解析判定**: 解析地基本身的输出契约——六态闭集（ok / 未知语法 / 畸形 / 中止 / 超容量 / 解析器不可用）加解析前字符级一票否决清单，是所有墙唯一的解析输入。仅"解析器不可用"降级旧扫描（终态、红字警示、不许静默），其余各态各有固定归宿。ADR-0124。

**递归检查**: 替换类语法的判定模型——`$(...)`、反引号、`<(...)` 的内层命令提取出来，走与顶层完全相同的权限判定，ask 逐层上传导，嵌套上限 2 层（第 3 层 → ask）。静态判定不赌运行时条件：`${X:-$(cmd)}` 按会执行分析。ADR-0125。

**组合墙**: 解释器（bash/sh/python/node…）直接执行 `<(...)` 产出内容 → 硬拒，不问内层是什么。拒的是"内容运行时才生成、谁都看不见"的组合，不是"解释器执行脚本"——heredoc 脚本内容白纸黑字，不在此墙内：读 **解析地基** 的 `heredocs[]`，按接收者定性，**把正文当 bash 再解析一次逐命令判**（不是扫行子串），干净的放行。ADR-0125。

Relationship lines (verbatim):

- **解析地基 vs hard-wall**: 地基给语法事实（哪段是代码哪段是数据、替换的内外层结构），墙做政策决定（deny/ask）；地基自己不 deny，墙不再各自扫裸文本（ADR-0123）
- **解析判定 vs hard-wall**: 判定是墙的输入契约（六态 + 前置否决清单），墙只消费判定结果做政策；判定层的"硬拒"（畸形/中止/超容量）发生在墙之前，不可被 grant 覆盖（ADR-0124）
- **递归检查 vs hard-wall**: 硬墙从"认字符"变"认意图"——command-substitution 收窄为真执行替换（归宿由递归检查定），新增 parameter-expansion / interpreter-procsub / unparseable 三 id；墙的不可覆盖性不变（ADR-0125）
