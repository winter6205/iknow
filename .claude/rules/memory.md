# Memory Rules

## 记忆分层

项目使用三层记忆：

1. **团队共享记忆** — `CLAUDE.md` 和 `.claude/rules/*.md`，提交到 Git。
2. **个人本地记忆** — `CLAUDE.local.md`，**不**提交（已加 `.gitignore`）。
3. **自动项目记忆** — 通过 `/memory` 查看和审计，本机项目级。

团队共享记忆只记录稳定、可复用、对所有贡献者有价值的信息。

个人偏好、临时路径、本地调试端口、个人 token、个人脚本不得写入团队共享记忆。

## 写入准入（可写入团队共享记忆）

- 项目架构原则
- 模块边界
- 常用命令
- 测试要求
- Git 工作流
- 发布流程
- 重要约定
- 反复踩坑的项目级事实
- 高风险目录规则

## 不应写入

- 密钥 / token / cookie / 证书
- 个人账号
- 临时任务状态
- 一次性 debug 信息
- 未验证猜测
- 与项目无关的个人偏好
- 过长的会议记录
- 可以从代码直接看出的低价值信息

## 更新规则

当你学到稳定且可复用的项目事实时，应建议更新记忆，但**不要擅自**把临时信息写入团队共享规范。

更新前必须判断：

1. 这是否对未来任务有帮助？
2. 是否适用于整个团队？
3. 是否已经存在于 README / docs / 代码中？
4. 是否包含敏感信息？
5. 是否应放入 `CLAUDE.local.md` 而不是 `CLAUDE.md`？

## 记忆维护

每次修改 `CLAUDE.md` 或 `.claude/rules/*.md` 时必须保持：简洁 / 可执行 / 无重复 / 无矛盾 / 与当前项目实际命令一致。

如果规范变得过长，应拆分到 `.claude/rules/` 或 `docs/`，并在 `CLAUDE.md` 中用 `@path/to/file` 引用。

建议月度维护流程：

1. 运行 `/memory` 查看加载文件和自动记忆。
2. 删除错误、过期、重复、敏感或低价值记忆。
3. 将稳定且团队共享的信息迁移到 `CLAUDE.md` 或 `docs/`。
4. 将个人偏好迁移到 `CLAUDE.local.md`。
5. 检查 `CLAUDE.md` 是否过长、重复或规则互相冲突。
6. 提交规范变更时单独成 commit。

## 写作纪律

1. 一段一判断，不写"但是 / 实际上"
2. 详细规则走跨引 `@~/.claude/rules/x.md`，不复制
3. 括号注释只放必要属性 (命名 / 出处 / 阈值)
4. 段首若重复标题 → 删
5. 决策进文档，探索留 thinking 块

**删项清单**: 段首元叙述 / 括号内技法 / 编辑评论 / `Let me think / Actually wait`。
