# 0006 · 检索阶段：重排序与混合检索（覆盖用户提前提出的问题）

- 日期：2026-07-19
- 类型：概念推进 + 用户提问归档
- 背景：用户在 0004 课后提出“按句切后，4句退款步骤系统怎么确定哪句是重点”。此问题本质属检索阶段（重排序），超出当时 chunking ZPD，用户主动同意“留到以后细化”。本课即承接该问题。
- 决策：开 0005 课，主题为检索阶段两阶段（向量粗召回 Top-N + cross-encoder 重排序 Top-K）+ 混合检索（向量+BM25）。用 retrieval-viz.js 交互组件演示：朴素向量 Top-5 会召回“运费险…”这种形似答非所问的块，重排序将其降权踢出，留下真正的退款流程块。
- 关键澄清：① bi-encoder 快但粗、cross-encoder 准但慢 → 先粗捞再精排；② 混合检索补向量抓不到的精确生僻词（订单号等）。
- 验证：组件在浏览器实测，阶段①含“运费险”块，阶段②将其降权、Top-3 全为退款流程。
- 组件复用：新增 retrieval-viz.js；quiz.js 复用（MC 自测）。
- ZPD 影响：用户已能从“系统怎么挑重点”的直觉问题，对应到“重排序/混合检索”的工程概念——认知跃迁到 qualified 线。下一步计划 0006 课：手搭最简 RAG CLI，把 embedding+chunking+检索+重排序串成真实管线，用真实数据验证。
