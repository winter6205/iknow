# 0012 · 教学纪律修正：贴真实源码 + 渐进式披露

## 用户反馈（原话摘要）

> "你把一些内容省略了，但是你把它简化之后，你又没有把源代码给贴出来。然后，你又在关键点注释里面写了源代码的函数……渐进式披露概念，请从你的技能概念里面认真遵循。老师，我是一个懂得很少的，你一上来把简化后代码的给我而且不贴原文，也不详细讲我也很难理解。前面学的那些东西，他是学得很简单，非常简单，并不是代表我真的会了。前面那个智能体教的东西太简单了，基本上前几章都在教概念，然后最后一两张教了一点点简单的Python而不是TypeScript。"

## 诊断

三个错误：

1. **贴了假代码**：`candidates.sort(byKeyword)` 这种写法在真实代码里不存在。用户无法对照学习，且会建立错误心智模型。
2. **一节课塞 4 个 tool**：违反渐进式披露。每个 tool 蜻蜓点水，用户一个都没真正懂。
3. **假设 RAG 概念已掌握**：learning-records 写"qualified"是上一个智能体的判断。用户自述"前面教的东西太简单了，没真懂"。不能假设他懂 RRF / BM25 / embedding。

## 修正（已写入 NOTES.md）

### 代码课铁律

- 绝对不写"简化版"伪代码。贴真实源码，可以只贴关键行（标注行号），但必须是 `src/` 里真实存在的那几行。
- 省略必须用 `// ... (省略 N 行：xxx) ...` 明确标出。
- 每段真实代码后面跟**逐行讲解**，不是"关键点列表"。

### 渐进式披露

- 一节课只讲一个东西。kb_retrieve 本身就够一节课。
- 先一句话概括 → 函数签名 → 逐块讲代码。不要一上来就贴代码。
- 不假设用户懂任何术语。第一次出现必须用一句话解释。
- 0001-0007 的 RAG 概念**不能当作已掌握**。遇到 RAG 概念要用真实代码重新锚定。

### TS 教学

- 每个 TS 语法第一次出现必须解释。
- 不要求"学会写 TS"，只要求"看到不慌、能说出这行在做什么"。

- 用户基线再次下调：RAG 概念不是"qualified"而是"听过这些词"。后续课遇到 RAG 概念要用真实代码重新锚定。
- 教学节奏从"一节课 4 个 tool"调整为"一节课 1 个 tool，逐行讲"。
