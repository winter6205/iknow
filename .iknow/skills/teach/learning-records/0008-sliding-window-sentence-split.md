# 0008 · chunk_size × overlap 交叉算法 + 句子切分器原理

- 日期：2026-07-19
- 类型：概念深化（滑动窗口数学 + 静态规则切分器）
- 背景：用户在 0006 课后暴露两个未完全掌握的具体问题：① chunk_size 和 overlap 到底怎么"交叉"计算（滑动窗口公式）；② 句子迭代器（`doc.sents`/正则）是怎么"识别"句子边界的，是 AI 还是规则。
- 核心澄清：
  - 滑动窗口公式：下一块起始 = 当前起始 + (chunk_size − overlap)。overlap 是相邻块共享的字数，不是"补丁"。
  - overlap 的单位混淆（我之前的锅）：在脚本里是字符、在 0003 课里可能是"句"。用户此前一直以为 overlap=3 是"3 句"导致认为冗余太多。
  - 句子切分器是静态正则规则（正向后顾 `(?<=[。？！.!?])\s*`），不是 AI/推理。spaCy `doc.sents` 也是类似的预定义规则更复杂版。
  - 对于 FAQ 短问答对，最优解一直是"句子切分 + overlap=0"，而非字符切。
- 输出：0007 课含两模式交互组件（滑动窗口滑块 + 句子边界可视化）。
- ZPD 影响：用户现在能自己讲清"什么时候用句子切、什么时候用字符切+overlap"的适用场景和取舍。
- 验证：浏览器实测两模式组件均正常工作；quiz 自测 3 题逻辑正确。
