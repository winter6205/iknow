iknow 形态定位句

iknow fork = gbrain serve (stdio + http, 无 OAuth 2.1 强制层) × 4 KB tool × Session HTTP × Vite SPA × deterministic/llm 双 agent mode——把 KB retrieval + trajectory scoring + 一轮 chat 跑通，但不携带 dream cycle / autopilot / cron / OAuth 2.1 HTTP transport / minions / multi-source / mounts / RLS 这一整套 "24/7 autonomous + team shared memory" 承诺。
升级到 gbrain 全自主需补 4 块（dream cycle + autopilot + serve --http + OAuth 2.1 + jobs work），升级到 Company Brain 形态需 5 阶段（数据底座 → 应用层隔离 → OAuth 字段 → 拓扑 + mounts → Postgres RLS）。两条路径正交，可独立 ship。

不要升级的部分（overkill）

iknow 是 offline tool，gbrain 是 billion-scale 公司脑基础设施。 以下部件在 gbrain 是必需的（60 cron + PgBouncer + 多 brain + thin-client），在 iknow 是 overkill：

❌ MinionQueue / worker.ts / 锁续约（无长跑后台场景）
❌ OAuth 2.1 / oauth-provider.ts（无 network surface）
❌ db-pacer / pace-mode（无 PgBouncer）
❌ subagent / brain-allowlist.ts（agent loop 在 CLI 进程内，不烧钱）
❌ cycle / cron / autopilot / dream cycle（无 60 cron 场景）

iknow 真实优势清单（被侦察反证的事实）

  • fact arm 设计更紧——kb_retrieve 把 fact 当排序信号但文本不进 G2 信封，避免 LLM 直接抄 fact 产生幻觉。gbrain recall不进 RRF，iknow 在这点反而领先。
  • citation 元数据主动挂——kb_retrieve 输出主动构造 chunk_id / doc_id / doc_type / summary / source_ref / chunk_version / fact_status，让 G2 信封能挂。gbrain query handler 不挂 citation，只在 chunk 上 stamp evidence。
  • ACL + freshness + fact_status 三件套内置——kb_retrieve 一开始就在做（retrieve.ts:102-173 内置过滤），gbrain 在 sourceScopeOpts 这一层独立做。
  • deterministic + llm 双 agent mode——iknow 的 --mode deterministic / --mode llm 切换是产品级的稳定设计；gbrain 的 deterministic 是 subagent system-prompt 的属性（不同抽象层）。
