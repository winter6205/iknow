技术架构概览（三版共享）

企业级智能客服/知识助手 Agent 平台，核心架构：

用户请求 → API 网关 → 意图识别 → Agent 编排器
                                    ├── ReAct Agent（思考-行动-观察循环）
                                    ├── 规划 Agent（任务分解与执行）
                                    ├── RAG Agent（知识检索与生成）
                                    └── 反思 Agent（质量校验）
支撑层：
├── 多路检索引擎（向量 + BM25 + 混合检索 + RRF 融合）
├── 记忆系统（短期：Redis 滑窗 + 长期：向量数据库）
├── 工具系统（搜索、计算器、数据库查询 + MCP）
├── 模型路由（多模型候选 + 三态熔断器 + 自动降级）
├── 全链路追踪（每步操作的 Trace 记录）
└── 文档 ETL（PDF/Word 解析 → 分块 → 向量化 → 入库）
[P5]

快速开始（最简命令）

Python 版（推荐首选）：
  cd project-python
  cp .env.example .env        # 填入 API Key
  pip install -r requirements.txt
  uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

Java 版：
  cd project-java
  mvn clean package -DskipTests
  java -jar target/agent-platform-1.0.0.jar

Go 版：
  cd project-go
  go build -o agent-server ./cmd/server
  ./agent-server
[P4–5]

2. 项目分级（按能力深度，决定「能否过面试」）

以下分级综合 PDF 第 245 页职业发展路径、第 260 页工程能力要求、第 864–868 页各背景转岗建议归纳，为教学用「通关阶梯」。

Tier 0 · 入门 Demo（不足以过面试，仅练手）
  • 单文件 LangChain/Spring AI 调通一个 RAG + 单轮问答；无观测、无评测、无部署。
  • 判定：能跑通「问→检索→答」，但讲不清状态、失败重试、成本。仅用于建立直觉。
  • 出处信号：小白「5 个浅尝不如 1～2 个深挖」[P278]；「项目易停留在 Demo」[P8657]。
Tier 1 · 完整链路（校招 / 实习 / 助理级可投）
  • 一条完整链路：数据 → RAG → Agent → 简单前端或 CLI → Docker 部署；可展示仓库（CI、类型检查、测试、评测脚本）。
  • 核心能力：API、Prompt、简单 RAG、脚本与工具（对应「初级 LLM 应用开发」[P8728]）。
  • 加分动作：自建 200 条评测集，离线 F1 达 0.78，代码与实验记录开源 GitHub [P9972–9974]。
  • passes_interview_if：能讲清「数据从哪来、指标怎么算、失败怎么改」，覆盖 8～10 分钟自我介绍。
Tier 2 · Agent 工程化（1～3 年经验 / 社招主流）
  • 编排、记忆、评测、观测、稳定性（对应「中级 Agent 工程化」[P8730]）。
  • 主动写 1 条与事故/评测/成本/延迟相关的内容；区分度明显 [P9966]。
  • 技术权衡示例：「延迟敏感场景放弃重型重排，改用轻量双塔+规则后处理，P95 达标且 Recall@5 仅降 2 个点，业务接受」[P9967]。
  • passes_interview_if：讲清 ownership、线上结果、协作边界、技术权衡，每条经历含可量化指标。
Tier 3 · 平台 / 多 Agent / 对齐（高级 / 专家）
  • 架构、成本、数据飞轮、团队规范（对应「高级 平台/多Agent/对齐」「专家/架构 跨业务平台」[P8732–8736]）。
  • 需 SFT/RLHF/DPO 理解、复杂多 Agent、成本与稳定性、K8s/Docker 训练推理服务化（腾讯高级岗 [P237–238]）。
  • passes_interview_if：能设计可扩展架构（插件化工具/配置化管道/事件总线，新工具接入 2 小时 [P307–309]），并有评测驱动与可观测体系。

3. 三语言项目落地要点（来自简历模板）

Python 版 · 企业级 AI Agent 智能助手平台

技术栈 & 边界 Python, FastAPI, LangChain, LangGraph, Milvus, Redis, PostgreSQL。
职责边界：对话编排、ReAct 循环、工具执行、RAG 客户端、记忆读写、与模型网关异步调用；用异步 IO 支撑高并发。 [P269, P285]
  • 核心职责：多步编排与状态持久化（工具失败重试+人工介入，日均 X 万轮）；RAG 流水线（混合检索+重排，Top-5 命中 X%→Y%）；会话级+业务记忆分层（Redis TTL+PG 归档，成本降 Z%）；模型网关联调流式与熔断（P95<X ms）。
  • 工程重点（面试话术）：会话隔离与并发安全、全链路 timeout 与重试、结构化日志+ trace id 贯通、与 Java/Go 团队 HTTP/gRPC 契约对齐 [P285]。

Java 版 · 企业级智能问答与 Agent 编排服务平台

技术栈 & 边界 Java 17, Spring Boot 3, Spring WebFlux, OpenFeign, Resilience4j, Elasticsearch, Redis, PostgreSQL, Kafka（可选）。
边界：会话、鉴权、网关、B 端编排与检索结果合并；Python 侧负责 LangGraph 与重模型推理 [P268]。 [P270]
  • 核心职责：模型网关调用层（流式 SSE、超时重试、熔断配额，大促可用性 X%）；工具执行与权限校验（角色/数据域，失败降级纯 RAG）；Java 侧检索策略编排（查询改写+结果融合，Top-3 命中 +X%）；Micrometer+Prometheus 指标大盘。
  • 亮点：WebFlux+SSE 低延迟；Resilience4j 按租户限流+多模型切换；gRPC/HTTP 契约+SLA+Trace ID 贯通。

Go 版 · 高并发 LLM 网关与 Agent 执行引擎

技术栈 & 边界 Go, Gin（或 Fiber）, gRPC, Redis, PostgreSQL, OpenTelemetry, Prometheus, Kubernetes。
边界：高性能基础设施——模型网关、流式 SSE/gRPC 转发、检索代理、高 QPS 接入层，部分 sidecar 形态 [P268]。 [P271]
  • 核心职责：高性能流式代理（chunk 转发、连接复用、优雅关闭，单机 X k QPS）；工具执行沙箱与超时控制（隔离用户输入+下游 HTTP，降 SSRF/资源耗尽）；Redis 令牌桶+滑动窗口限流（按租户/模型配额）；全链路 Trace ID 贯通。
  • 亮点：连接池与内存分配优化降 GC/尾延迟；多模型路由（成本/延迟/质量优先可配置，失败自动切换）；与 Python 编排服务职责分离。

5. 必备 / 加分 / 差异化技能清单（学习计划优先级）

依据岗位出现频次、面试追问深度与落地难度整理，适合 6–12 个月学习计划 [P8608]。

Must Have（必备） 1. Python 后端能力：异步 IO、API 设计、依赖注入与模块化，能独立部署带工具调用的 Agent 服务。
2. LLM 应用基础：消息格式、流式输出、常见参数（temperature/max_tokens）、限流与重试。
3. RAG 全流程：切分、embedding、向量库、重排序、幻觉与引用溯源对策。
4. Tool Calling：JSON schema、函数描述、错误处理、并行/串行策略。
5. Agent 范式：ReAct / Plan-and-Execute 能口述+画图，理解「何时结束」与「状态」。
6. 基础 Prompt Engineering：角色/约束/Few-shot/输出格式（JSON/XML）。
7. Git 与工程习惯：可审查仓库、最小可运行示例、README 与复现步骤。
Nice to Have（加分） LangGraph（或同类）、公有云（AWS/GCP/Azure）、K8s/Docker、对齐与微调入门（SFT/DPO/RLHF 名词与边界）、开源贡献、多模态。
Differentiator（差异化） 领域结合的 RAG（能讲数据从哪来、如何评测）、记忆槽位与上下文工程、Token 与成本优化（可量化前后对比）。 [P8611–8632]
