工业级 Agent 架构：Claude Code 生态（TS/Rust/Python 移植/HitCC）+ 企业级 RAG 项目

来源：PDF 第 247–262 页《开源项目学习笔记》。{ROOT} 指本地克隆路径。[原文 Pxxx] 标注出处。本卡为教学压缩，路径与结论均引自原文，未做外部补充。

第一部分：工作区内四个项目

1. claude-code-main（TypeScript 源码快照）[P247-250] 真实产品级 CLI 模块划分与运行时行为（非教学 Demo）。运行时/构建以 Bun 为主（广泛用 bun:bundle）；语言 TypeScript；终端 UI 用 React + Ink。

核心架构[P248-250]

  • src/tools/：每个业务工具（Bash/文件读写/Grep/MCP/子 Agent）以目录组织，含 Tool 实现、Prompt 片段、权限 UI、常量。基类 src/Tool.ts（findToolByName、工具上下文类型、权限/进度耦合边界）。
  • Bash：src/tools/BashTool/ 含 bashPermissions.ts、readOnlyValidation.ts 等纵深安全逻辑。
  • 子 Agent：src/tools/AgentTool/（runAgent.ts、forkSubagent.ts、loadAgentsDir.ts）。
  • MCP：src/tools/MCPTool/MCPTool.ts 及 src/services/mcp/ 客户端/传输层。
  • 注册/发现/执行：工具实现统一接口，由上层 Query 循环按名调度；findToolByName 将 tool_use 映射到实现；执行路径与权限回调（CanUseToolFn、hooks/useCanUseTool）强绑，形成「先策略、再执行」。
  • src/commands/ + src/commands.ts：斜杠命令（/compact、/mcp、/plan）解析注册分发，按 Feature Flag 条件挂载可选命令（bridge/voice/workflows）；与 Query/工具层解耦。
  • src/services/：可复用横切能力（API 客户端、会话记忆、压缩 compact、遥测、自动摘要、语音、插件、远程托管）。体现「主循环瘦、服务胖」——复杂策略下沉 service 单测友好。
  • src/query.ts（QueryEngine 主路径）：多轮对话、流式事件、compact、工具结果摘要；按构建裁剪压缩策略（feature('REACTIVE_COMPACT') 等）；Token 预算 src/query/tokenBudget.ts。
  • 权限与 Feature Flag：权限类型集中 src/types/permissions.ts；大量 import { feature } from 'bun:bundle' 实现同一源码树多产品形态（内部版/桥接版/语音版）。

学习价值：工具抽象、查询主循环、服务化横切、Bridge 远程面、权限与 Feature Flag 组成可维护 Agent 产品——适合当「架构地图」阅读，而非逐行抄写。[P250]

2. claude-code-rust（规范 + Rust 实现）[P250-252] 洁净室（clean-room）思路：先写可读可检索的 spec，再实现 Rust。适合回答「从零设计同类系统，模块如何切分」。

规范 spec/[P250-251]

  • 索引入口 spec/INDEX.md，00_overview → 13_rust_codebase 共 15 文件（约 990KB 说明文字）。
  • 阅读顺序：00_overview（总览/结构/数据流/权限设置分层）→ 01_core_entry_query（入口/QueryEngine/历史/费用/token 预算）→ 02_commands → 03_tools → 04/05（UI 与权限交互）→ 06_services_context_state → 07_hooks → 08_ink_terminal → 09_bridge_cli_remote → 10~12（工具函数/常量类型）→ 13_rust_codebase（Rust 侧映射）。

Rust 工作区 src-rust/[P251]

  • cli：cli/src/main.rs、oauth_flow.rs —— 进程入口与 OAuth。
  • core：core/src/lib.rs、system_prompt.rs、team_memory_sync.rs、oauth_config.rs。
  • tools：tools/src/lib.rs 及 bash.rs、file_read.rs、grep_tool.rs、mcp_resources.rs、agent_tool.rs。
  • query：query/src/coordinator.rs、compact.rs、cron_scheduler.rs、auto_dream.rs。
  • 另有 tui / commands / mcp / bridge / buddy crate。

关键设计模式（SDD 规范驱动开发）：Spec 先行定边界/定数据契约/定交互语义，再落 Rust mod；13_rust_codebase.md 明确 crate 与工具数，便于 parity（对等性）检查。面试可表述为「契约优先 + 分 crate 隔离依赖方向」。[P252]

3. claude-code（Claw Code — Python 为主移植）[P252-254] 不依赖完整 TS 栈复现「入口→QueryEngine→工具/命令」骨架，保留与上游 TS 的 parity 对照能力。

Rust 子树 rusty-claude-cli（CLI/TUI 实验）+ compat-harness（兼容性/行为对齐测试）。学习价值：用少量 Python 模块+manifest 表达移植范围；parity_audit 适合企业内多语言栈（Java+Python sidecar）迁移。[P254]

4. HitCC（逆向文档库，针对 Claude Code v2.1.84）[P254-255] 非官方逆向分析文档库，补足「只看自己源码树」的盲区——运行时行为、模块边界、生态扩展。
  • 01-runtime/：设置、配置、缓存、迁移、CLI 注入 schema。
  • 02-execution/：工具、Hook、权限、Prompt 组装与上下文分层、附件、非主线程 Prompt 路径——理解「一次请求里上下文如何叠层」的核心。
  • 03-ecosystem/：Resume/Fork/子 Agent、远程持久化与 Bridge、Plan 系统、MCP、Plugin、Skill、TUI 子系统。
  • 04-rewrite/：重写架构取舍与开放问题；05-appendix/：证据图、术语表。
  • recovery_tools/：extract_js_symbols.py、js_identifier_tools.py、js_readability.py、format_bundle.py——文档+工具链一体化。

学习价值：与 claude-code-main 交叉验证（HitCC 描述运行时与边界，源码提供真实实现），可发现版本漂移与文档滞后；适合准备「Claude Code 的 Prompt 分层与权限边界」深度面试题。[P255]

第二部分：网上优秀项目分析

5. nageoffer/ragent（企业级 Agentic RAG）[P255-258] 社区典型企业级 Agentic RAG 开源实现，强调「检索增强 + 多步工具/流程编排 + 可运维」，与 CLI Agent 的 Claude Code 系互补。

技术栈[P256]

  • 后端：Java 17 + Spring Boot 3.5（REST/任务/配置/向量库客户端）。
  • 前端：React 18 管理端。
  • 向量库：Milvus 2.6。
  • 规模：后端约 4 万行、前端约 1.8 万行、约 20 张业务表——已超越 Demo，进入领域建模+持久化+运营阶段。

核心能力[P256-257]

  1. 多路检索引擎：意图定向通道（按意图缩小范围）+ 全局向量通道（广域召回），融合用重排序或加权融合，需可追溯检索决策日志。
  2. 意图识别体系：树形分类（由粗到细对齐业务流程/权限域）；低置信度则追问槽位或列候选意图。
  3. 问题重写与拆分：口语化改检索友好查询；多跳拆子问题分别检索综合。
  4. 会话记忆：滑动窗口（近期全保留）+ 摘要压缩（窗口前历史压摘要，需处理摘要与事实一致性）。
  5. 模型路由与容错：三态熔断器（关闭/半开/打开）；自动降级（主模型失败切备用或缩小任务如仅检索不生成）。
  6. MCP 工具调用：与 Claude Code 系 tools/MCPTool、services/mcp 概念对齐，统一协议利于多端复用。
  7. 文档入库 ETL：清洗/分块/元数据/版本/增量更新；知识库「越用越准」取决于 ETL 与溯源。
  8. 全链路追踪：TraceId 贯穿网关→检索→LLM→工具，排障与 SLA 归因必备。

6. 阿里商旅 Agent（业务向参考）[P258-259]

  • 业务：机票/酒店/火车/用车/审批/差标/发票报销；强规则（差标/职级）、强时效（余票/价格）、强协同（审批流/企业支付）。
  • 设计：任务型对话+工具/API 编排（自然语言落结构化意图再调供应链 API）；状态机与槽位填充（目的地/日期/人数/差标，避免模型幻觉覆盖业务规则）；人在回路（超标/无票/冲突显式确认或转人工，与 Claude Code 权限对话框同理）。
  • 挑战→解法：规则与模型冲突→规则引擎优先、模型输出仅作候选必经校验；多系统异构→统一 BFF/API 网关+工具层抽象（类 MCP）；合规审计→全链路日志+脱敏+可归因；峰值稳定→异步任务/队列+降级为「仅查询不下单」；体验一致→同一意图 taxonomy 驱动前端引导与后端路由。

第三部分：架构模式总结[P259-261]

  1. 分层：接入（CLI/API）→ 编排（Query/Coordinator）→ 工具与外部系统 → 持久化与观测。本工作区映射：main/cli → query.ts/query crate → tools/ → services/+DB。
  2. 契约优先：工具入参 schema、权限结果、消息类型在类型系统集中定义（TS：types/；Rust：spec/12_constants_types.md）。
  3. 扩展点显式化：Feature Flag、Hook、Plugin/MCP，避免无限 if-else。
  4. 工具系统设计：统一基类+按工具分包（Tool.ts + tools/<Name>Tool/）；权限外置（CanUseToolFn、审批 UI 与执行解耦）；横向能力复用（Bash 路径/只读/沙箱校验拆多模块文件）。
  5. 记忆管理：工作记忆（当前会话+token 预算 tokenBudget.ts/compact）；长期记忆（SessionMemory、teamMemorySync）；压缩（自动 compact、微压缩边界消息）。
  6. 错误处理：API 层 FallbackTriggeredError、withRetry；用户可见 vs 调试日志分流（logError/logForDebugging）；可恢复=重试/降级模型/跳过非关键工具（需定义 SLA）。
  7. 可扩展性：Bridge（新客户端实现协议不 fork 核心循环）；MCP（新工具提供方独立进程降崩溃面）；命令插件化（commands.ts 聚合注册+Feature Flag）。

第四部分：对项目的启发[P260-262]

  1. 先写「架构地图」再写模块：参考 claude-code-rust/spec/INDEX.md 提供唯一索引，避免新人误读。
  2. Query 与 Tool 边界写死：工具只做单职责动作，编排（多步/重试/合并上下文）放 Query/Coordinator。
  3. 权限与审计一等公民：不仅「能不能调 API」，还要「谁在何时批准了什么」。
  4. 可观测性：Analytics/内部日志/TraceId；企业交付常因缺观测而被拒收。
  5. 多语言/多运行时并存时：维护 parity_audit 式对照表，避免语义漂移。
