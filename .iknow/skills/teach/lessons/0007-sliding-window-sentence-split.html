这节课解决两个具体问题：
1. 滑动窗口数学：chunk_size=15，overlap=3，"交叉"到底是怎么算的？下一块从哪里开始？
2. 句子切分器：`doc.sents` 或正则是怎么"知道"哪里是句子边界的？它不是 AI 识别的，是规则静态切分。

1. chunk_size 和 overlap 的交叉计算（滑动窗口）

字符切的本质是滑动窗口，和"我每读 N 个字，就往前挪 N—O 个字"是同一件事。

公式只有一条：

下一块起始位置 = 当前块起始位置 + (chunk_size − overlap)

举例：文本 退款将在3个工作日内原路返回。（15字，位置 0–14），size=10，overlap=2：

块 起始 内容 公式
[0] 0 退款将在3个工作日 从 0 开始取 10 字（位置 0–9）
[1] 8 日内原路返回。 0 + (10−2) = 8（位置 8–14）

下一块应从 16 (=8+8) 开始，已越界（>14），循环结束 → 共 2 块。越界即停止，不会无限切。

「交叉」的意思是：块[0]的末尾"日内"也出现在块[1]的开头（位置 8、9 在两块里各出现一次）。overlap=2 就是每块有 2 个字和上一块重复——不是"断裂后粘合"，是同一段字在相邻两块里各出现一次。系统检索时只要命中任何一块就行。

3. 句子切分器：它到底怎么"认"出句子边界？

不是 AI，不是 embedding——就是一行正则规则：

import re
chunks = re.split(r'(?<=[。？！.!?])\s*', text)

(?<=[。？！.!?]) 叫「正向后顾」——正则引擎在扫描时，每遇到 。？！.!? 中任何一个字符，就在它后面切一刀。不破坏原文（保留标点）。\s* 吃掉句尾可能有的空格/换行。

这就是你 0004 课里学的「离线静态规则」——切分器不"理解"句子，它只是看见了句尾标点就切。

spaCy 的 doc.sents 本质也是干同一件事，只不过用了更复杂的规则（处理 Mr. Smith 这类带点但不表示句末的缩写），中文版额外处理引号配对。但核心仍然是「预定义规则」，不是模型推理。

4. 回到 FAQ 场景

对于一问一答一句的 FAQ，最优解一直是句子切分 + overlap=0。
字符切 + overlap 是为了长文档准备的——当你有一段 5000 字的说明文档时，不能等句号出现，必须按固定大小切才能控制 chunk 数量。

你的直觉是对的（"一般就一句"），但现在你知道了选择的理论基础：

  • 问答对按句分：句子切分 + overlap=0（零冗余，每块完整）
  • 长文档统一切：字符切 + overlap=chunk_size 的 10%~20%（防腰斩）

5. 一句话钉死

滑动窗口：下一块起点 = 当前起点 + (chunk_size − overlap)。overlap 是相邻块共享的字数，不是"补丁"。
句子切分器：是静态规则（正向后顾匹配句尾标点），不是 AI 推理。`doc.sents` 也是类似原理。
选择原则：短句/FAQ 用句子切 + overlap=0；长文档用字符切 + overlap=10~20%。
