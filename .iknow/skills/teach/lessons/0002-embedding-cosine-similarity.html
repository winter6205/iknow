向量化 Embedding —— 从"文字"到"可比较的数字"

第二课 · RAG 基础原理系列 | 参考：RAG 技术卡 | 上一课：体系解构

先回答最直觉的问题

你说"我只表面看了一下，不理解原理"——我们先从这里开始。

你问："机器怎么知道两段文字像不像？"

答案不是机器"理解"了文字，而是它把文字变成了数学上的坐标。两段文字像不像，变成了两个坐标在空间里离得近不近。这就是 embedding。

从你的已有知识出发：

  • 你用过 Dify/Coze 的 RAG 流程，选过"embedding 模型"——那是把你上传的文档切成段落、每段算一个向量。
  • 你试过"用一句话搜索"——那是把搜索词也变成向量，然后去找最像的文档段。
  • 你现在要做的是：揭盖——看"像不像"到底怎么算的。

第一步：文字 → 坐标

假设一个极度简化的世界：每个词只有两维含义。比如"猫"这个词在这个二维坐标系里的坐标是 (0.9, 0.4)：

猫 → (0.92, 0.39)
第一维偏向"生物"，第二维偏向"萌宠"。
猫[0] = 0.92（很像生物），猫[1] = 0.39（有点可爱）
狗 → (0.85, 0.52)
第一维也偏"生物"，但也在此维度上稍大；
两轴方向几乎一致——猫和狗是相似的。

真正的 embedding 不是 2 维，而是 768 维或 1024 维（取决于模型）。但数学原理一样：每个文字（词/句/段）用一个高维坐标点表示。

同样重要的推论

  • 猫和狗坐标接近 → 语义相似
  • 汽车坐标在另一个区域 → 与猫不相似
  • 机器学习过程决定了坐标的分布——好的 embedding 模型训练时让"相似文本"的坐标聚在一起

第二步：两段文字的"相似度"怎么算？

有了坐标，剩下的就是数学。最常用的指标叫 余弦相似度（Cosine Similarity）。

相似度 = cos(θ) = (A · B) / (|A| × |B|)

它只关心方向是否一致（不管长度）：

  • cos(θ) ≈ 1（θ 接近 0°）→ 方向几乎相同 → 语义非常相似
  • cos(θ) ≈ 0（θ 接近 90°）→ 方向垂直 → 语义不相关
  • cos(θ) ≈ -1（θ 接近 180°）→ 方向相反 → 语义几乎相反

第三步：动手感受余弦相似度

下面是一个交互式的 2D 示意图。两个实心圆点各代表一段文本的坐标（简化到 2 维方便可视化）。拖动红色或蓝色端点，看夹角和余弦值实时变化：

你试一下：

  1. 点击「猫 ↔ 狗」预设 → 夹角很小，cos ≈ 0.98。两段文本语义高度相似。
  2. 点击「猫 ↔ 汽车」预设 → 夹角变大，cos 骤降。语义偏离，不该被召回。
  3. 把红色和蓝色拖到几乎同方向 → cos 接近 1。
  4. 把红色拖到第一象限、蓝色拖到第二象限 → 观察夹角 > 90° 时 cos 变 负数。

现在你能回答：

当你问 Dify "给我一份关于猫的文档"时，它内部干的是：把你的搜索词变成向量 → 求这个向量和知识库里的每个文档向量的余弦相似度 → 找出 cos 最大的（方向最一致的）top-K 个文档。就这么简单——没有"理解"，只是几何上的靠近。

它在你的 RAG 管线里起什么作用？

文档入库
每个 chunk → embedding 模型 → 高维向量 → 存入向量库。这是一次性的离线程，但选择哪个 embedding 模型决定了后续"相似"的标准。
用户提问
问题 → 同样 embedding 模型 → 查询向量 → 向量库召回 top-K。这是每一次问答的实时的流程，耗时大头在向量比较。

来源：知识卡 05-RAG 技术 [原文 P54-85]

为什么理解这个对你有用？

  • 面试题："什么是 embedding？"现在你能说：文本到高维空间的映射，用余弦相似度衡量语义距离。而不是只说"把文字变成向量"。
  • 选模型：bge-m3 vs text-embedding-3 vs m3e 的区别不是哪个"更好"，而是它们的 768 维空间的"相似"定义不同（训练数据/目标不同）。
  • 定位问题：如果召回结果质量差，可能是因为 chunk 文本语义不对齐（向量方向散）、embedding 模型不适合你的领域，而不是"RAG 本身不行"。

总结 & 下节预告

这一课你学会了 之前你不知道（只看过名词）
文字 → 坐标（高维向量） 只知道"embedding 把文字变成向量"
余弦相似度 = 方向一致性 只看到调接口传参数
cos ≈ 1 相似, cos ≈ 0 无关 不知道 0.7 和 0.8 差多少
embedding 模型决定"相似"的标准 以为所有 embedding 都一样
