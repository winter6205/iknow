手搭最简 RAG CLI

把 0001–0005 的全部原理写成一个可运行的 Python 脚本——你改参数、跑一遍、看结果

这课做了什么：前面的 5 课都是原理/交互。这一课你把它们写成代码跑起来。 你修改 CHUNK_SIZE / OVERLAP / RERANK_ON 三个参数，观察召回变化——亲手验证「切分决定召回质量」这件事。

1. 脚本长什么样

一个文件 minimal_rag.py（约 100 行），文本编辑器打开就能改。结构就是 RAG 管线： 

 文档加载 → FAQ 文本硬编码在脚本里
 → 切分（chunk_text：按字符切，参数 CHUNK_SIZE + OVERLAP）
 → 向量化（vec_sim：字重叠近似余弦——教学用，真实系统换 embedding API）
 → 检索（retrieve：余弦比大小，返回 Top-K）
 → 重排序（rerank：主题关键词乘子近似 cross-encoder）
 → 输出（打印召回结果 + 分数变化）

2. 亲手跑一次

打开终端，切到 lessons/ 目录运行（不需要装任何依赖——纯 Python 标准库）：

$ python minimal_rag.py

先不改参数跑一次（默认 CHUNK_SIZE=10, OVERLAP=2, RERANK_ON=True），看输出。然后依次改参数再跑：

实验 1：关掉重排序

把 RERANK_ON = False 再跑一次。观察召回结果里是否出现了“运费险”“会员”等答非所问的块。

实验 2：加大 overlap

把 OVERLAP = 4（原来是 2），RERANK 保持开，观察 chunk 列表变化。

实验 3：把 chunk 调到完整句子大小

把 CHUNK_SIZE = 30（让每块足够容纳一整句），OVERLAP = 0。观察召回是否更好。

3. 你应该观察到什么

实验 预期观察 原理对应
RERANK_ON=False 召回结果含“运费险”噪声块 0005：朴素余弦不认主题
RERANK_ON=True 噪声块被降权，Top-2 全是退款流程 0005：重排序精筛
OVERLAP=4 每句可能出现在多个 chunk 里（部分 chunk 更完整） 0003：overlap 保句子完整
CHUNK_SIZE=30, OVERLAP=0 块很少（4-5块），但每块是整句或整段——召回更准确 0003：大 chunk 保上下文
